# Эталон конфигов Grim AC

Два файла для развёртывания внешнего античита Grim 2.x в `plugins/Grim/`.
Мост CHRDK_Anticheat рассчитан именно на них — см. `docs/design/ANTICHEAT.md`
и `wiki/anticheat.md`.

- **config.yml** — основной конфиг Грима (config-flavor V2, config-version 11):
  заводские значения без послаблений. Экспериментальные проверки выключены,
  Forge-версии со встроенными Reach-читами отключаются, блоки ресинхронизируются
  по миру сервера, алерты пишутся в консоль.
- **punishments.yml** — группы проверок и команда моста. Каждое срабатывание
  исполняет консольную команду
  `chrdkac flag %player% %check_name% %vl% %verbose%` — журнал доказательств
  и алерты модераторам. Иных команд (кики, баны, штрафы) нет: запрет выносит
  человек по журналу. Проверки, не попавшие ни в одну группу, Грим не включает,
  поэтому группы перечисляют все проверки Grim 2.x и не пересекаются
  (пересечение дало бы два журнальных записи на один флаг).

## Порядок выкладки (кратко)

1. Поставить JAR Grim 2.x в `plugins/` (внешний плагин, без форка — GPLv3).
2. Один раз запустить и остановить сервер: Грим создаст свои файлы.
3. Заменить `plugins/Grim/config.yml` и `plugins/Grim/punishments.yml` эталонными.
4. Запустить сервер: в консоли не должно быть «Error while loading punishments.yml»,
   команда `/grim` подтверждает, что плагин активен.
5. Права обхода (`grim.exempt`, `grim.nosetback`, `grim.nomodifypacket.*`)
   не выдавать никому, включая персонал и OP.

## Что пинит GrimConfigsTest

- все 127 проверок Grim 2.x покрыты ровно одной группой (нет ни дыр, ни
  двойного учёта);
- команды групп — только мост `chrdkac flag %player% %check_name% %vl% %verbose%`,
  без `[alert]`/`[webhook]`/`[proxy]`;
- жёсткие значения config.yml не ослаблены.
