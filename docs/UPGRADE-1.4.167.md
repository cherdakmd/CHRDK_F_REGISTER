# Обновление до 1.4.167 — свободный вход и пять рангов

Это обновление меняет смысл сервера: **играть можно бесплатно**, а деньги
берут за ранг гильдии — комфорт, оформление и темп. Старая проходка осталась
только как механизм совместимости, её можно не трогать.

Ниже — что сделать на сервере, чтобы всё включилось правильно.

---

## 1. Ядро (`plugins/CHRDK_Core/config.yml`)

### 1.1 Вход

```yaml
pass:
  enabled: false      # вход свободный
  trial:
    enabled: false    # вместо триала — приветственный ранг ниже
```

`pass.enabled: true` возвращает старую стену `NO_PASS`: регистрация, пароль и
2FA никуда не делись, но играть без оплаты будет нельзя. Мы рекомендуем
оставить `false`.

### 1.2 Ранги

Новая секция `ranks`. Если её нет в старом файле — скопируйте целиком:

```yaml
ranks:
  enabled: true
  show-name-in-chat: false     # слово «Хранитель» рядом с ником; false — только знак и цвет
  announce-join: true
  hat:
    min-level: 5               # /hat — с пятой ступени; админам хватает права chrdkregister.hat
  bonuses:
    xp-percent: [0, 10, 20, 30, 40, 50]
    drop-percent: [0, 5, 10, 15, 20, 25]
    skill-levels: [0, 2, 4, 6, 8, 10]
  welcome:
    enabled: true
    level: 1
    days: 3                    # три дня Странника сразу после регистрации, раз на UUID
  levels:
    # … пять ступеней с name, format, badge, join-line
```

Индекс в таблицах — ступень: `[без ранга, I, II, III, IV, V]`. Потолки
контракта: 50 % опыта, 25 % добычи, +10 уровней навыка. Конфиг может задать
меньше, но не больше — выше значения обрежет `RankBonus`, чтобы витрина не
могла продать силу.

Если таблица бонусов записана с ошибкой (нечисло, короче шести значений),
она целиком откатывается на значения по умолчанию — сервер не падает.

### 1.3 Товары-ранги в каталоге

В `shop.products` десять карточек: пять месячных и пять годовых. Цена —
единственный ключ, по которому TradeMC находит товар, поэтому **цены должны
быть уникальными**:

| id | Цена, ₽ | Дней | rank |
|---|--:|--:|:--:|
| `rank-wanderer` | 99 | 30 | 1 |
| `rank-wanderer-year` | 990 | 365 | 1 |
| `rank-pathfinder` | 159 | 30 | 2 |
| `rank-pathfinder-year` | 1 590 | 365 | 2 |
| `rank-keeper` | 229 | 30 | 3 |
| `rank-keeper-year` | 2 290 | 365 | 3 |
| `rank-patron` | 299 | 30 | 4 |
| `rank-patron-year` | 2 990 | 365 | 4 |
| `rank-founder` | 365 | 30 | 5 |
| `rank-founder-year` | 3 650 | 365 | 5 |

Проверьте, что в каталоге нет других товаров с такими же ценами — иначе ядро
возьмёт первый по порядку и напишет в консоль предупреждение.

### 1.4 Продажи через TradeMC

```yaml
trademc:
  enabled: true
  shop-id: <числовой id магазина>
  payment-url: "https://trademc.org/..."   # витрина, её видят игроки
```

`trademc.enabled: true` выключает опросы DonatePay, EasyDonate и Boosty.
В панели TradeMC у каждой карточки в поле «команда при покупке»:

```
pass shoppay %username% <цена карточки>
```

Ядро сначала ищет товар по цене. Нашёл — выдаёт ранг (при повышении старый
срок пересчитывается по цене). Не нашёл — работает старый путь донатов, чтобы
не сломать уже настроенные карточки.

`donatepay.enabled`, `boosty.enabled` и `easydonate` оставьте `false`.

## 2. Модули

Все новые ключи необязательны: пустая или отсутствующая таблица означает
старое поведение. Ничего не сломается, если конфиг не трогать, — просто ранги
не будут влиять на лимиты.

| Модуль | Ключ | Значение по умолчанию |
|---|---|---|
| `CHRDK_Teleports` | `homes.rank-limits` | `[3, 4, 6, 8, 10, 12]` |
| | `costs.rank-discount-percent` | `[0, 10, 20, 30, 40, 50]` |

| `CHRDK_Claims` | `limits.rank-chunks` | `[24, 28, 34, 40, 44, 48]` |
| `CHRDK_Auction` | `rank-lots` | `[10, 12, 15, 18, 24, 30]` |
| `CHRDK_Queue` | `rank-priority` | `true` |
| `CHRDK_DailyRewards` | `vip.min-rank` | `2` |
| `CHRDK_BattlePass` | `premium.min-rank` | `4` |
| `CHRDK_Lottery` | `general.min-rank` | `0` |
| `CHRDK_Cosmetics` | `trails.*.min-rank` | по шлейфу |

Правила, которые стоит помнить:

- Скидка на телепорт **не делает его бесплатным**: базовая цена урезается, но
  минимум один алмаз остаётся (решение владельца от 24.10.2026).
- При истечении ранга дома и приваты сверх лимита **не удаляются**. Игрок
  сможет пользоваться ими, но новые создавать не получится, пока не вернёт
  ранг или не освободит место.
- Права LuckPerms по-прежнему приходят из группы товара (`group`), а ранг —
  отдельная запись в аккаунте. Ничего синхронизировать вручную не нужно.

## 3. Тексты и плейсхолдеры

- В `messages.yml` ядра секция `messages.presentation` теперь говорит
  «Приветственный ранг» и «Ранг активен». Если вы правили эти строки у себя,
  сверьте — старые тексты про проходку останутся вашими.
- Плейсхолдеры `%chrdk_rank%`, `%chrdk_rank_level%`, `%chrdk_rank_badge%`,
  `%chrdk_rank_status%`, `%chrdk_rank_until%`, `%chrdk_rank_days_left%`,
  `%chrdk_rank_xp%`, `%chrdk_rank_drop%`, `%chrdk_rank_skill%`.
- Старые `%chrdk_pass_%` работают, но возвращают ранговые значения:
  `%chrdk_pass_status%` → `активен / истёк / нет ранга`, `%chrdk_pass_left%` →
  «2 дн. 3 ч.» или «бессрочно». Скорборды и таблички не отвалятся, но слова
  в них сменятся.
- В табе `%player_tagged%` рисует знак и цвет ранга; настройка
  `tablist.player-name-format` не меняется.

## 4. Проверка после обновления

1. `/pass doctor` — хранилище, 2FA, права, провайдеры.
2. Зарегистрировать тестовый аккаунт: должен получить 3 дня Странника и
   увидеть «Приветственный ранг активирован».
3. `/rank` — витрина с пятью карточками; `/rank my` — свой ранг;
   `/rank top` — Меценаты и Покровители; `/rank rules` — границы продаж.
4. Из консоли: `pass shoppay TestPlayer 99` — должен выдать Странника на 30
   дней. `/rankadmin info TestPlayer` покажет ступень и срок.
5. `pass shoppay TestPlayer 3650` — Покровитель на год; проверить `/hat`.
6. `/papi parse <ник> %chrdk_rank_xp%` — число бонуса опыта (10 у Странника,
   50 у Покровителя).
7. `/pass reload` — конфиг перечитывается без рестарта, включая `ranks`.

---

## 5. Откат

- Вернуть платный вход: `pass.enabled: true`. Ворота, тексты и боссбар
  сохранены в коде целиком.
- Вернуть автопровайдеры: `trademc.enabled: false` и включить нужный
  (`donatepay.enabled`, `boosty.enabled`).
- Убрать бонусы: `ranks.bonuses` с нулями — тогда ранг даёт только лимиты и
  оформление. Код при этом не меняется.
- Убрать ранги совсем: `ranks.enabled: false` — витрина отключится, аккаунты
  сохранят ступени и сроки, повторное включение всё вернёт.

Данные аккаунтов не переписываются: `rankLevel`, `rankPermanent`, `passUntil`
и `tempRankLevel` живут в том же `data.json`. Бэкап перед обновлением всё
равно сделайте — `/pass backup`.
