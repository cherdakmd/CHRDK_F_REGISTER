# CHRDK_VK 1.5.2-rc.5 — дайджест стены сообщества (пререлиз)

**Это пререлиз только модуля `CHRDK_VK`.** Стабильный комплект `v1.5.2`
(KARAS UPDATE) не меняется: его тег, заметки и три ассета остаются в истории,
`Latest` по-прежнему указывает на `v1.5.2`. `plugin_version` в
`gradle.properties` оставлен `1.5.2`; версию `1.5.2-rc.5` получает только
этот JAR при сборке. `main`, GitHub Pages и PR в `main` не затрагивались.

## Что вошло

Один оформленный пост **в сутки** на стену сообщества ВКонтакте. Весь контур
работает в плагине на сервере: сбор игровых событий, агрегация суток, постер
1280×720 на Java2D, загрузка фото и `wall.post` от имени группы. GitHub Actions,
служебный чат, GitHub Issues и write-токен репозитория не являются
рантайм-зависимостями; CI нужен только для сборки и тестов.

- **Престиж** — прирост ступеней по `ChrdkSkillsApi.totalPrestige()` через
  `ServicesManager`, опрос раз в `wall-digest.poll-minutes`.
- **Поддержка сервера** — число выдач по `PassGrantedEvent`, тестовые платежи
  отсекаются.
- **Сервер** — пик онлайна и число новичков; тихий день пропускается.
- Советы, оперативные события и релизные новости остаются в беседе и на стену
  не дублируются. Владелец стены один — `CHRDK_VK`.

На публичную стену уходят только агрегаты: без сумм, названий товаров, UUID,
IP и времени входа. Имена лидеров выключены по умолчанию
(`show-player-names: false`), при включении уважается существующий opt-out
игрока из `/vk`.

## Надёжность

- Состояние суток, снимок престижа и дедуп — в `wall-digest.json` в папке
  плагина, запись атомарная через `.tmp` + `move`.
- Один пост в сутки в 21:00 Europe/Moscow; окно повторов пять минут, не более
  трёх попыток; скрытый маркер и стабильный `guid` на `wall.post`.
- Прерванная между `wall.post` и записью ledger публикация при рестарте
  пропускается, а не повторяется: дубль на стене хуже одного пропущенного дня.
- Адрес загрузки фото проверяется по allowlist доменов VK и только по HTTPS.
- Штатная перезагрузка конфига подхватывает расписание и ключ без рестарта.

## Что нужно сделать на сервере

1. Заменить **только** `chrdk-vk-1.5.2-rc.5.jar` вместо текущего
   `chrdk-vk-1.5.2.jar` и сделать полный рестарт. Остальные JAR комплекта
   обновлять не требуется: `CHRDK_Core` и `API_VERSION=42` не менялись.
2. Выдать ключу сообщества права **`wall` + `photos`** и сделать бота
   администратором сообщества. С ключом, рассчитанным только на беседу, пост
   не уйдёт — плагин напишет предупреждение в лог.
3. Проверить `community.group-id` и `community.access-token`.

Новые ключи `wall-digest.*` **необязательны**: при их отсутствии работают
безопасные значения по умолчанию, чужой `config.yml` не переписывается.
Отключение — `wall-digest.enabled: false`. Тонкая настройка: `hour`, `minute`,
`timezone`, `min-events`, `max-names`, `show-player-names`, `poll-minutes`,
`include-prestige`, `include-donations`, `include-online`, `title`, `footer`.
Схема миграций `vk/config-schema.yml` намеренно не вводилась, чтобы не
возвращать владельцу все стоковые ключи модуля.

## Границы

- Произвольные SKU-покупки магазина в дайджест не входят: для них нужен
  отдельный ивент ядра. Учитываются выдачи проходки/ранга.
- `wall.get` с ключом сообщества по-прежнему не используется;
  `wall.announce-new-posts` по-прежнему делает «стена → игровой чат».
- Python-контур `tools/social/` не менял своих запретов: `wall.post`,
  `wall.get` и `photos.saveWallPhoto` в нём по-прежнему недоступны.

## Проверки

Build ветки: **3782 теста / 24 модуля / 0 ошибок** (модуль `vk` — 131 тест,
включая 19 новых офлайн-тестов на агрегацию, клампы конфига, реальный PNG
нужного размера и всю цепочку `photos → wall.post` на fake-транспорте).
Вики — 39 страниц, Social automation offline — зелёный.

Живой `api.vk.com` в сборочной песочнице недоступен: реальная публикация на
стену, установка на игровой сервер, RCON, TradeMC и живой smoke не
выполнялись. Пререлиз предназначен для контролируемой проверки владельцем.
