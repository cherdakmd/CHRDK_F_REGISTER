# 1.4.231 — денежные награды кладоискателя в /bal

**Этап общей миграции, не отдельный релиз.** Core API 21 без повышения.
Публикации, установки и новых материалов TradeMC нет. После Treasures остаются
сквозной native/recovery/config-аудит и финальная проверка всего комплекта.

## Для игроков

- Алмазы за звания и пороги коллекции поступают в единый `/bal`.
  Физические денежные стеки не выдаются ни в инвентарь, ни на землю.
- Сохраняются прежние пороги/награды: звания 5/15/35/75/150 находок,
  коллекция — число **разных** найденных именных вещей, а не повторов.
- Осколки, опыт, специальные находки, предметный лут, карты, сеты и способности
  не конвертируются в деньги. Автоматического обмена всей прогрессии нет.
- Награда одноразовая на UUID и стабильный ключ (`rank:seeker`, `collection:20`).
  Сброс личного/общего прогресса не открывает её повторно и не удаляет долг.
- Уже принятая сумма не меняется при reload цен. Нулевая сумма также закрывает
  награду. Новый порог коллекции — отдельная новая награда за сохранённый прогресс.
- Лимит банка, его недоступность и пока неизвестный Core UUID оставляют очередь.
  Доставка повторяется автоматически, физического денежного fallback нет.

## Canonical source и миграция

`treasures.json` v2 объединяет прежний прогресс и `finance`: namespace
`treasures-income`, lineage, признак регистрации, UUID → ключ → frozen amount.
Накопленный доход вычисляется из неизменяемых claims, отдельного расходуемого
личного кошелька Treasures нет. Claims находятся **вне** reset-профилей.

При переходе с v1 все звания до сохранённого числа находок и явно отмеченные
`milestones` закрываются суммой 0: исторические выплаты не выдаются заново.
Сохранённые предметы, настройки, осколки и прочие счётчики остаются на месте.
Не отмеченный ранее порог может стать новой наградой при проверке прогресса;
файл v1 не содержит достоверной истории физических выплат сверх этих отметок.
Удалённую до обновления историю прежних reset восстановить из него невозможно.

Чтение строгое: версия, объекты, canonical UUID, типы, целочисленные диапазоны,
ключи наград и полная финансовая метаинформация. Повторяющиеся JSON-поля,
неверный синтаксис и trailing garbage не принимаются. Неоднозначный файл
останавливает модуль; shutdown не перезаписывает оригинал пустой структурой.

## Порядок принятия награды

До изменения прогресса вычисляется и проверяется полный план новых наград.
Находка, достигающая нового денежного/нулевого порога, записывает прогресс,
once-claims и суммы **одним durable replace до выдачи world/inventory loot**.
Админская/API-выдача именной вещи использует тот же порядок.
Обычный прогресс без новой once-награды сохраняется штатным async autosave.

Запись: file force → atomic replace → directory force. Snapshot и replace
удерживают тот же монитор, что финансовая операция: старое async-сохранение
не может затереть новое обязательство. Snapshot не снимает dirty; нужен durable ACK.
Переполнение счётчиков находок/предметов/серии/осколков не оборачивается в минус.

Ошибка IO/RuntimeException при записи переводит source в карантин. До rename
на диске остаётся прежнее состояние, после rename прогресс и обязательство
видны вместе. Неизвестный исход запрещает дальнейшую запись до перезапуска/сверки.
Это не повод удалять файл, менять lineage или сбрасывать банковские receipts.

## Доставка и ограничения

Production executor передаёт банку cumulative total. Банк начисляет только
разницу с сохранённой квитанцией: трата полученных денег и restart не повторяют
старую выплату. Конфликт lineage, потерянная регистрация и receipt больше source
останавливают доставку, без регистрации подменного namespace.
Раз в секунду ограниченно проверяются до 16 онлайн-профилей и до 16 получателей.
Сохранённый денежный долг может быть выплачен офлайн после подтверждения UUID.

Добыча сохраняет Survival/Adventure-проверку, требует авторизации и права
`chrdktreasures.use`, исключает NPC. Явная админская/API-выдача авторизованному
игроку допускается и в Creative, как выдача предмета, но не обходит once-claims.
Диагностика `/treasuresadmin awards` закрыта прежним `chrdktreasures.admin`.

**Предметы/playerdata/карта/мир не являются частью JSON-транзакции.** При сбое
между принятием находки и native-выдачей предметная часть может не дойти;
её автоматическая exactly-once доставка здесь не заявляется. Карта и её
потребление остаются прежней независимой native-границей. Новая интеграция
не делает независимые файлы и Minecraft playerdata распределённой ACID-системой.
Резервные копии банка, source/journal-файлов и playerdata снимаются согласованным
комплектом на остановленном сервере; независимый откат финансовых файлов небезопасен.

## Тихий режим

`feedback.find-notifications: false` теперь также выключает чат о званиях,
вехах коллекции и соответствующие broadcast. При включении учитываются личные
настройки уведомлений отправителя/получателя. Статистика, награды и звания
не исчезают; не добавляется отдельный финансовый чат на каждую находку.

## Проверки

29 новых `TreasureFinanceTest` используют настоящий source и `BankStore`:
rank/unique-collection/same-find, frozen/zero/dynamic awards, reset/resetAll,
v1 migration и повреждённые типы/метаданные/duplicate JSON, restart после траты,
cap/partial cap/down/unknown UUID, lineage/lost registration/receipt ahead,
необоснованный total, IO до/после rename и RuntimeException, dirty ACK,
переполнение и конкуренция async writer с финансовым commit. Контракты call sites
проверяют порядок до native loot, отсутствие денежного fallback, quiet mode
и permission-gate диагностики. Старый malformed-file тест теперь требует карантин.

Локально: контракт сообщений всех модулей, `git diff --check`, 22 теста существующей
витрины и 11 тестов release-validator. Существующая текстовая метаинформация
витрины синхронизирована только с номером версии; новых карточек/изображений/ZIP нет.
Полная сборка Root + 29 аддонов выполняется GitHub Actions Java 25/Purpur 26.3.
Это не live-проверка на Minecraft-сервере; отдельной установки/публикации нет.
