# 1.4.282 — линейка пререлизов RC1–RC16 (стабильного выпуска не было)

**Стабильного комплекта 1.4.282 не существует.** Номер остался за серией
пререлизов `v1.4.282-rc.1` … `v1.4.282-rc.16`: оформление клана и TAB,
справочники, наковальня, BattlePass и Кузня (`/shop forge`). Они собирались
из отдельной ветки `arena/49bc75f7` и в стабильный **1.4.283** не входили.

Теперь все 45 коммитов этой линейки влиты в пререлиз **1.4.284-rc.1** поверх
стабильного 1.4.283; версия `1.4.282` по-прежнему не используется как номер
стабильного комплекта, чтобы не обозначать одним номером разные исходники.
Администратору не нужно искать `chrdk-plugins-1.4.282.zip`. Полный порядок
обновления и границы — в [1.4.284.md](1.4.284.md).

---

## Заметки кандидата RC.16

Подготовлено исправление; стабильный релиз, установка на Minecraft-сервер и публикация TradeMC не выполнялись.

- Анимации aurora / shine / pulse / prism / flame передают готовые RGB-цвета символов. Кадр сохраняется после шаблона клана, сериализации, выделения метки в Core и финального рендера чата/TAB; односимвольный тег тоже меняет цвет.
- В TAB один общий таймер обновляет только имена с действующей анимацией. Теперь можно отключить общее периодическое обновление шапки (`tablist.refresh-ticks: 0`), не останавливая анимацию. Пустой/изменённый формат больше не гасит активную анимацию; явное tablist.enabled=false остаётся административным выключателем.
- В чат попадает кадр на момент отправки; история не переписывается. Красная/зелёная статусная рамка клана сохраняется, цвет эффекта остаётся внутри тега, ник/соседние метки не перекрашиваются.
- По отдельной команде владельца отменены ожидание переноса 24 часа, предложения участников и согласования. Менять, применять и снимать все четыре типа оформления может только текущий глава по своим действующим личным лицензиям. Покупки, цены и сроки сохранены.
- Участникам доступен предпросмотр без применения. Команды, клики и отложенные клики повторно проверяют роль; `clear` совместим с `off` и не стирает выбор других покупателей. Старые сохранённые варианты участников не подменяют выбор главы.
- При смене главы/выходе владельца из клана/истечении лицензии старый эффект выключается. Лицензии не удаляются и не передаются новому главе. Старый `clan-styles.json` schema 1 читается без удаления и без ожидания по movedAt.
- GUI и `/clan style status` показывают активную анимацию текущего клана. Stock-тексты об ожидании и согласованиях мигрируют только при точном совпадении; авторские тексты не перезаписываются. Текстовые материалы магазина обновлены без изменения утверждённых PNG и без публикации TradeMC.

## RC16 — Кузня: восемь PDC-расходников и `/shop forge`

RC16 воссоздан заново из закоммиченного RC14; утерянных некоммит-правок не использовалось.
Версия `1.4.282-rc.16` выставлена осознанно в `gradle.properties`, Core переведён на **API42**.
Java 25 / Purpur 26.3 / Gradle 9.7.1, полноценный JDK с `javac` — в CI GitHub Actions;
локальная песочница содержит только JRE и полную сборку выполнить не может.

- Раздел `/shop` получил кнопку «Кузня» (слот 46) и команду `/shop forge`; витрина показывает
  ровно восемь whitelist-SKU: `ascend`, `temper`, `reforge`, `seed`, `repair`, `inscribe`,
  `remove`, `name`. Цены за штуку: `128, 96, 160, 64, 24, 192, 32, 16` алмазов.
- Настройки `forge-shop.enabled`, `forge-shop.operations.<sku>` и `forge-shop.prices.<sku>`:
  неверная/нечисловая цена **закрывает** SKU вместо подмены дефолтом. Обратной скупки нет.
  Отключённая операция или незагруженный производитель `CHRDK_TierForge` не продаются.
- Оплата прежняя: сначала личный `/bal`, затем физическая недостача из 36 storage-слотов,
  целая сдача от крупных номиналов уходит на `/bal`. Штатный экран количества и отложенное
  подтверждение (`ShopQuantityGui`) повторно проверяют цену/производителя; искра — максимум 1.
  Запрещён путь «списать деньги и отдельно выдать `addItem`/командой».
- `ShopExchange` расширен nullable **frozen grant** при сохранении прежних конструкторов и
  receipts без grant. Грант — native `ChargeInventory` снимок ОДНОГО прототипа: слот 0,
  количество 1, остальные 35 пустые. `ForgeMarketCatalog` в Core проверяет whitelist SKU,
  материал, PDC `forge_material_v1`, канонический UUID искры и `max-stack-size=1`.
- `ShopInventory.replay` воспроизводит платёж и exact `isSimilar` clone insertion, сравнивая
  полный native after. Используются прежние `ShopStore`/`BankStore` WAL (`prepareForge` пишет
  pending без виртуального склада) — нового кошелька нет. Recovery принятой сделки не требует
  живого TierForge, текущих цен или нового источника расходников.
- Искра `seed`: только `QualifiedHuntKillEvent`, база 0.5% на ур.1 → 1% на ур.30 → 3% на
  элитном ур.30. Четыре остальных новых расходника по умолчанию **только в магазине**;
  неограниченного `EntityDeathEvent`-дропа не добавлено. У искры уникальный канонический UUID,
  покупка и админвыдача строго по одной, результат стабилен после переоткрытия наковальни/relog.
  `ForgeMaterial.seedUid` переводит 36-символьный UUID в действующий 12-hex modifier UID;
  сам UUID в `TierModifierIds.validUid` не передаётся.
- Только искра расширяет eligibility до вещи без тира; первая редкость фиксированная
  «Обычный». Неопознанные, уже tiered, неподходящие предметы и стопки отвергаются. Клон
  сохраняет чары, авторское имя, прочность и чужие PDC; случайные чары не добавляются.
  Семь тиров, прежние максимумы и PvP-формулы не расширялись.
- Новые действия: ремонт тир-вещи (6 уровней XP), выбранная отсутствующая ковка I (10 XP),
  удаление выбранной ковки без возврата (4 XP), другая кузнечная кличка (2 XP); искра — 8 XP.
  XP — **уровни, не очки**. На наковальне сохранены preview, ПКМ-выбор, полная цена XP,
  отложенная exact-snapshot ревалидация, anti-spam и rollback; preview входные вещи не меняет.
- `TierItems.refreshOwnedLore` остаётся migration-only. `forgeMaterialCopy` добавляет новый
  owned-блок **ОДИН РАЗ** после `refreshTierModifiers`; финальный append не удалялся.
  Custom/empty overrides владельца сохраняются, добавлен exact-stock снимок
  `tierforge-messages-legacy-1.4.282-rc15.yml`.
- Что **не** обещается: общей crash-atomic гарантии для Minecraft playerdata и разных
  плагинных файлов нет. Модельные/`source-inspection` тесты не заменяют native
  `CraftItemStack` codec и живой серверный smoke. Матрица непроведённого smoke:
  `docs/audits/forge-shop-rc16.md`.

## RC13 — характер и движение пяти эффектов

- Вместо одинаковых волн с разными цветами у каждого эффекта своё движение: aurora — широкая лента с ледяным гребнем; shine — направленный узкий блик; pulse — синхронное дыхание всего тега; prism — сглаженный бегущий спектр; flame — две связанные волны жара с тремя оттенками.
- В меню каждый эффект получил отдельную иконку и описание своего движения/ритма; preview по-прежнему ничего не выдаёт и не покупает.
- Для равномерного дыхания оставлен один цветовой компонент на весь тег; остальные эффекты проходят Unicode один раз. Не раздуваем одноцветный pulse покомпонентной разметкой.
- Один проход по Unicode, общий источник времени и прежний heartbeat; никаких задач на каждый клан, случайных вспышек, смены букв или переписывания истории чата.
- Дыхание асимметрично: 2 секунды вдох, 4 секунды выдох. Сохраняется достаточное количество различимых кадров даже при обновлении раз в 500 мс.
- Ритмы 4–6 секунд внутри бесшовного 12-секундного общего цикла. Проверяются реальные RGB после сериализации, короткие теги, движение блика и одновременность пульса.
- Пять прежних ID и действующая личная лицензия сохранены. Новых товаров, выдач, переносов прав и изменения сроков нет.
- RC13 не опубликован и не установлен. Проверка глазами в настоящем Minecraft и production MSPT не выполнялась.

## Проверка после отдельного разрешения на установку

1. Главе с действующим «Клановым комплектом» выбрать `/clan style animation aurora` (либо shine / pulse / prism / flame). Переключать все варианты и переносить в свой текущий клан можно сразу.
2. Проверить отказ участнику и офицеру через команды и старый открытый GUI. Сменить главу до отложенного клика: старый глава не должен применить оформление.
3. В TAB наблюдать смену RGB внутри статусной рамки. Отправить новые сообщения в разные моменты: кадры новых сообщений различаются, история неизменна. Проверить `refresh-ticks: 0`, затем восстановить настройку.
4. Проверить снятие/истечение лицензии и смену главы. Лицензии участников не списываются и не передаются. Старые выборы участников не включаются вместо выбора главы.
5. Перезапустить с существующим schema 1 clan-styles.json: данные сохранены, ограничение по старому movedAt отсутствует. Сделать backup Core и Guilds до установки.

Автотесты проверяют фактические цвета в полном пути клан → Core → чат/TAB для всех эффектов/шаблонов/коротких и экранированных тегов, неизменность старого сообщения, роль главы при смене руководства, мгновенный перенос/перезапуск и неизменность чужих покупок.

## RC.3: деньги BattlePass и накопление буста без потолка

- К часам XP-буста добавлены целые алмазы на личный `/bal`: 17 400 бесплатной дорожке, +8 700 рангу, +26 100 премиуму (52 200 за все дорожки, RC4: ×10 к RC3). Цели, ID, даты, очки и часы 222/216/366 сохранены; платные ранги/товары не выдаются.
- На каждой карточке показаны часы и деньги. Денежная часть имеет отдельную отметку: старый полученный буст не повторяется, деньги можно получить при выполненном задании и текущем доступе к дорожке. Первый банковский receipt фиксирует сумму: последующее изменение настройки не создаёт доплату.
- Core API39 сохраняет весь денежный приз и квитанцию атомарно. При полном `/bal` частичной денежной выдачи нет, квитанция не сгорает. Ошибка до/после atomic replace разрешается повтором без дублирования. BP подтверждает каждую часть только после durable ACK Core.
- `battlepass-money.json` — durable witness регистрации банковского домена. Не удалять и не обнулять. Если банковская регистрация исчезла, деньги fail-closed до сверки согласованных backup; буст и прогресс не удаляются. Незавершённая первая регистрация также требует сверки, если банк не подтверждает её.
- Накопленный запас буста больше не ограничен 24 часами или годом. Старый `reward-boost.max-bank-hours` игнорируется. +10% XP, общий предел силы XP +50% и расход только онлайн не менялись. Защита от переполнения машинного long остаётся технической, не игровым потолком.
- Стоковые 23 задания получают деньги по точному совпадению прежнего списка волн; пользовательские задания не переписываются. Для них доступны поля `free-diamonds`, `vip-diamonds`, `premium-diamonds` (целые неотрицательные суммы). Старые stock-подсказки мигрируют, авторские тексты сохраняются.

## RC.4: новый TAB, постоянно действующая анимация и деньги ×10

- Новая двухцветная RGB-шапка CHERDAK, бегущий разделитель, индикаторы TPS/MSPT и пинга,
  онлайн, мир, часы МСК, меняющиеся каждые 12 секунд игровые подсказки, личный банковский
  баланс и оставшийся +10% XP-буст. Баланс, буст, мир и советы закрыты до AUTHENTICATED.
  Авторские header/footer сохраняются; точный stock RC3 обновляется со snapshot/backup.
- Один heartbeat 5..20 тиков (stock 5) восстанавливает активные клановые имена. Имена
  используют лёгкий путь без полного контекста header/TPS/банка; шапка обновляется
  каждые два heartbeat. Равные header/footer и имена не отправляются повторно.
  В цикле нет сети, файловых операций и отдельных задач на клан/участника.
- Активная оплаченная анимация показывается всем вошедшим участникам независимо от
  ранга, мест/скрытия меток, chat-prefix, онлайна главы, refresh-ticks=0 и пустого либо
  пользовательского player-name-format. Для неё принудительно применяется безопасный
  player_tagged. При прекращении действия эффекта возвращается обычный формат;
  статические изменения обнаруживаются и при refresh-ticks=0 (не реже 8 heartbeat).
- Шесть рамок чата/TAB теперь собираются с RGB-телом как независимые компоненты:
  `*-prefix-open` / `*-prefix-close`. Внешний старый gradient или шаблон без `%tag%`
  не перекрашивает/не удаляет оплаченный анимированный тег. Статические теги продолжают
  использовать прежние авторские шаблоны. У активной анимации рамку настраивать новыми
  ключами; цвета статуса по умолчанию сохранены.
- `/pass tabcheck [ник]` доступна только admin/консоли: probe 30 тиков, не более 16
  одновременно и одного на цель. Результат: нет активной лицензии/входа, TAB выключен,
  нет кадров, кадры замерли, последнее имя перезаписано, замеченная перезапись исправлена
  либо кадры движутся. Счётчик учитывает промежуточные кадры (pulse может вернуть тот же
  цвет). Задачи/кэши очищаются при выходе, reload и shutdown. Это НЕ клиентский smoke-test.
- Деньги всех 69 призов stock увеличены ровно ×10: FREE 17 400, VIP дополнительно
  8 700, PREMIUM дополнительно 26 100, всего 52 200 💠. Размеры по заданиям:
  FREE 400/600/800/1000/1200; VIP 200/300/400/500/600; PREMIUM 600/900/1200/1500/1800.
  Отдельный snapshot RC3 сохраняет старый pre-money snapshot. Миграция — только при
  точном совпадении всего stock списка; пользовательские суммы/задания не переписываются.
  Уже выплаченная сумма receipt неизменна: без автоматической доплаты/повторной выдачи.
  Новые неполученные призы используют новые суммы. Личные деньги, durable receipts,
  witness, часы, цели, даты, ID и очки не менялись.

## RC.5: дополнительный аудит жизненного цикла TAB

По выбору владельца продолжается аудит, не релиз/установка. Найдены и исправлены:

1. Общий refresh/join сразу отмечает активное имя: если эффект снят, лицензия истекла,
   провайдер отключён или участник вышел из клана ДО первого heartbeat, кадр снимается
   на ближайшем heartbeat, а не ждёт восьмого статического обновления.
2. Смена стадии входа принудительно обновляет имя/шапку даже при refresh=0 и
   dashboard-animation=false. Прежние приватные поля не застревают после потери входа;
   это изменение представления, не обход/переписывание авторизации.
3. Пользовательский header/footer с player_tagged получает декорированный ник на
   каждой перерисовке; чередования со строкой без меток больше нет.
4. Join/quit refresh объединяется в одну отслеживаемую задачу на ближайший тик.
   Reload/shutdown отменяют её вместе с таймерами и probes. Отложенная задача не
   может воскресить выключенный TAB. При массовом одновременном входе нет отдельного
   полного прохода онлайн-списка на каждого входящего.
5. При освобождении TAB удаляются только ещё совпадающие с нашим последним кадром
   имя/header/footer. Уже установленное внешним плагином оформление не стирается.
   Во время работы проверяется фактический header/footer, так что cache не скрывает
   чужую перезапись даже при постоянном авторском тексте.
6. Быстрые активные и обычные player_tagged имена не строят полный контекст;
   скрытая/пустая шапка не читает персональный header-контекст. Для каждой группы
   строк массив placeholders собирается один раз, а не заново для каждой строки.
   Недоступный TPS отмечается неизвестным, а не выдуманными 20 TPS.

Новый TabLifecycle282Test запускает настоящий TabListService через внутренний порт
окружения: управляемые часы, очереди задач и Player-компоненты в памяти. Проверены
14 сценариев: снятие/expiry до первого heartbeat, auth-переходы, custom player_tagged
в шапке, hidden header, чужая перезапись/снятие владения, disable/late task, 200 join
за один тик, 30 reload подряд, все основные probe-ветки, доступ/лимиты, возврат к
custom-формату, quit и отзыв admin-permission, dedup постоянных кадров. Число задач,
кэшей, полных контекстов, декораторов и отправок проверяется утверждениями.

**Границы доказательства:** это детерминированный компонентный прогон реального

### Найдено и исправлено

- BP ранее обновлял stock weeks через getConfig()/saveConfig(): без отдельного
  backup, а saveConfig() может поглотить ошибку записи. Теперь BattlePassStockMigration
  строго читает реальный YAML без наследования defaults, сопоставляет точный список

- При неподтверждённом результате после atomic replace файл проверяется при следующем
  reload: либо старый stock мигрирует, либо уже новый остаётся без повторной записи.

  файловой системой. На symlink stock-конфиг автоматически не заменяется: нужна ручная
  миграция целевого файла. За время подготовки перед replace повторно проверяется,

детерминизм UID + paid sequence, сохранение чужой metadata/чар/прочности не меняются.

Отложенная выдача повторно проверяет полные обе вещи, количество, выбранное окно,
rename, настройки, итог, цену, режим, auth, право, расстояние до реальной наковальни,
курсoр и XP. Одновременные клики не ставят две выдачи. Предмет результата содержит
только настоящее оформление, без интерфейсных подсказок. Ошибка изменения слотов
откатывает входы/XP; это не обещание crash-atomic сохранения playerdata при аварии JVM.

**Core API40:** общий cost bridge позволяет обычной починке/книгам/соединению
превысить ванильные 39 уровней. Из-за жёсткой логики клиента визуальный счётчик
ограничен 39, **но полная цена дорогой операции сообщается в чате и списывается
полностью** при ЛКМ с пустым курсором. Это не скидка и не обход конфликтов.
Чистое переименование сохраняет ванильную скидку до 39. Без валидного результата
вещь не выдаётся. Чары HIGH → общий bridge HIGHEST: доплата читается по полной цене,
проверки mixed/pure book, повторного prepare, source generation и overflow сохранены.
Ручная выдача сохраняет расход второго слота и износ с AnvilDamagedEvent Paper.
Обычные дорогие операции доступны и в Adventure с ванильной оплатой; Spectator
не забирает результат. Расходники Hunt по-прежнему только для Survival.

Точные стандартные RC9 тексты мигрируют в памяти без записи поверх файла владельца;
собственные/пустые остаются. Старый стандартный лор расходников обновляется при входе
или открытии наковальни без изменения PDC/чужого оформления. Вики и игровые карточки
используют одни descriptions. Обновлять весь комплект, в том числе Core/Enchants/
TierForge/Hunt, совместно. Никакой установки/публикации/слияния/релиза этим не выполняется.

### Обязательный игровой smoke RC10 перед разрешённой установкой

1. Все три расходника, каждый доступный выбор ПКМ, максимумы, несовместимое/неопознанное
   снаряжение и поддельный обычный материал. Проверить количество и XP ровно один раз.
2. Убрать вход/закрыть окно/сменить мир/выполнить reload между кликом и следующим тиком;
   ни платы, ни выдачи. Спам кликами, Shift, цифры, двойной клик, курсор занят, недостаток XP.
3. Preview/ПКМ/закрытие/relog не меняют будущий результат; оплаченная перековка меняет
   ровно выбранное ✧. Проверить имя/прочность/UID/чары/чужие PDC и netherite-перенос.
4. Обычная ванильная починка/соединение/книги при ценах 39/40/80+; ниже полной цены
   отказ без потерь, при достатке — ровно полная плата, правильный остаток материала.
   Чистое дорогое переименование — не более 39. Сломанная наковальня/защита её износа.
5. Чистая и mixed кастомная книга при цене 40+, повторы prepare/смена имени/конфликт/
   reload. Не удваивать доплату; устаревший preview не забирается, vanilla-запреты остаются.
6. Точный старый stock messages/лор обновляется, авторские и пустые строки сохраняются.
   Слияние, старая ковка, амeтистовая настройка, обычные операции дешевле 40 не ломаются.

CI компилирует весь комплект и проверяет unit/контракты/вики; реальный клиентский
smoke, playerdata после аварии и MSPT требуют отдельного staging, не подменяются CI.


### Совместимость со скидкой профессии «Кузнец»

Professions теперь использует API40 price bridge. Enchants/TierForge softdepend
Professions обеспечивает явный порядок HIGH: скидка native-части → custom-книга/
фиксированный расходник → Core full-price transport. У скидки сохраняется прежний
процент, доплата кастомных чар не скидируется, фиксированные цены расходников
не меняются. Повтор готового preview не накладывает скидку ещё раз; свежий native-
пересчёт того же действия получает одну скидку. Скидка считается с полной цены,
а не с экранных 39. Чистое переименование ограничивается 39 до скидки, поэтому
прежняя скидка кузнеца с 39 (например, 35 при 10%) тоже сохранена. Все три аддона
обновлять совместно с Core API40.


## RC11 — аудит пограничных сценариев RC10 и устойчивость CI

- Core handler полной ручной оплаты теперь исполняется в новых компонентных тестах
  с подменяемыми адаптерами auth/доступа/звука/логгирования, а не заменяется собственной
  тестовой реализацией. Проверяются 40/80 уровней, остаток материала, повторный клик,
  режимы, право входа/доступ, неподдержанные клики, занятый курсор, все поля quote,
  close, невозможный расход и откат после исключения в каждом из пяти этапов мутации.
- Пустой/нулевой result не становится quote; современный ItemStack.isEmpty учитывает
  нулевое количество, а не только Material. Отменённый event явно отвергается и при
  прямом вызове обработчика. Rename-only cap не обрезает цену изменения чужой metadata.
- **Core API41 AnvilPaidResultEvent** — синхронное неотменяемое read-only событие только
  после ручной оплаты/выдачи Core. Копии входов/результата защищены от изменения слушателем.
  Native take и preview его не вызывают, ошибка/откат тоже. Enchants требует Core API41
  и по этому событию восстанавливает потерянное уведомление нового/усиленного проклятия
  на дорогом результате. Обычная native-нотификация по-прежнему уважает отмену клика.
- 13 новых Core test methods (внутри — матрицы кликов/состояний/сбоев), 2 Enchants tests.
  Модель ItemStack и платформы не является CraftItemStack и не доказывает поведение
  реального клиента/сети/диска playerdata. Баланс, шансы Hunt, стоимость, команды и материалы
  не изменены. Авария JVM не объявляется crash-atomic транзакцией.
- Build workflow получает bounded retry: максимум 3 попытки с паузой 15с только при
  распознанной ошибке разрешения/загрузки зависимости + transient transport причине.
  Все failure-секции --continue должны соответствовать этому правилу. Compiler/test/
  OOM/401/403/404/PKIX/unknown ошибки завершают job сразу, даже вместе с сетевым сбоем.
  Финальный exit code сохраняется; каждая попытка имеет отдельный диагностический log.
  10 Python-тестов политики/runner, включая реальный subprocess без сети.

Перед выпуском остаётся отдельный live smoke обычной наковальни/клиента и проверка
сохранения playerdata на staging: [матрица RC11](../testing/anvil-rc11.md).
Это подготовка кандидата, не релиз, merge, установка, Pages или TradeMC-публикация.


### RC11: закреплённый официальный PlaceholderAPI для CI

После трёх корректных повторов Maven extendedclip продолжил таймауты в обеих проверках.
CI теперь получает официальный GitHub plugin release PlaceholderAPI 2.12.3,
проверяет фиксированный SHA-256/размер/классы и передаёт только compileOnly файл всем
восьми потребителям. Это не тонкий Maven JAR и не случайный mirror; та же версия API,
официальный distributable с закреплённым digest. Никакой упаковки в наш комплект или
установки внешнего плагина нет; локальная сборка без свойства остаётся Maven-сборкой.
Pin и границы описаны в evidence-документе. 7 дополнительных Python-тестов проверяют
атомарную подготовку/cache, подмену/неверный JAR/размер/отказ сети и охват build-файлов.
