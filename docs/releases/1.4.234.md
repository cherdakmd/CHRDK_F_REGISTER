# 1.4.234 — DiamondShop: сохранность источника и точный импорт

**Промежуточный этап аудита, без публикации релиза и установки. Core API 22.**
Это фундамент для журнала сделок магазина, а не заявление о завершённой
транзакционности DiamondShop. Последовательность `exchangeDiamonds → учёт рынка`
пока остаётся отдельным блокирующим пунктом общего релиза.

## Исправления

### Старый остаток — только вход миграции

- Удалены старые `ShopStore.addBalance/trySpend`: магазин больше не предоставляет
  методов пополнения/расхода второго кошелька. В рабочих сделках они уже не
  использовались; личные средства остаются в `/bal`.
- Исходные значения `balances` теперь хранятся и сохраняются как `BigDecimal`,
  без промежуточного преобразования в `double`. Округление вверх выполняется
  **над точным значением из shop-data.json**, после проверки предела банка.
- Например, `1.00000000000000000000000001` переносится как 2, а не как 1.
  Очень малая положительная дробь переносится как 1, а не как 0. Хвост дроби
  выше предела счёта не округляется вниз до разрешённой суммы.
- Большие обязательства (включая не представимые в double) сохраняются точно,
  но не импортируются сверх банковского предела. Нулевые входы не создают денег.
  Неизвестный UUID/неработающий Core/предел по-прежнему оставляют обязательство.
- Core-квитанция однократного импорта сохранена. Preview старого значения может
  быть приблизительным; финансовое решение использует только canonical source.

### Запись и чтение shop-data.json

- Snapshot больше не снимает `dirty`: простое чтение JSON не подтверждает запись.
- Snapshot, запись и финансовые мутации рынка используют общий монитор.
  Старый async writer не может записать устаревший снимок после новой мутации;
  следующая мутация после ACK снова ставит `dirty`.
- Запись: временный файл → file force → atomic replace → directory force → ACK.
  Нет прямого усечения основного файла и нет неатомарного fallback.
- IOException или RuntimeException останавливают writer. Неопределённый исход
  после rename не превращается в успешное сохранение; shutdown не затирает файл.
  Новые покупки/продажи/импорты отказываются через прежний health-gate.
- `/shopadmin stock` при остановленном хранилище не сообщает ложное успешное
  изменение. Reload конфигурации не снимает финансовую блокировку.
- Строгий JSON reader отвергает duplicate keys, trailing garbage, комментарии,
  неправильные таблицы, UUID-алиасы, дробные/переполненные integer-счётчики,
  повреждённые UTC-окна и историю. Некорректные строки больше не пропускаются
  с тихим восстановлением нулевого оборота/счётчика.
- Весь источник проверяется до публикации в память. Повреждение поздней строки
  не публикует половину прочитанного состояния. Оригинал не перезаписывается.
- Неизвестные корневые поля запрещены, чтобы старый writer не удалял будущие
  финансовые журналы при downgrade. Предел файла 64 MiB, вложенности 64,
  истории 4096 точек, мантиссы/scale старой суммы — 10 000.
- Snapshot товара теперь включает копию истории; внутреннее ItemState не
  выдаётся как изменяемая ссылка через публичный lazy getter.
- Отрицательные/нечисловые/нулевые запросы дневного оборота и нечисловой/отрицательный
  лимит отклоняются. Для нормальных настроек цены, spread, партии, сутки UTC,
  существующее поведение выключенного дневного лимита и права не менялись.

## Проверки

27 новых `ShopDurabilityTest`: точность дробей на границах 0/1/cap,
огромные обязательства, read-only вход, snapshot/dirty, IO до/после rename,
runtime-неопределённость, отказ дальнейшей записи и импорта, actual NIO round-trip
запаса/оборота/лимита/истории, гонка async writer с мутацией, некорректный JSON,
UUID/числа/UTC-окна, отсутствие частичной публикации, изоляция snapshot,
каталог вместо файла, размер/вложенность и production call-site точного импорта.
Старые wallet-тесты заменены чтением исторических fixtures: больше не создают
новые денежные остатки через удалённые мутации. Это не live crash-test Minecraft.

Локальные проверки: messages всех модулей, diff, существующие 26 карточек витрины,
22 её регрессионных теста и 11 тестов release-validator. Версия обновлена только
в существующей текстовой метаинформации витрины, без новых карточек/изображений/ZIP.
Полная проверка — Root + 29 аддонов в GitHub Actions, Java 25/Purpur 26.3.

## Следующий обязательный шаг

Нужен сохранённый intent всей сделки: frozen котировка/партия/план inventory,
подтверждение Core и playerdata, затем идемпотентное применение stock, статистики
и **принятого UTC-окна** ровно один раз. Падение между Core-обменом и учётом рынка
этот этап **ещё не устраняет**. Атомарная запись одного shop-data.json не является
ACID-транзакцией с bank.json/playerdata.

Остаются также земельные платежи/аренда Claims, денежные награды DailyRewards
и обычные алмазы Treasures loot, затем повторный сквозной census. Общий релиз —
только после закрытия всех gates, ZIP 30 JAR + `ОБНОВЛЕНИЕ.txt`, без установки.
