# 1.4.244 — обновлятор принимает настоящий ZIP-only релиз

Исправление **F02** из [аудита 1.4.242](../audits/full-project-1.4.242.md).
Комплект: **26 плагинов**, **Core API 27**, Purpur 26.3 / Java 25.
Схемы данных, пароли, добровольная TOTP, банк и игровые механики не меняются.
Защита административных команд из 1.4.243 сохраняется.

## Единый формат

В релиз по-прежнему публикуется только `chrdk-plugins-<версия>.zip`:
26 JAR одной версии и `ОБНОВЛЕНИЕ.txt` внутри. Отдельные JAR-asset не нужны
ни для публикации, ни для проверки обновлятором. Посторонние assets не
используются как источник доверия к плагинам.

Workflow и интеграционный Java-тест используют один stdlib-упаковщик
`.github/scripts/pack_release.py`. Он проверяет полноту модулей, версии,
CRC JAR, ограничения размеров и памятку, создаёт новый плоский ZIP через
временный файл и проверяет результат. Старый ZIP не дополняется; при уже
существующем выходном файле упаковщик отказывает. Публикация остаётся ZIP-only.

## Что проверяет обновлятор

- Только опубликованный стабильный релиз; точные имя, GitHub URL, целый
  положительный размер и SHA-256 ZIP из метаданных GitHub. Нельзя обходить
  отсутствующий digest или автоматически переходить на непроверенные JAR.
- **До распаковки** сверяются размер и SHA-256 всего архива. Он покрывает
  все байты вложенных JAR и памятки; отдельные хеши JAR-assets не требуются.
- Полный набор 26 известных имён JAR, даже если установлен только Core
  или часть аддонов. Проверяются plugin.yml, имя, единая версия, Minecraft
  API, главный класс и допустимая версия Java.
- Обязательная непустая UTF-8 памятка без NUL. Допускаются UTF-8 BOM и CRLF;
  памятка проверяется, но не копируется в `plugins/update` как плагин.
- Нет каталогов, чужих файлов, повторов JAR/памятки, вложенных и обходящих
  пути имён. Лимиты: ZIP и суммарное распакованное содержимое — 64 MiB,
  один JAR — 32 MiB, памятка — 2 MiB.
- Не понижаются версии, не перезаписывается занятый `plugins/update`,
  не допускаются symlink и дубли установленных CHRDK-плагинов. Снятые
  аддоны требуют ручного разбора, автоматически их JAR не удаляются.
- Живые JAR не заменяются: сохраняются их исходные имена, проверяется
  отсутствие изменения во время операции, делается backup JAR, вся
  подготовленная пачка публикуется одним атомарным rename. Ошибка проверки
  не оставляет частичную установку; shutdown и конкурентные вызовы закрыты.

`/pass update check` проверяет стабильные метаданные ZIP без скачивания и
без записи файлов. Полнота содержимого проверяется при `download`.
Скачивание исполняемого кода остаётся доступным только Console/RCON;
внутриигровому OP оно не открывается. Другие прежние проверки прав сохраняются.

## Проверки

Фикстуры обновлятора теперь по умолчанию содержат **единственный ZIP-asset**
и памятку внутри, а не искусственный набор отдельных JAR-assets.
Интеграционный тест вызывает именно workflow-упаковщик Python 3, затем
передаёт его ZIP настоящему updater stage, проверяя отсутствие изменений
живого JAR и установку только выбранных модулей. Поэтому для полного
набора Java-тестов нужен Python 3 (`python3`), как в CI.

Регрессии покрывают отсутствующие JAR/памятку, повреждение digest/размера,
дубликаты, чужие файлы и пути, неверную UTF-8, BOM/CRLF, ограничения размеров,
несовместимые plugin/API/Java, переименованные JAR, backup и остановку.
Python-тесты упаковщика включены в Build и Release. Имена архивов модулей
в Gradle сверяются с реестром обновлятора, лимиты — с упаковщиком.

## Первый переход и ограничения

**Старый обновлятор 1.4.243 и более ранних версий сам содержит F02.**
Для первого перехода на исправленный код использовать ручную установку
полного комплекта при штатно остановленном сервере. Не возвращать отдельные
JAR в GitHub-релиз ради обхода старой ошибки. После установки исправленного
ядра подготовка следующих совместимых ZIP-only релизов возможна штатно.

Перед установкой нужен согласованный backup данных, мира, playerdata и
журналов. Backup обновлятора содержит JAR и не заменяет такой снимок.
Не удалять аккаунты, TOTP-секреты, банк, source lineage или квитанции.
Для старых установок сохраняются инструкции снятия модулей
[1.4.239](1.4.239.md), [1.4.241](1.4.241.md), [1.4.242](1.4.242.md),
включая сверку pending-выплат до удаления старых JAR.

F03–F12 и эксплуатационные риски аудита этим шагом не объявляются
исправленными. Релиз и установка на рабочий сервер не выполняются.
