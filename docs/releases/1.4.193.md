# 1.4.193 — игровые награды отдельно от платных прав

## Исправлена причина, а не только поздравление

`pass.enabled: false` отключал платный вход, но не запрещал аддонам продлевать
`passUntil`. Этот срок одновременно считался рангом I. Теперь игровая награда
пополняет отдельное поле `rewardBoostMillis`, не изменяя проходку, ранг,
постоянную/временную ступень, покупки, статистику оплат и группы LuckPerms.
Она не отправляет уведомление `pass.granted` и не вызывает событие покупки.

Буст даёт **+10% обычного XP Minecraft, опыта профессий и навыков**. Бонус
аддитивный, а не множитель поверх ранга; потолок XP +50%, округление до единицы.
Дроби мелких начислений сохраняются отдельно для трёх видов опыта. Суточный
потолок профессии применяется после буста; уровни навыков, добыча, права и
платные товары от буста не меняются.

Время расходуется только после авторизации, прекращается при выходе из
аккаунта/сервера и остановке плагина. Остаток и дроби сохраняются в общем
`data.json`; офлайн-таймеров нет. Штатное выключение сохраняет последний расход.
При аварийном завершении возможен откат последних списаний до очередного
сохранения — как у остальных данных с асинхронной записью.

Повторная награда продлевает время, а не процент. Старый час награды = час
буста. `reward-boost.max-bank-hours: 24` задаёт общий запас, максимальная
настройка — 8760 часов. При заполненном запасе избыток не выдаётся; интерфейс
ядра сообщает фактически добавленные минуты. Остаток виден в `/profile`.

## Проверенные источники и закрытые обходы

| Источник | Новое поведение |
|---|---|
| Достижения | Отдельный буст вместо продления платного срока |
| Батлпасс: бесплатная, VIP и премиум-ветки | Только бусты; платные товары исключены |
| Старые `premium-products` батлпасса | Не выдаются, предупреждение валидации; продуктовая награда без часов заменяется 1 ч. буста |
| Эфиры Twitch/VK Play Live и зрители-фолловеры | Часы буста; прежние условия подтверждения и лимиты сохранены |
| Ежедневки, рефералы, артефакты, кузня тиров, заказы | Буст вместо платного времени; обычные игровые предметы/коллекции сохранены |
| Первая регистрация | 3 ч. буста по `reward-boost.welcome-hours`, 0 отключает; не 3 дня ранга |
| Звания за стаж | Памятные звания сохранены, за новое звание настраиваемый буст; произвольные консольные награды не выполняются |
| `grantPassHours` старого API/хранилища | Совместимый адаптер к бусту, не к проходке |
| Игровые `grantRank`, `grantRankPermanent`, `grantPass`, `grantEntitlement`, `ShopService.grantInternal` | Платные права не выдают, в том числе с поддельной строкой источника `shop:`/`donatepay:` |
| `/pass add`, `grant`, `gift`, `/rankadmin give` | Свободная выдача закрыта; просмотр и отзыв сохранены |
| Тестовые платежи и тестовые консольные действия | Не выдают права и не выполняют платёжные команды, даже при `pass-group-paid-only: false` |
| Автомиграция по сумме всех покупок | Больше не повышает ранг и не превращает срок в постоянный |
| Консольные действия каталога | Только внутри подтверждённой покупки |
| Произвольные donation-actions | Только после успешной реальной оплаты; не после теста/ожидания/отказа |

У стримов удалены объявления даты платного ранга после награды. Неуспешное
самоподтверждение платежа не пишет ложное сообщение об активации. Сохранён доступ
к VIP-наградам уже существующих постоянных рангов без даты окончания. Асинхронный
вызов награды сохраняет буст сразу, откладывая только сообщение в главный поток.

API v12: `grantRewardBoostHours`, `rewardBoostRemainingMillis`,
`boostExperience`. Старые сигнатуры не удалены. Исправлено также копирование
полей оплаченной ступени/постоянного ранга в снимках аккаунтов.

## Реальные оплаты и обязательное изменение RCON-команд

**До установки обновить команды витрины. Старые команды без номера платежа
отклоняются, чтобы не оставлять свободную выдачу.** Только консоль или RCON:

```text
pass shopbuy Nick rank-wanderer payment=trademc:12345
pass shopgift Friend nick-aurora Nick payment=trademc:12346
pass shoppay Nick 99 payment=trademc:12347
```

Вместо примеров нужны реальные id товаров своего каталога и реальные уникальные
номера оплаченных заказов. Последний аргумент обязателен. Одинаковую оплату
нельзя повторно оформить другой командой. Если панель не умеет подставлять
уникальный номер заказа, **не подставлять постоянный или случайный номер**:
пока не настроен такой хук, подтверждать покупки вручную по реальным квитанциям.

Это **подтверждение владельцем/доверенной платёжной интеграцией**, а не проверка
квитанции по одному текстовому номеру. Консоль/RCON остаётся административной
границей доверия. Номер резервируется на диске до выдачи, сохраняются оператор,
операция и исход. Повтор и неопределённый исход после сбоя блокируются до
сверки. Не обходить блокировку новым номером. Токен подтверждения одноразовый. Произвольный срок вместо оплаченного периода карточки запрещён.
Выдача по неоднозначной цене запрещена. Оплаченный подарок допустим.

DonatePay/EasyDonate продолжают проверять реальные транзакции. Подтверждение
`/pass approve` допускает только ожидающий, нетестовый, достаточно оплаченный
платёж и срок его тарифа; повторное подтверждение не продлевает права снова.

## Старые данные: без опасного автоматического обнуления

`/pass paidaudit` создаёт JSON в `paid-audit/`: сроки, ступени, покупки,
последний источник, агрегаты оплат и журнал подтверждений. Пароли, TOTP и IP
не включаются. Это **отчёт для сверки**, не исправление старых сроков.

Уже выданные до обновления игровые продления и бесплатные товары автоматически
не отзываются и не превращаются в буст: последняя метка источника и общая сумма
покупок не позволяют отделить оплаченные дни от наград. Перед очисткой нужны
резервная копия, квитанции провайдера, журнал продаж/аудит и прежние снимки.
Сверить каждую спорную покупку/срок; смешанные и неизвестные случаи оставить
на ручной разбор. Чистка по одному `lastGrantSource` запрещена.

## Конфиги, тексты, границы аудита

Новые ключи наград: `boost-hours`, `vip-boost-hours`,
`free-boost-hours`/`vip-boost-hours`/`premium-boost-hours`,
`boost-hours-chance`. Старые `pass-hours`, `*-hours`, `pass-days` и их варианты
продолжают читаться, но выдают только буст. `ranks.welcome` и `pass.trial` не
могут вернуть бесплатный платный ранг даже в старом пользовательском конфиге.

Обновлены сообщения, описания, справка, витрина и автообъявления. Стоковая
презентация мигрируется сравнением со снимками; пользовательские файлы не
перезаписываются. Известные старые формулировки игровых сообщений и объявлений
нормализуются при загрузке в память. Произвольные авторские тексты необходимо
дополнительно просмотреть: автоматическая замена не понимает любую формулировку.

Аудит охватывает исходники и поставляемые конфиги всех модулей репозитория,
публичный API, прямые записи прав и места выполнения консольных команд.
Доступа к боевому серверу, его данным, изменённым конфигам, внешним плагинам,
LuckPerms, алиасам, панели платежей и RCON-настройкам нет. Их аудит и сверка
исторических выдач **не объявляются выполненными**. Нельзя запускать на сервере
недоверенные плагины: плагины одного JVM технически могут изменять чужие файлы
и права вне публичного API.

Перед установкой: полная копия данных/LP/конфигов; проверка на копии сервера;
обновление RCON-хуков; затем остановка, замена JAR без удаления данных и
проверка `/profile`, выдачи награды, офлайна, перезапуска, реальной покупки и
оплаченного подарка. Тег и GitHub-релиз — только по отдельной команде.
