# 1.4.232 — native proof и первая часть сквозного аудита

**Не отдельный релиз. Core API 22.** Публикации/установки нет: аудит выявил
оставшиеся блокирующие пути. [Подробный реестр и следующие gates](../audits/native-economy-1.4.232.md).

## Исправления

- Общая предметная доплата Lottery/CommonGoals/Teleports/claim tp/Guilds теперь
  проверяет native nonce, а не считает совпавший AFTER-inventory доказательством.
  Требуются также банковская квитанция и точный исходный/итоговый source.
- Новый production executor `InventoryTransfer`: storage+nonce сохраняются в
  playerdata **до** публикации результата. Повторный nonce не списывает/не выдаёт
  вещи заново, но требует успешный checkpoint текущего playerdata. Это закрывает
  случай, когда прежний saveData бросил исключение, а nonce остался лишь в памяти.
- Orders использует тот же checkpoint перед публикацией денежного дохода.
- Guilds разрешён в Core allowlist с `chrdkguilds.use`. Раньше отсутствие source
  в switch могло отклонять создание/взносы, несмотря на правильный модульный WAL.
  Unknown source, отсутствие прав/auth, NPC и неправильный план по-прежнему запрещены.
- Auction: доплата cash, выставление и выдача посылки используют native proof.
  Новый transferId хранится в pending; деньги/товар не публикуются по одному AFTER.
  Полностью банковская покупка не требует онлайн-покупателя и не трогает storage.
- Старый предметный pending аукциона без transferId не угадывается и не удаляется:
  требуется сверка market.json с playerdata. Новые операции могут завершить
  сохранённый запрос из BEFORE после restart. Имена ключей аукционного PDC
  отделены от Root BankChargeGuard: ложные orphan charge-маркеры не создаются.
- RuntimeException при финансовой записи BankStore/ChargeJournal/PaidActionStore/
  AuctionStore теперь также переводит writer в карантин, включая неизвестный
  исход после rename. Shutdown не перезаписывает его старым in-memory снимком.

## Что аудит ещё не разрешает публиковать

Core deposit/withdraw, DiamondShop и земельные/арендные операции Claims ещё
используют прежние callback-связки: необходим отдельный durable native recovery.
В BankService.withdraw найден страховочный денежный drop — убрать вместе с
переходом на storage-only журнал, а не скрыть потерю предметов локальной правкой.

Дополнительно в стандартных конфигах найдены обычные алмазные награды DailyRewards
и безымянные DIAMOND/DIAMOND_BLOCK в Treasures loot.yml. Отсутствие отдельного
кошелька не делает эти выходы частью `/bal`: они добавлены в блокирующий реестр.
Именованный амулет, экипировка, XP/осколки/ключи и материальные рецепты остаются
предметной прогрессией. Новые adapters должны учитывать и старые пользовательские
конфиги, а не только изменить поставляемые YAML.

## Проверки и границы

36 новых тестов: 10 InventoryTransfer, 14 NativeRecoveryAudit, 11 AuctionTransfers,
1 дополнительный Orders. Настоящие BankStore, ChargeJournal, PaidActionStore и
AuctionStore проверяют receipt/source-публикацию, restart, неопределённый saveData,
повторный checkpoint, отсутствие повторного consume/grant, BEFORE/AFTER без nonce,
чужой UUID/недоступный native port, bank-only, потерянный receipt, legacy pending,
allowlist Guilds и runtime IO после rename. Fake используется только для native
playerdata; это не live crash-test Minecraft.

Старые матрицы recovery и call-site контракты обновлены под обязательное proof.
Локально проверяются сообщения всех модулей, diff, 22 теста существующей витрины
и 11 тестов release-validator. Номер версии синхронизирован только в существующей
текстовой метаинформации витрины: новых карточек/изображений/архивов нет.
Полная Java 25/Purpur 26.3 сборка выполняется для Root и всех 29 аддонов.

Обновление потребует совместимый Core API 22 и комплект аддонов. Независимые
файлы/мир/playerdata не становятся распределённой ACID-системой; независимый
откат не поддерживается. Резервные копии — согласованным комплектом на остановленном
сервере. Условия общего ZIP-релиза и установки остаются прежними.
