# 1.4.207 — единое меню косметики и этап 3 плана

## Косметика: исправление по скриншоту

Причина буквальных `<red>`/`<gradient>`: готовое MiniMessage-имя шлейфа из
серверного конфига передавалось в сообщение как обычный, экранируемый текст.
Теперь доверены **только собственные названия из конфига**, не произвольный
ввод игрока. В GUI имена превращаются в Adventure-компоненты; текстовый
список и подтверждения используют `Messages.trusted`. Общий механизм
экранирования Messages не ослаблен.

### Одна точка входа

- `/cosmetic` — главное GUI; `/cosmetics` и `/cos` сохранены как алиасы.
- Кнопка «Косметика» в `/menu` ведёт туда же. **Старый пункт `cosmetics list`
  тоже открывает GUI**: не требуется стирать или вручную пересобирать меню.
- `/cosmetic trails` — выбор шлейфа; настоящая пагинация по 45 записей,
  выбранное/закрытое/приостановленное/недоступное состояние и отключение.
- `/cosmetic off` — отключить шлейф; `/cosmetic <id>` — прежний прямой выбор.
- `/cosmetic text` — явный текстовый список с корректными цветами/градиентом.

Главное меню объединяет шлейфы, личный переключатель эффекта входа, палитру
ника, общую видимость надписей, конкретные места, пресеты и `/hat`.
Карточка питомца/кличка доступна отдельной кнопкой при установленном Pets.
Цвета, надписи, места и пресеты открывают уже существующие родные GUI ядра,
а не вторые независимые настройки. В меню надписей добавлена кнопка возврата
ко всей косметике; внутри палитры/пресетов сохраняется прежняя навигация.
Ник остаётся первым, не занимает место; явные назначения не подменяются.

**Меню ничего не продаёт, не покупает и не выдаёт платных прав.** Премиум-цвета
по-прежнему требуют активной реальной покупки, даже у V. Цвет/пресет
проверяет существующая LabelPalette. `/hat` применяет настоящий блок основной
руки и прежние проверки ранга/админ-права, не создаёт копию. Карточка питомца
не выдаёт животное, уровень или косметический предмет.

### Доступ, эффекты и сохранение

- Авторизация и `chrdkcosmetics.use` проверяются для команд, открытий,
  отложенных кликов и показа эффектов. Выбор шлейфа проверяет текущий доступ
  и совместимость частицы; истечение доступа приостанавливает показ, но
  сохраняет выбор. При отключении определения он не стирается из файла.
- Эффект входа воспроизводится после `PlayerAuthCompletedEvent`, один раз
  за подключение, с проверкой текущего снимка настроек/покупки/ранга и
  личного предпочтения. По умолчанию предпочтение включено, как раньше.
- Шлейф и публичная вспышка не раскрывают invisible/vanished-игрока. Звук
  входа слышит сам игрок. Исправлен registry ID звука по умолчанию;
  старый `entity_player_levelup` поддержан как совместимый alias.
- Явно пустой `product` означает ранговый эксклюзив и больше не превращается
  автоматически в `trail-gold`/`trail-aurora`: набор пяти каталожных шлейфов
  не открывает эти два эффекта без нужного ранга. Для отсутствующего поля
  прежний автоматический `trail-<id>` сохранён.
- Количество частиц и числовые параметры ограничены; NaN/Infinity не
  передаются в spawnParticle/playSound. Предупреждения частиц ограничены.
- Все клики/drag закрыты для переноса GUI-предметов. Серверный holder хранит
  владельца/снимок/действие; не используется клиентское имя/lore как команда.
  Переходы разрешены только по фиксированному списку команд от самого игрока,
  без консольной эскалации. После смены окна/выхода/reload старый клик не
  открывает GUI. Очередь — максимум одно действие на UUID, всего до 4096.
- Reload/disable закрывает GUI и отменяет ожидающие действия. Выбор и новый
  флаг входа сохраняются асинхронно каждые 100 тиков через SafeJsonWriter,
  финальная запись — при штатной остановке. Один writer не допускает, чтобы
  старое async-сохранение перезаписало более новое финальное.

`cosmetics-data.json` прежнего формата UUID→шлейф читается без потери выбора.
При следующем изменении записывается v2 с `trails` и `join`; в `join` хранятся
только отключения. Перед обновлением нужна резервная копия; старый JAR не
умеет читать v2, откат требует соответствующей копии данных. Старые
настройки messages.yml не удаляются; новые GUI-тексты берутся из defaults.

## Продолжение 25 улучшений + 35 нововведений

Косметика — отдельный запрос, **в 60 пунктов не засчитывается**.

Выполнены **I13, I15 и N28**. Всего **18/25 улучшений + 15/35 функций = 33/60**.
Остаются **7 улучшений и 20 нововведений**; [реестр](../roadmaps/mobs-enchants-60.md).
Каталог пока остаётся 70 чар. Остальные пункты не заявляются готовыми.

- **I13:** строгая проверка всего набора PDC до переноса книги. Неизвестный
  ID, неверный/запредельный уровень, дубли, оборванный токен или неправильный
  тип PDC отклоняют перенос целиком. Проверяется и цель. Preview и получение
  результата проверяют текущие входы/auth/permission; повреждённая книга не
  расходуется частично. Терпимый кодек старых эффектов не переписан.
- **I15:** очередь стола ограничена 4096 действиями и одним ticket на игрока;
  очищается при reload/disable. Старый ticket не заберёт новый с тем же UUID.
  Некорректный финальный ванильный набор пропускается без исключения и
  добавочного результата; точное сравнение с оплатившимся ванильным
  результатом и финальная отмена сохранены. Это не возврат стоимости
  ванильной операции при отказе в бонусной чаре.
- **N28:** `/enchants sources` — действующие настройки стола, библиотекарей,
  мобов, книг в кладах и предложений за осколки: шансы, пулы, потолки.
  Моб-шансы используют ту же функцию ограничения, что настоящий обработчик.
  Клады предоставляют read-only API `ChrdkTreasureBookInfo` из нормализованного
  runtime-снимка своего конфига, а не повторно разбираются другим плагином.
  При отсутствии совместимого модуля отчёт не подставляет выдуманные defaults.
  Процент книги на найденный клад не выдаётся за процент на каждый блок;
  условия мира, прогресса, доступных пулов и антифермы остаются в силе.

**I14 (цена наковальни), I16 (отмена смерти), I25 (атомарный reload)** остаются
планом, а не закрываются побочными правками этой версии. Новые покупки,
множители наград, боевые эффекты и старое PvP этой задачей не менялись.

## Проверки и установка

15 новых unit/contract-тестов: отображение цветных имён/градиента и сохранение
экранирования ввода, пагинация, миграция/сохранение, закрытый эксклюзив,
ограничения параметров, защитные контракты GUI, проверка целой книги,
нетипичная ванильная выдача, шансы и живой снимок кладов.

Полная сборка всех модулей, проверка сообщений, вики и упаковки выполняются
на общей версии. Unit/contract-тесты не заменяют живой smoke-test клиента:
`/menu`→косметика, цвета/градиент, number-key/drag/shift, отзыв доступа,
reload с открытым GUI, вход с 2FA, сохранение после перезапуска, палитра
премиум-цветов без покупки и повреждённая книга в наковальне.

Обновлять все JAR одной версии на остановленном сервере после резервной
копии. Конфиги и данные не удалять. Тег, GitHub release и установка на
сервер не выполнялись: для них нужна отдельная команда.
