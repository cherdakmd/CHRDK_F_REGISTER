# 1.4.211 — добровольная 2FA и защита новичков

## Вход: приложение по желанию

- `totp.enabled: true`, `totp.required: false` по умолчанию, в том числе в parser fallback. Регистрация/пароль, ограничения до авторизации, captcha и защита от перебора не выключены.
- Без привязки после регистрации или пароля можно играть. Добровольное подключение: `/2fa setup` → приложение/QR → `/2fa confirm <код>`.
- **Привязанный аккаунт продолжает требовать код**: `/login <пароль> [код]` или `/2fa <код>`. IP-сессия при `auth.session-skips-2fa: false` восстанавливает лишь шаг пароля. Секреты, пароли, replay-защита и данные игроков не сбрасываются.
- Отключение своей 2FA — после полного входа, `/2fa disable <код_или_пароль>`. Потеря приложения: проверка владельца администрацией и `/pass reset2fa <ник>`.

### Существующие серверы

При старте и `/pass reload` до чтения настроек выполняется **однократная** миграция:

1. Строго читается настоящий `config.yml` без подстановки новых defaults. При ошибке YAML замена не выполняется.
2. Создаётся точная резервная копия `config-before-optional-2fa-1.4.211.yml`; существующий бэкап не перезаписывается.
3. `totp.required` и `auth.session-skips-2fa` становятся `false`. Это касается и старых добровольных конфигов: ранее разрешённый обход кода по IP отключается ради сохранения защиты привязанных аккаунтов.
4. Ставится `migrations.optional-totp-1-4-211: true`. YAML записывается через временный файл и атомарную замену, где она поддерживается; сохраняются POSIX-права исходного файла. Прочие значения и комментарии сохраняются; комментарий обязательности обновляется. `data.json` не открывается миграцией.

Новый стоковый конфиг уже содержит маркер и не требует бэкапа/перезаписи.
После успешной миграции администратор может осознанно включить `totp.required: true` обратно: следующие запуски/перезагрузки не изменят этот выбор. Маркер не удалять; восстановление старого бэкапа без маркера запустит миграцию снова.

Ошибка бэкапа/записи видна в консоли без вывода секретов: старый конфиг остаётся, ядро авторизации не отключается. Ручной переход — `totp.required: false`, `auth.session-skips-2fa: false`; выключать `totp.enabled` для этого не нужно.

При смене обязательного режима на добровольный через reload завершается вход **только** ожидающих принудительной привязки, уже подтвердивших пароль и ещё не включивших TOTP. Сохраняются anti-multi-alt, запись сессии, обычный cleanup авторизации и аудит. Незавершённый принудительный ключ удаляется. Ожидающих код уже привязанного аккаунта или ещё не подтвердивших пароль это не авторизует.

README, первые шаги/FAQ вики, комментарии и сообщение перехода обновлены. Из первых шагов также убрано устаревшее обещание бесплатного платного ранга за вход: ранги только за покупку.

## N19 — опциональная защита новичков

В `CHRDK_Hunt/config.yml` добавлена секция:

```yaml
mob-progression:
  newcomer-protection:
    enabled: false
    max-skill-total: 20
    radius: 16
```

Только при **первом природном появлении** враждебного моба ищется любой новичок рядом, а не лишь ближайший игрок. В смешанной группе ветеран может быть ближе, но видимый новичок в радиусе всё равно защищает группу: уровень нового моба становится минимумом географического диапазона, вариант элиты — обычным.

Условия: авторизованный живой Survival-игрок, право `chrdkhunt.use`, не NPC/неуязвимый, прямая видимость от моба, 3D-радиус 16 блоков включительно, суммарный уровень CHRDK_Skills 10–20. Без Skills безопасный fallback — 10. Порог зажат в 10–50, радиус — в 4–24; NaN/Infinity заменяются на 16.

- По умолчанию защита **выключена**; старые серверы не меняют баланс самопроизвольно.
- Сохраняются финальная отмена spawn, generation/reload guard, исключения чужой PDC, NPC, питомцев, боссов и неприродных причин.
- Уже существующие мобы не пересчитываются при подходе/выходе игрока, загрузке чанка или reload. Уровень и вариант фиксированы.
- Минимум региона сохраняется: Энд/дальний мир не превращаются в стартовую зону.
- Нет изменения агро, PvP, приватов, имён, опыта, монет, осколков, ключей или множителей наград. Обычный моб получает обычный шанс/тир книги; подавленная элита не сохраняет элитный шанс.
- Нет отдельной очереди/вечного списка новичков, сообщений в чат или дополнительного сканирования всех миров. Проверка использует уже существующий ограниченный поиск игроков при spawn.

## Счётчики и проверки

План: **23/25 улучшений + 23/35 нововведений = 46/60**. В этой волне закрыт N19; добровольная 2FA — отдельный пользовательский запрос, не искусственный пункт плана. Остаются 2 улучшения и 12 функций. Каталог не менялся: **74 чары = 59 светлых + 15 проклятий**.

Добавлены **20 Java-тестов**: 13 для миграции/политики TOTP и 7 для защиты новичков. Проверяются точный бэкап, повторная миграция, старые/новые/неполные/выключенные конфиги, ошибки YAML/бэкапа, POSIX-права, неизменность файла аккаунтов, пароль/TOTP/replay, комбинации сессий и безопасного освобождения стадии привязки; mixed-group, границы/нечисловые настройки, минимумы всех измерений и spawn-only контракты.

Java-тесты и source-контракты не заменяют **live-smoke**. На живом сервере отдельно проверить: новый аккаунт без приложения; старый привязанный аккаунт и IP-сессию с обязательным кодом; неверный/повторный код; добровольное подключение/отключение; reload в стадии привязки и стадии кода; N19 off/on в смешанной группе, стену/радиус и неизменность существующих мобов.

Версия всех модулей повышена совместно. Подготовлены памятка обновления и метаданные TradeMC без изменения товаров/цен. Тег, GitHub Release и установка — только по отдельной команде; live-smoke в этой волне не выполнялся.
