# 1.4.265 — точность и безопасное обновление TierForge

## Исправления

- Лор сохраняет дробные бонусы: +1.2% / +2.4% скорости, −2.5% брони вместо
  округления до целого. Хвосты двоичной арифметики вроде 89.99999999999999%
  не показываются. Броня и твёрдость теперь тоже видны в плашке.
- Формулы не усилены: легендарное оружие +60% к атрибуту урона, инструмент
  +90% скорости добычи, деталь брони +15% к атрибутам брони/твёрдости и +6%
  скорости. Это модификаторы атрибутов, не обещание такого же снижения
  конечного входящего урона. Разные MULTIPLY_SCALAR_1 перемножаются.
- Отпечаток версии 4 учитывает роль, реальный процент и политику свойств.
  Изменение процента при reload больше не оставляет старую силу на предмете.
- Отключённые свойства больше не участвуют ни в атрибутах, ни в событиях.
  Применяются только свойства своего тира/роли и в пределах текущего лимита.
  При обслуживании сохранённый список PDC не стирается и не переролливается:
  после обратного включения подходят те же свойства, не новые случайные.

## Миграция без новой выдачи

Обновление атрибутов отделено от полной выдачи `apply`: не запускает броски
свойств/имён/зачарований, не возвращает снятые точилом чары, не дополняет
недостающие свойства случайными. UID, исходные уровни ковки, свой список
PDC, кличка, источник и чары сохраняются. Снимаются только собственные
модификаторы namespace TierForge; ванильная база сохраняется/дополняется,
пустой компонент не перекрывает ванильные значения.

Известная плашка и точно распознанные строки свойств/аффиксов обновляются;
чужие строки не удаляются за один похожий маркер ✧/◆ или начало названия тира.
Для аффиксов учитываются прежние наборы при всех допустимых потолках:
изменение max-good могло менять и последующий случайный выбор дефекта.
Если пользовательский блок редкости не распознан, лор сохраняется как есть,
а атрибуты всё равно обновляются. Выбранный визуальный стиль по-прежнему
управляет своим блеском; неизвестный чужой override не снимается как «свой».

Подбор, смена рук/слота, клики/перетаскивание/закрытие инвентаря, вход и
возрождение запускают один объединённый проход на следующем тике. Изменённые
стеки явно записываются в соответствующие слоты, включая броню/вторую руку.
Reload обслуживает онлайн-инвентари. Сундуки не сканируются глобально:
их содержимое обновится после перехода в инвентарь. Доставленные сторонними плагинами старые предметы
обрабатываются следующим подходящим событием/reload/входом, не новым таймером.
Это не универсальная проверка произвольного прямого редактирования PDC:
изменять уровни и свойства следует штатными операциями, а не подменой ключей.
Отрицательный кэш экипировки при reload сбрасывается: обратное включение
свойств не ждёт его прежнего 30-секундного TTL.

## Оружие снаряда

Тир и суммарный «Снайпер» фиксируются в PDC снаряда при выстреле из фактического
лука/арбалета, включая вторую руку и залп, или из предмета брошенного трезубца.
Смена оружия, его передача/изменение и reload после выстрела не подменяют снимок.
Попадание использует прежнюю формулу: исходный урон × (1 + бонус тира) ×
(1 + сумма бонусов Снайпера), без повторного сложения уровней.

Снимок не потребляется первым попаданием: пробивающая стрела сохраняет свой
бонус для остальных целей. Он хранится с сущностью, без бессрочного UUID-кэша.
Нейтральный/нестрелковый снаряд не заимствует бонус из текущей руки стрелка.
Для старых стрел/трезубцев допускается только сохранённое оружие самой сущности;
при отсутствии источника бонус не угадывается. Старый фейерверк без снимка не
получает случайный бонус от руки. Повреждённые/неизвестные снимки нейтральны;
валидация покрывает все допустимые сочетания текущего каталога.

## Проверки и границы

Регрессии: дроби для всех процентов −50..60, отпечатки конфигурации, отключение/
повторное включение сохранённых свойств, чужие тиры/роли, все варианты потолков
аффиксов, бережный и повторный лор, неизменность снимка и формула Снайпера,
повторные попадания, повреждённый PDC и границы каталога. Сохранены остальные
тесты. Полная сборка Java 25 всех 25 модулей, сообщения, архив, вики и браузер
проверяются в CI. Minecraft-world smoke и установка отдельно.

Новые цены, усиление потолков, новая экономика и переработка PvP-правил не
добавляются. Это не полный аудит всех 85 событийных свойств и взаимодействий
со сторонними плагинами. Артефакты 1.4.264 сохранены без изменений.

## Установка

Только `chrdk-plugins-1.4.265.zip`: 25 JAR одной версии + `ОБНОВЛЕНИЕ.txt`.
Остановить сервер, сделать согласованный backup миров/PDC/playerdata и данных
плагинов, заменить весь комплект вручную, без `/reload`. Не удалять JSON/WAL.
CHRDK_Queue не возвращать в `plugins/` или `plugins/update/`. Откат обновлённого
лора/меты — из backup. Core API 31 и схемы JSON не менялись. Minecraft-сервер
не трогали, TradeMC не готовится и не публикуется.

Отдельный smoke: старый предмет после точила/с чужой метой, изменение силы
тира, выключение/включение свойств и аффиксов, перенос из сундука в броню/вторую
руку. Выстрелить, сменить оружие до попадания; обычная стрела плюс легендарный
лук в руке, лук из второй руки, залп/пробивание, трезубец/фейерверк, reload и
сохранение сущности. Сравнить силу, лор, UID, PDC, имя, чары, ванильную базу и
повторный проход без накопления. CI не заменяет эти мировые проверки.
