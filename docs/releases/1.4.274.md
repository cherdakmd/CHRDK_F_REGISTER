# 1.4.274 — игровые постеры и проверка подключения ВКонтакте

Вместо технического фона — утверждённая владельцем AI-иллюстрация в стиле
блочного игрового мира: дом у реки, горы и закатный свет. Это не скриншот
настоящего сервера. Локальный рендер добавляет крупный заголовок и короткую
подпись; полные правила и команды остаются в тексте поста. Все темы проходят
проверку вёрстки; иллюстрация хранится компактным JPEG, результат — PNG1280×720.

В ручном workflow добавлен `mode`:
- `preview` — прежнее превью, без вызовов VK и без журнала;
- `check_connection` — проверка `wall.get` и `photos.getWallUploadServer`,
  без загрузки фото, `wall.post` или записи журнала. Не выдаётся за доказательство
  доступа к двум непроверенным методам сохранения фото и публикации;
- `test_post` — **один настоящий пост** после preflight, только вручную на main,
  без включения расписания. Долговечный ключ `test:1.4.274` защищает повтор запуска
  от дубля. Подтверждения в GitHub Issues и защита неопределённой отправки сохранены.

В режимах проверки `publish` должен быть выключен, `kind=tip`, тег пустой.
Обычная отправка по-прежнему требует отдельного разрешающего флага. Новый
режим теста не меняет Variables и не включает автоматическое расписание.
Ошибки имеют имя метода и числовой код, попадают в GitHub Annotations, но не
содержат ключ, сырой ответ VK или подписанный URL загрузки.

Ключ сообщества с правами «стена/фотографии» не объявляется заранее ни совместимым,
ни несовместимым: проверяется доступ конкретных методов. Не подменяются ключи
игрового бота и не запрашиваются секреты в чате. При отказе preflight публикация
не выполняется; режим не обходит ограничения VK.

Основной комплект:22JAR+памятка, Core API33; игровые данные/правила без изменений.
Minecraft и TradeMC не меняются, релиз не публикуется. Результат живой проверки
следует оценивать отдельно по журналу workflow, не по офлайн-тестам.
