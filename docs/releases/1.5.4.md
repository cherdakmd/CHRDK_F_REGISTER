# CHRDK 1.5.4 — встроенная группа модератора

## LuckPerms и Core

- `/pass luckperms setup` идемпотентно создаёт группу `moderator`: вес 50,
  родитель `default`, права панели, наказаний и аудита.
- В группу не входят полный `chrdkregister.admin`, назначение модераторов, OP,
  wildcard, обход привязки или права аддонов.
- `/pass moderator add|remove <ник>` синхронизирует роль Core и LP-группу;
  `list` показывает состав, `status <ник>` проверяет обе стороны.
- `/adminpanel moderator add|remove` и GUI используют ту же синхронизацию.
  Повтор команды исправляет старую роль без группы или потерянную группу.
- `integrations.lp-moderator-socialspy: false` по умолчанию: личные сообщения
  модератор не видит без отдельного решения владельца и повторного `setup`.

## Границы

LuckPerms остаётся опциональным. Без него роль Core продолжает работать, но
LP-права наказаний не выдаются. Core и LP — разные хранилища, общей транзакции
нет: итог LP сообщается отдельно, ошибку нужно исправить повторной командой.

## Обновление и проверка

Обновить общий комплект до 1.5.4 с полным перезапуском, затем из консоли:

```text
pass luckperms setup
pass moderator add <ник>
pass moderator status <ник>
```

Старые роли в `moderation.json` сохраняются; production-назначение модераторов,
живой LuckPerms и smoke на сервере этой разработкой не выполнялись. До Release
требуется полный Java 25 CI; состав групп, запрет эскалации и opt-in socialspy
покрыты JUnit.
