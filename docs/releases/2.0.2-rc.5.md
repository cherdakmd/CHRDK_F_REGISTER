# CHRDK DiamondShop 2.0.2-rc.5

**Пререлиз только `CHRDK_DiamondShop`.** Усилен суточный лимит доплаты горячей
скупки 5000 ⛁. Общий ZIP и остальные JAR не публикуются.

## Durable-резерв до сделки

Прежний порядок записывал расход бонуса после денежного WAL. Ошибка записи или
аварийная остановка между этими операциями могла оставить часть доплаты неучтенной.

Теперь порядок такой:

1. Рассчитанный бонус атомарно резервируется в `promotions-data.json`.
2. Только после успешного сохранения создаётся и принимается `ShopExchange`.
3. Если WAL не принял сделку, резерв снимается.
4. Если WAL принят, резерв сохраняется при любом результате последующего recovery.
5. После успешной продажи записываются только единицы; бонус повторно не списывается.

Если прогресс невозможно сохранить, продажа продолжается по обычной цене **без
бонуса**. Это fail-closed поведение для эмиссии: обычный магазин не блокируется,
а лимит 5000 не обходится. Ошибка снятия резерва непринятой сделки оставляет лимит
зарезервированным — безопасная потеря доступного бонуса, но не лишняя выплата.

Пять ресурсов, ротация каждые 6 часов, +50%, цены, сделки и остальной магазин не
изменены. Существующий `promotions-data.json` сохраняется; вайп не требуется.

## Установка и проверка

Остановить сервер, сохранить backup и заменить только DiamondShop на
`chrdk-diamond-shop-2.0.2-rc.5.jar`. Остальные плагины остаются 2.0.1.

Продать горячий ресурс и убедиться, что остаток бонуса уменьшился сразу. После
полного restart остаток должен сохраниться. Обычная продажа без бонуса работает
как прежде.
