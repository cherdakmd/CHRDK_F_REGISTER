# CHRDK 1.5.2-rc.12 — MySQL storage каркас и offline migrator

**Дата:** 3 ноября 2026 года
**Версия API:** 42 · **Storage API:** 1
**Базовая версия:** Purpur 26.3 (Java 25)

## Краткое содержание

Первая итерация централизованного хранилища на MySQL: каркас NIO FileSystemProvider, DocumentStore API, DDL 55 таблиц, inventory 55 файлов, offline migrator с 7 normalized parsers и 3 DB-aware adapters. Это позволяет аддонам работать с данными в MySQL через единый API без изменения бизнес-логики.

## Что нового

### Storage API v1
- **ChrdkStorage**: сервис с `DocumentStore`/`DocumentSnapshot` и `StorageMode {FILE, MYSQL, FILE_READONLY}`
- **ChrdkStorageFileSystem**: custom NIO `FileSystemProvider` с inventory-based routing — DB-bound файлы идут в `chrdk_storage_file`, остальные на filesystem
- **ChrdkStoragePaths**: Bukkit-aware wrapper, заменяет 46 raw `getDataFolder().toPath()` на `dataFolder(plugin)`, оставляет 6 намеренных путей (database.yml, plugins parent, update folder, paid-audit, internal legacy lookup)
- **ChrdkDatabase**: custom bounded `DriverManager` pool (size 8), SHA-256 CAS, schema migration, DDL checksum verification (fail-closed при mismatch), `redacted()` без credentials
- **JdbcDocumentStore**: `documents/<key>.json` namespace isolation
- **ChrdkStorageImpl**: owner-scoped `DocumentStore` factory, throws для non-MYSQL

### DDL и inventory
- **database-schema.sql**: 55 таблиц (player/account/entitlement/purchase/bank/milestone/paid-action/social/vk), normalized schema, `STORAGE_API_VERSION=1`
- **storage-inventory.json**: 55 runtime JSON/YAML файлов с target/strategy/secret_class/checksum_policy
- **database.yml**: `backend=FILE|MYSQL|FILE_READONLY`, env placeholders (`CHRDK_DB_HOST/NAME/USER/PASSWORD`), TLS/pool/timeouts

### Offline migrator
- **tools/db/migrate.py**: CLI для offline cutover legacy JSON/YAML → MySQL
  - `--dry-run`: scan source-root, report SHA-256/size/status без записи
  - `--import`: write в normalized таблицы с idempotency (`ON DUPLICATE KEY UPDATE`)
  - `--verify`: post-import check из `chrdk_migration_source` по batch
  - `--report`: JSON output для аудита
- **7 normalized parsers**: per-table parsers для критичных strategies
  - `normalize_player`: `data.json` (schema 4) → `chrdk_player/account/entitlement/purchase_receipt/store_delivery/donation_journal/processed_donation/payment_code/purchase_cursor`
  - `normalize_finance`: `bank.json` (schema 8) → `chrdk_bank_account/cash_receipt/income_source`
  - `normalize_social`: `social-links.json` (schema 2) → `chrdk_social_global/chat`
  - `normalize_social_players`: `players/social.yml` (schema 1) → `chrdk_social_player/link`
  - `normalize_moderation`: `moderation.json` → `chrdk_moderation_global`, `players/warns.yml`/`bans.yml` → `chrdk_sanction`
  - `normalize_exploration`: `exploration.json` → `chrdk_exploration`
  - `auth_reset`: `vk-second-factor.json` → `chrdk_auth_reset`

### DB-aware adapters
- **MilestoneMigration.tierForge**: `StoragePath` → `Files.readString` + `YamlConfiguration.loadConfiguration(Reader)`, legacy `File` → `yaml.load(file.toFile())`
- **StatsBackup**: `StoragePath.resolveSibling` автоматически создаёт DB paths, `rotate()` работает с DB через NIO API
- **ShopCatalogMigration**: `StoragePath` → `loadConfiguration(Reader)` + `saveToString()`, legacy `File` → `yaml.load/save`

### CI contracts
- **.github/workflows/build.yml**: новый step «Verify storage inventory and schema contracts» перед Build plugin
- **tools/db/test_contracts.py**: 6 тестов проверяют sync между Python generators и Java constants
  - `STORAGE_API_VERSION` / `storage_api_version` match
  - `ChrdkRegisterApi.API_VERSION` / `api_version` match
  - `database-schema.sql` SHA-256 == `StorageSchema.DDL_CHECKSUM`
  - `PROJECTED_TABLES` все существуют в DDL
  - inventory files имеют валидные strategy/secret_class/checksum_policy
  - secret files перечислены в secret_exclusions

## Изменения в коде

- **build.gradle**: Connector/J 8.3.0 `compileOnly` (админ кладёт драйвер для `backend=MYSQL`)
- **RegisterPlugin**: storage init после `ConfigUpgrader`, fail-closed disable на ошибке, `FILE_READONLY` блокирует запуск
- **46 Java файлов** переведены на `ChrdkStoragePaths.dataFolder(plugin)`, 6 намеренных raw paths оставлены
- **SocialPlayerStore/ModerationPlayerStore**: DB-bound YAML через `StringReader` (не `File`)

## Совместимость

- **API_VERSION=42**: без изменений, обратно совместимо с rc.11
- **STORAGE_API_VERSION=1**: новый API, доступен через Bukkit `ServicesManager`
- **backend=FILE**: legacy JSON/YAML backend, работает как раньше
- **backend=MYSQL**: требует MySQL 8.0+ и Connector/J на classpath (админ кладёт в `plugins/CHRDK_Core/libs/`)
- **backend=FILE_READONLY**: только для офлайн-сверки мигратора, блокирует запуск сервера

## Установка

1. Скачайте `chrdk-register-1.5.2-rc.12.jar` и поместите в `plugins/`
2. Для `backend=MYSQL`: скачайте MySQL Connector/J 8.3.0 и поместите в `plugins/CHRDK_Core/libs/`
3. Настройте `plugins/CHRDK_Core/database.yml`:
   ```yaml
   backend: MYSQL
   mysql:
     host: ${CHRDK_DB_HOST}
     port: 3306
     database: ${CHRDK_DB_NAME}
     user: ${CHRDK_DB_USER}
     password: ${CHRDK_DB_PASSWORD}
     tls: true
   ```
4. Установите env variables: `CHRDK_DB_HOST`, `CHRDK_DB_NAME`, `CHRDK_DB_USER`, `CHRDK_DB_PASSWORD`
5. Запустите сервер — schema применится автоматически с checksum verification

## Миграция с FILE на MYSQL

1. Остановите сервер
2. Запустите offline migrator:
   ```bash
   python3 tools/db/migrate.py --dry-run --source-root plugins/CHRDK_Core
   python3 tools/db/migrate.py --import --source-root plugins/CHRDK_Core --batch rc12-20261103 \
     --db-host localhost --db-name chrdk --db-user root --db-password secret
   python3 tools/db/migrate.py --verify --batch rc12-20261103 --db-host localhost --db-name chrdk \
     --db-user root --db-password secret
   ```
3. Измените `database.yml`: `backend: MYSQL`
4. Запустите сервер

## Откат

1. Измените `database.yml`: `backend: FILE`
2. Запустите сервер — legacy JSON/YAML файлы останутся на filesystem
