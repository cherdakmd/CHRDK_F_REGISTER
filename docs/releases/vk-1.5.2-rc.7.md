# CHRDK_VK 1.5.2-rc.7 — пять постов стены и `/vkadmin testcard` (пререлиз)

**Это пререлиз только модуля `CHRDK_VK`.** В релизе ровно один ассет —
`chrdk-vk-1.5.2-rc.7.jar`. Общий ZIP комплекта, `CHRDK_Disasters`, заметки и
ассеты `v1.5.2`, `v1.5.2-rc.6` и `vk-v1.5.2-rc.5` не пересобираются и не
переписываются. `Latest` по-прежнему указывает на `v1.5.2`; `main`, GitHub
Pages и PR в `main` не затрагивались. Core API и `API_VERSION=42` не менялись.

`plugin_version` в `gradle.properties` остаётся `1.5.2-rc.6`: версию
`1.5.2-rc.7` получает только этот JAR через `-Pplugin_version` в workflow
`vk-prerelease.yml`. Тег намеренно начинается с `vk-v`, поэтому общий
`release.yml` не срабатывает и не прикладывает `chrdk-plugins-*.zip` и
`chrdk-disasters-*.jar`.

**Анонс в беседу ВКонтакте не отправляется:** по выбору владельца пререлиз
публикуется только на GitHub. Workflow всё равно готовит офлайн-превью
заметки, но шаг живой отправки `messages.send` пропускается; секреты
`VK_NEWS_*` не используются.

## Что вошло относительно `vk-v1.5.2-rc.5`

JAR собран из `de69f6dc` и включает весь накопленный код CHRDK_VK после
первого VK-пререлиза, а не только последнюю команду.

### Ровно пять постов в сутки на стене сообщества

* 09:00 «САМЫЙ БОГАТЫЙ», 12:00 «САМЫЙ ПРОКАЧАННЫЙ», 15:00 «ШАХТЁР ДНЯ»,
  18:00 «ОХОТНИК ДНЯ» и 21:00 обезличенный дайджест «ИТОГИ ДНЯ».
* Четыре персональные карточки рисуются Java2D в 1280×720; ник лидера и
  величина идут и на картинку, и в текст записи. Адаптивная вёрстка не даёт
  длинным никам залезть на бейдж и подвал.
* Вечерний дайджест по умолчанию обезличен: на публичную стену уходят только
  агрегаты — «добыто блоков», «получено алмазов», «побед над монстрами»,
  прирост престижа, поддержка сервера, пик онлайна и новички. UUID, IP,
  координаты, суммы платежей и названия товаров не публикуются; при
  `show-player-names: true` уважается существующий opt-out игрока из `/vk`.
* Состояние суток — в `wall-digest.json` и `daily-cards.json`, запись атомарная.
  Свои `guid` (`chrdk-wall-<дата>` и `chrdk-card-<номинация>-<дата>`),
  скрытые маркеры, окно повторов пять минут и не более трёх попыток на пост.
  Прерванная между `wall.post` и записью ledger публикация при рестарте
  пропускается, а не дублируется.
* Адрес загрузки фото проверяется allowlist доменов VK и только по HTTPS;
  шрифты и фон постера лежат внутри JAR.

### `/vkadmin testpost` — текстовая проверка

`/vkadmin testpost [chat|wall|both] [текст]` с правом `chrdkvk.admin` шлёт
один технический текст в беседу и/или на стену, не дожидаясь расписания.
Текст до 1000 символов, `guid=chrdk-test-<UUID>`, маркер
`#chrdk_test_<8 hex>`. Пост идёт **только текстом** — без PNG и без
`photos.*`; не пишет суточные ledger’ы и не анонсируется в игровом чате
(`VkService.eligibleWallPost`).

### `/vkadmin testcard` — новая проверка фото-цепочки

`/vkadmin testcard [текст]` — отдельная админская команда, добавленная в
`de69f6dc`. Она не расширяет `testpost`, не ждёт 09:00/12:00/15:00/18:00/21:00
и не публикует ничего сама по себе: живой вызов делает администратор на
сервере.

* Рендерит техническую PNG-карточку 1280×720 через штатный
  `DailyPlayerCard.render`: тестовый ник `CHRDK_TEST`, игровые величины
  скрыты, подвал `ТЕСТ CHRDK_VK · НЕ ИГРОВАЯ НОВОСТЬ`.
* Публикует через `VkWallPublisher.publish(byte[], text, guid)`, то есть
  полную штатную цепочку `photos.getWallUploadServer` → multipart-загрузка →
  `photos.saveWallPhoto` → `wall.post` с `attachments`.
* Маркер `#chrdk_test_card_<8 hex>` отсекается в
  `VkService.eligibleWallPost`: тест не уходит в игровой чат и не двигает
  `last_announced_post_id`. `guid=chrdk-testcard-<UUID>` не пересекается со
  штатными постами дня.
* Не трогает `wall-digest.json`, `daily-cards.json`, суточные счётчики
  попыток и аудит. Произвольный текст админа ограничен 1000 символами.
* Рендер и сеть уходят в фоновый поток, ответы админу (`post_id` + ссылка
  либо текст ошибки) возвращаются в главном потоке — по образцу
  `VkService.publishTestWallPost`.
* Добавлены сообщения `admin.testcard-*`, `testcard` в usage и tab-complete,
  офлайн-тест `VkTestCardTest` на реальный PNG, маркер, guid и контракт
  цепочки.

## Что сделать на сервере

1. Заменить **только** `chrdk-vk-1.5.2-rc.7.jar` вместо текущего
   `chrdk-vk-1.5.2.jar` / `chrdk-vk-1.5.2-rc.6.jar` и сделать полный рестарт.
   Остальные JAR комплекта обновлять не требуется.
2. Ключ сообщества — с правами `wall` **и** `photos`, бот — администратором
   сообщества. Проверить `community.group-id` и `community.access-token`.
3. Сначала проверить текстом: `/vkadmin testpost wall`. Затем выполнить
   `/vkadmin testcard` (или `/vkadmin testcard Мой текст`) — это и есть
   проверка `photos.*` на живом ключе.
4. Новые ключи необязательны: при отсутствии секций работают дефолты, чужой
   `config.yml` не перезаписывается. Отключение —
   `wall-digest.enabled: false` и `wall-daily-cards.enabled: false`. Тонкая
   настройка: часы четырёх карточек, `timezone`, `retry-minutes`,
   `show-values`, `show-player-names`, `min-events`, `max-names`, `title`,
   `footer`, `wall.announce-new-posts`.

### Если снова `VK API error 27`

Успешный текстовый `wall.post` уже подтвердил, что ключ живой и право `wall`
есть. `/vkadmin testcard` проверяет именно загрузку фото. Если VK вернёт
`error 27` на `photos.getWallUploadServer`, это ограничение авторизации
ключа сообщества, а не отсутствие галочки в «Типах событий» Long Poll и не
версия API. Текстовый контур остаётся рабочим; при необходимости отключите
постеры на время диагностики ключа. Секреты из настроек Callback/Long Poll
в конфиг плагина не переносятся.

  `wall.get` и `photos.saveWallPhoto`; превью анонса офлайн, без сети.

  production или игрового smoke. Реальную команду выполняет владелец.
* Нет bump `config-schema.yml`, нет правок исторических release notes, нет
  изменения `main`/Pages/PR, тегов и ассетов прежних релизов, нет смены
  `Latest`.
