# 1.4.220 — мастерская, preview и последние два эффекта

Закрыты **N24–N27, N30, N32**. Реестр: **25/25 улучшений + 35/35 нововведений = 60/60**.
Каталог: **76 чар = 61 светлая + 15 проклятий**, редких теперь 31.
Это счётчик реализованных критериев с автоматическими регрессиями, не заявление
о проведённом live-тесте. Purpur 26.3 / Java 25; все 30 плагинов обновляются вместе.

## Мастерская N24–N26

Только авторизованный живой Survival-игрок с `chrdkenchants.use`, не NPC.
Закройте контейнер: операции работают только из обычного инвентаря игрока.
В основной руке ровно один исходный предмет; обычные материалы — в storage-инвентаре,
не на месте исходного предмета и не во второй руке. Переименованные, зачарованные
и любые материалы с метаданными не расходуются.

| Команда | Условия / цена |
|---|---|
| `/enchants cleanse <id>` | Удалить ровно одно указанное кастомное проклятие: **8 осколков аметиста + 1 алмаз**. Остальные чары/данные не копируются и не удаляются |
| `/enchants combine` | По одной полностью одинаковой кастомной книге в каждой руке; ровно один одинаковый id/уровень, без stored/direct vanilla-чар. Обе книги → одна уровнем выше, строго до её собственного максимума. **8 лазурита + 1 алмаз** |
| `/enchants split <id>` | Смешанная книга (несколько кастомных или кастомная + vanilla): **1 обычная книга + 8 лазурита**. Выбранная чара уходит в отдельную книгу; всё остальное, vanilla и чужая PDC остаются только в исходной. Нужно место под результат |
| `/enchants confirm <код>` | Одноразовое подтверждение из ответа, **30 секунд**. Сам предварительный ответ ничего не выдаёт и не списывает |

Изменение полного storage-снимка, второй руки, выбранного слота, мира/generation,
выход, смерть, разрешённый TP, закрытие окна или reload делает подтверждение
непригодным. Максимум 256 планов, без вытеснения чужого действующего плана.
Цена и оба результата подготовлены на копиях; финальный commit — на основном
потоке, без внешних команд/событий между расходом и заменой инвентаря.
Повторное подтверждение не выполняется. Ошибка подготовки не меняет инвентарь;
при исключении Bukkit-setter выполняется восстановление исходного снимка.
Невозможно обещать транзакцию при аварийном завершении JVM/сбое самих setters.
Новые выходные книги получают источник «мастерская чар»; шансы добычи не растут.

Переключатели `workshop.enabled`, `workshop.cleanse.enabled`,
`workshop.combine.enabled`, `workshop.split.enabled` по умолчанию включены.
Очистка проклятия допустима и после выключения его новой выдачи.

## N27 — отчёт по настоящей наковальне

Откройте наковальню, предмет слева, кастомная книга справа:
`/enchants preview`. Отчёт читает тот же production-quote, который проверяется
при получении: identity окна, оба полных входа, переименование, результат,
цена, расход одной книги, native-предел, generation и режим Creative/Survival.
Показывает базовую часть + кастомную доплату, итог в уровнях, возможность оплаты
и перенос каждой кастомной чары до/после. При насыщении int-цены базовая часть
не выдумывается. Survival требует цену **строго ниже** native-предела и достаточный
уровень. Creative остаётся native-исключением, отдельный bypass-cost отклоняется.
Отчёт ничего не выдаёт, не тратит XP, не меняет PDC/слоты и не обещает будущий клик:
при получении все условия проверяются заново. Невалидный/устаревший quote не используется.

## N30 — PvE-якорь

`pve_anchor`, редкая чара ботинок **I/II**: уменьшает горизонтальную составляющую
конкретного native-knockback на **15/30%**, вертикаль не меняет. Только обычный
враждебный моб и его разрешённый положительный ближний урон, Survival/auth/use.
Не игроки, питомцы, NPC, именные мобы, боссы/Варден/древний страж; не снаряды,
взрывы и не произвольные velocity/атрибуты. Совместим с native-сопротивлением:
меняется уже рассчитанная остаточная отдача, не даётся иммунитет.
**Общий PvE-cooldown 15 секунд**, без суммирования уровней брони. Приоритет
`/enchants guard pve_anchor` или прежний auto; якорь участвует в прежнем GUARD-выборе.
Поздняя отмена отдачи не возвращает cooldown. Мастер-выключатель `pve-effects.enabled`
и индивидуальный `enchants.pve_anchor.enabled` сохраняют значение.

## N32 — пересадка за семя, единая со Skills

`harvest_replant`, редкая чара мотыги **I**. После разрешённого ручного сбора зрелых
пшеницы/моркови/картофеля/свёклы/адского нароста/какао — один росток возраста 0
с исходной ориентацией. Расход **одного настоящего обычного семени/корнеплода**
из storage-инвентаря; без семени ничего не сажается. Предметы на земле автоматически
не подбираются. Нет роста, добавочного XP/дропа или второго запуска сбора.

На следующем тике проверяются финальная отмена BlockBreakEvent, разрешённый дроп,
онлайн/жизнь/Survival/auth/use, мир/загруженный чанк, расстояние ≤6 блоков,
пустое место, подходящая native-опора и актуальность источника. Чара также требует
тот же инструмент (естественный износ допустим), generation и действующий эффект.
Мастер-выключатель `utility-effects.enabled` и `enchants.harvest_replant.enabled` работают.
Skills AUTO_REPLANT использует **тот же** Core-координатор вместо прежней бесплатной
пересадки: один реальный harvest-event → одна заявка/таймер/посадка/семя, даже при
двух источниках. Разные события на той же позиции не создают второй одновременный
таймер. До 4096 окон; переполнение отказывает, identity-remove не удаляет новый запрос.
Выход/смерть/TP/reload/disable очищают соответствующие окна/поставщика.

Семя списывается **до** размещения и callbacks. После реального временного размещения
вызывается native `BlockPlaceEvent`: приваты/аренда/другие защиты могут запретить
посадку. Проверяется финальный cancel/canBuild, текущая заявка, блок и опора.
При обычном отказе собственный росток откатывается в воздух и возвращается ровно
одно семя; если инвентарь заполнен — возврат падает в исходной точке.
**Если чужой callback уже заменил/сломал росток, автоматического дополнительного
возврата нет**, чтобы не размножить семена. Произвольные побочные действия чужих
плагинов невозможно атомарно откатить; это консервативная граница, не универсальная
изоляция всех плагинов. Не отменяется сам разрешённый сбор урожая.

## Проверки и установка отдельно

Регрессии: преобразования всего каталога и потолков, сохранение каждой чары при
split, точный немутирующий расход, одноразовые/истёкшие/заменённые подтверждения,
лимиты 256/4096, event/value identity и устаревший callback, семена шести культур,
native-anvil quote и readonly wiring, native PvE-only handler и общий cooldown.
Полная сборка всех модулей — GitHub Actions Java 25; wiki/messages/release-archive
и прежние контракты тоже проверяются. Это не Bukkit/live smoke-test.

Формат текущего релиза: **только `chrdk-plugins-1.4.220.zip` с 30 JAR и
`ОБНОВЛЕНИЕ.txt` внутри**. Без новых материалов/ZIP/картинок TradeMC и отдельных JAR.
Существующие текстовые version-метки магазина синхронизированы лишь для старого
контракта CI; товары/цены/изображения не менялись. Автоматическая публикация TradeMC
удалена из обоих workflows. Приваты/суточная аренда, пароль и добровольная opt-in
2FA не менялись, новые экономические/XP-множители не добавлены.

На сервер ничего не устанавливалось. Перед установкой: остановить сервер,
сделать полную резервную копию JAR/данных/миров, заменить весь комплект из ZIP,
сверить config/messages без удаления пользовательских данных и запустить сервер.
Не использовать Bukkit `/reload`. Перезапуск без удаления данных обязателен.
При приёмке отдельно проверить cleanse/combine/split (включая full inventory и
истёкший код), реальную цену anvil/rename/повтор preview, моба против игрока,
оба источника пересадки вместе, запрет строительства гостю/арендатору,
позднюю отмену break/place и отсутствие семени. Live-проверки пока не выполнялись.
Откат: остановка, возврат JAR **и данных** из единой резервной копии.
