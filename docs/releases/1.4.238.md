# 1.4.238 — магазин: количество предметов вместо обязательных партий

Core API 25, Purpur 26.3 / Java 25. Финансовая схема не меняется.

## Управление

- ЛКМ по товару открывает выбор количества покупки, ПКМ — продажи. Shift больше
  не исполняет мгновенную покупку/продажу 16 партий: сначала меню и подтверждение.
- Кнопки `1 / 8 / 16 / 32 / 64`, изменение `±1 / ±8 / ±64`, минимум для продажи.
  Одна сделка: 1–2304 шт. с прежними ограничениями вместимости и оборота.
- Показаны точное количество, итог в целых алмазах, эталонная партия/цена,
  минимум для продажи, /bal и физические средства. Отдельная кнопка подтверждения.
- `/shop buy <товар> <штук>` и `/shop sell <товар> [штук|all]` — **теперь штуки,
  не число партий**. Команды исполняют сделку сразу; меню предлагает preview.
  Скрипты/привязанные команды, передававшие число партий, нужно обновить.
- `all` и `sellall` выбирают максимум выручки в пределах текущего лимита/счёта,
  но минимум предметов для этой суммы. Неоплачиваемый остаток остаётся игроку.

## Выбранная экономическая модель

Без дробного кошелька и без повышения дохода от дробления сделки. Целая цена
старой эталонной партии сохраняется: покупка `ceil(ask × штуки / партия)`,
продажа `floor(bid × штуки / партия)`. Для целых кратных прежняя сумма точна.
Расчёт через целые long с проверенными пределами, не double-баланс.

Если 64 шт. продаются за 3 алмаза: 21 шт. не продаётся за ноль; 22 шт. дают 1;
43 — 2; 64 — 3. Автопродажа 63 шт. заберёт только 43 и оставит 20 с той же
выручкой 2. Явная ручная продажа исполняет ровно выбранное количество по
показанной цене: учитывайте округление, для подбора используйте кнопку максимума.
Покупка одной дешёвой вещи может стоить целый алмаз — сумма показана до подтверждения.

Динамическая цена/спред, запас, восстановление, существующие цены полных партий,
суточные лимиты и общий личный `/bal` сохранены. Сначала счёт, затем только
обычные поддерживаемые физические средства; сдача в банк. Именные предметы,
броня и offhand не используются; money/item overflow не выбрасывается на землю.

## Сохранность и совместимость

- Нулевая выручка отклоняется до нового inventory-плана/намерения магазина.
- Старый catalog/price/service не исполняется: проверка при открытии меню,
  на каждом действии и повторно перед исполнением, плюс защита самого service.
- Подтверждение одноразово для экрана; проверяются владелец и именно открытый
  inventory. Закрытие/смена меню до следующего тика отменяет ещё не начатый запрос.
- Иконки нельзя забрать shift/hotbar/offhand/drag-операциями экрана количества.
  Reload/disable закрывает и витрину, и меню количества. Нативные диалоги не нужны.
- Прежний canonical ShopJournal/ShopExchange/native witness хранит точные units
  и сумму, не повторно вычисляемую цену. Legacy pending до обновления исполняются
  по старым frozen данным; миграции баланса повторно не запускаются.
- Отказ места, средств, cap, режима/прав, лимита или записи не превращается в
  успешную сделку. Неизвестный принятый исход сохраняет прежнюю блокировку/recovery.

Тесты: поштучные/полные котировки, границы/overflow/нулевая продажа, минимальная
оплачиваемая продажа, оптимальность all под budget, отсутствие rounding-arbitrage
при неизменной котировке, frozen journal partial quantities, restart/native failure,
реальный BankStore, cap и повтор после траты. Вики и русские сообщения обновлены.
Live-тестов на рабочем сервере и автоматической установки не было.

## Повторный аудит перед выпуском

- Исправлена автопродажа: `all`/`sellall` сохраняют объём, размер партии и bid
  одним frozen plan. Изменённая котировка отклоняется до нового inventory-плана,
  а не применяется к ранее подобранному количеству незаметно для игрока.
- Убрана неверная подсказка минимума продажи из окна покупки: прежний расчёт
  использовал ask вместо bid. Кнопка минимума доступна только при продаже;
  покупка имеет собственные подсказки. В обоих окнах показано наличие товара.
- Закрытие окна теперь окончательно отменяет его ещё не начатое подтверждение,
  даже если тот же объект inventory повторно открыт сторонним обработчиком.
  У сессии один владелец и только одно подтверждение. Уже принятое source/Core
  намерение закрытием интерфейса не откатывается — его завершает прежний recovery.
- Добавлены регрессии frozen auto-sale и lifecycle экрана, независимая проверка
  предельных расчётов через BigInteger. Всего 33 новых теста относительно 237,
  включая реальные source/BankStore сценарии перезапуска, отказов и native save.
