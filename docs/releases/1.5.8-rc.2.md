# 1.5.8-rc.2 — полное восстановление финансовых привязок

## Общий хотфикс

Расширен аудит RC1: одинаковый разрыв «локальный registered ACK есть, lineage в Core
отсутствует» устранён в Diamond Shop, Claims, Daily Rewards, PaidActions
(Teleports/Guilds), Common Goals, Milestones и Orders.

Если Core уже знает тот же UUID, модуль обязательно дозаписывает отсутствующий локальный
ACK. Если lineage потерян в Core, повторная регистрация того же UUID разрешена только до
первой финансовой операции и при отсутствии pending/обязательств. Точные условия по
модулям: `docs/audits/income-source-recovery.md`.

Другой UUID, sequence выше нуля, прошлые выплаты, refunds, incomes или pending остаются
fail-closed. Ничего не начисляется, не списывается и не удаляется. Battle Pass не
восстанавливает ACK=true автоматически: его witness не доказывает отсутствие выплат.

`/shopadmin recovery` теперь пытается безопасно восстановить пустую привязку и выводит
фактический `binding` после попытки. Существующий WAL принудительно не завершается.

## Обновление и проверка

Общий ZIP содержит 19 JAR версии 1.5.8-rc.2 и памятку; VK, Disasters, Mine Treasure и
SHA256SUMS отдельно. Остановить сервер, сделать согласованный backup Core и всех модулей,
заменить весь комплект и полностью перезапустить. Не смешивать версии JAR.

Проверить `/shop`, `/shopadmin recovery` (`привязка Core true`), покупку/продажу, Claims,
Daily, Teleports/Guilds, Common Goals, Milestones и Orders. При наличии финансовой истории
и потерянном lineage нужен согласованный backup, а не удаление JSON.
