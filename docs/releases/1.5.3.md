# CHRDK 1.5.3 — проверяемые резервные копии

Накопительный выпуск поверх `1.5.2-fix`; Core API 42 и игровые механики не меняются.
MySQL не добавляется: для одного сервера усилены файловое хранение, снимки и
проверяемое офлайн-восстановление.

## Надёжность

- `SafeJsonWriter` и `data.json`: `fsync` содержимого до атомарной замены и `fsync`
  каталога там, где его поддерживает ФС. Один писатель на путь и прежние повторы
  записи сохранены.
- `/pass backup create`: асинхронный ZIP состояния всех `CHRDK_*`, манифест размеров
  и SHA-256, строгий JSON, ограничение размеров, защита от symlink/Zip Slip.
- Готовый архив сразу читается повторно. Ошибка чтения, JSON, записи или проверки
  не оставляет опубликованного частичного снимка.
- `/pass backup list` и `verify <ZIP>`; прежний gzip только аккаунтов доступен как
  `legacy`, его восстановление сохранено.
- Автоснимок после запуска и раз в час: 6 последних + 14 дневных + 8 недельных.
  Новые ключи `storage.snapshots.*` добавляются мигратором конфига.
- `tools/backup/restore_chrdk_backup.py`: независимая проверка и восстановление на
  остановленном сервере с pre-restore копией заменяемых файлов. Python 3.11+,
  сторонние зависимости не нужны.

## Границы

Core сбрасывает свои основные хранилища перед снимком, но между аддонами нет общей
паузы записи: согласованность гарантируется на уровне каждого файла, а не единой
транзакции всего сервера. Конфиги, токены, ключи, логи, аудит, кэши и прежние
бэкапы в ZIP не входят. `data.json` с паролями/TOTP входит и требует приватного
хранения (`0600` на POSIX). Полный ZIP нельзя восстанавливать из игры.

[Регламент, внешняя копия и контрольный restore](../BACKUP.md).

## Обновление и откат

1. До установки: полный внешний backup текущих `plugins/CHRDK_*` и миров.
2. Обновить весь общий комплект одной версии; VK/Disasters остаются отдельными.
3. Полный перезапуск, не `/reload`. Дождаться первого проверенного снимка.
4. `/pass backup verify <имя>` и контрольный restore в staging.
5. Настроить внешнее копирование: локальная ротация не спасает при отказе диска.

Откат: остановить сервер, вернуть весь прежний JAR-комплект и соответствующий
снимок состояния через скрипт. Не смешивать WAL и данные разных моментов.
