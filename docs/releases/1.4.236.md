# 1.4.236 — Claims: деньги и состояние территории под одним подтверждением

**Этап общего аудита; не отдельный релиз и не установка. Core API 24.**

Покупка земли, обратный выкуп, продажа объединённой территории, серверная рента,
погашение долга, первая аренда и автопродление переходят с inventory-callback
на canonical source WAL и отдельную квитанцию Core. Цены, налоги, интервалы,
правила соседства, роли, лимиты и оплаченный срок арендатора не меняются.

## Порядок проведения

1. Все проверки и расчёты выполняются на независимой копии ClaimStore. Живые
   Claim-объекты и права не меняются до подтверждения. Сохраняются все участвующие
   счета, принятые даты, долг, владельцы, роли, объединение, снятие привата,
   аренда и счётчики. JSON содержит точные целые числа, включая long > 2^53.
2. При ручной оплате обычные алмазы, обе руды и блоки покрывают только недостачу
   после `/bal`. Core отдельно журналирует CLAIM_FUND: storage BEFORE/AFTER,
   nonce и успешный saveData/checkpoint, затем зачисляет физическую сумму в `/bal`.
   Сдача с целого блока остаётся в банке; offhand, броня и предметы с meta не
   затрагиваются. Если дальнейшая покупка отклонена, пополнение остаётся личным
   балансом игрока: предметы не пропадают и не возвращаются второй раз.
3. До банковского domain settlement Claims сохраняет полный frozen AFTER,
   before-hash, SHA-256 эффекта, UUID lineage/операции и sequence. Core одним
   replace bank.json меняет ВСЕ счета и gross-счётчики и сохраняет квитанцию.
   У автоматических списаний нет физической доплаты.
4. Только COMMITTED применяет полный сохранённый AFTER, повышает sequence и
   удаляет pending в том же replace claims-data.json. Старые Claim-ссылки
   сохраняются для оставшихся чанков. Перезапуск не пересчитывает старую цену
   или оплаченный срок и не повторяет снятие/выручку.

Исходный lineage сначала сохраняется локально, затем регистрируется в Core,
затем сохраняется registration ACK. После ACK исчезнувшая банковская привязка
не создаётся автоматически. Старые казны импортируются через принудительно
сохранённую квитанцию по имени/UUID; повторный перенос не пополняет счёт ещё раз.
Неизвестный UUID, cap и недоступность сохраняют исходное обязательство.

## Отказы и эксплуатация

- Неопределённость IO останавливает writer; старый async/shutdown snapshot не
  затирает новое намерение или подтверждение. Оба writer: file force, atomic
  replace, directory force под монитором; небезопасного fallback replace нет.
- Pending приостанавливает команды, GUI-мутации, администрирование, таймеры,
  миграцию и выдачу отложенных notices. Старые территории остаются защищены;
  новый чанк из pending также предварительно защищён, без выдачи доступа.
- Core UNAVAILABLE не является нехваткой денег: дата/долг не меняются и аренда
  не прекращается. Истинная нехватка заканчивает аренду, не отнимая уже оплаченные
  сутки. Простой не выставляется арендатору задним числом.
- Безденежное освобождение за долг тоже имеет domain receipt. Снятие территории
  не остаётся отдельным несохранённым действием после списания.
- `/claimadmin recovery` — только диагностика lineage/ACK/sequence/pending.
  Принудительного «считать оплачено» нет. Live restore финансового источника
  запрещён; восстанавливайте согласованные копии Claims, банка и playerdata
  при остановленном сервере. Не удаляйте WAL и банковские квитанции.

Это восстановимый протокол независимых файлов, **не distributed ACID** и не
защита от произвольного независимого отката одной части резервной копии.
Тесты используют реальные ClaimStore/BankStore и имитацию native-порта;
реальный Minecraft crash-тест на staging отдельно не проводился.

DailyRewards DIAMOND/VIP и обычные алмазные выходы Treasures loot остаются
блокирующими этапами общего релиза. ZIP и установка пока не выполняются.
