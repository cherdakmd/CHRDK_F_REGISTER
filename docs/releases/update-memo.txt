===========================

Комплект 1.5.2-rc.12 — ПРЕРЕЛИЗ, не стабильное обновление
---------------------------------------------------------
22 JAR одной версии + памятка; chrdk-vk-1.5.2-rc.12.jar и
chrdk-disasters-1.5.2-rc.12.jar отдельно. Общий архив —
chrdk-plugins-1.5.2-rc.12.zip; четвёртый ассет датапака — тот же
mine-treasure-1.6.5-ru.zip (1 758 991 байт, SHA-256
d51346e81b32fda61e7d4ba7a9475289815857451f4bea8a69d45f61527f3ec6). Installer,
docs и отдельный JAR датапака как release-ассеты не прикладываются.
ПРЕДВАРИТЕЛЬНАЯ СБОРКА: только изолированный staging после полного backup;
production, TradeMC, Pages и стабильная новость ВК не меняются. Latest остаётся
v1.5.2; тег, Release, четыре ассета и VK-анонс v1.5.2-rc.11, стабильный 1.5.2,
общие rc.1 ... rc.6 и отдельные vk-v1.5.2-rc.5/7/8/9/10/11 не переписываются. Полный
общий пререлиз v1.5.2-rc.12 публикуется по явной команде владельца: annotated
тег и GitHub prerelease создаются, Release-workflow приложит общий ZIP,
отдельные VK/Disasters JAR и patched Mine Treasure ZIP; штатный анонс в беседе
ВК разрешён, wall.post и стабильная новость не используются.

CHRDK_Queue и снятые JAR убрать вручную из plugins/, plugins/update/, staging.

Что нового в rc.12: MySQL storage каркас (первая итерация централизованного
хранилища). Storage API v1 с DocumentStore/DocumentSnapshot/StorageMode,
NIO FileSystemProvider с inventory-based routing (DB-bound файлы в chrdk_storage_file,
остальные на filesystem), DDL 55 таблиц с checksum verification, inventory 55 файлов
с strategy/secret_class/checksum_policy. Offline migrator (tools/db/migrate.py)
с 7 normalized parsers (player/finance/social/social_players/moderation/exploration/auth_reset),
3 DB-aware adapters (MilestoneMigration.tierForge, StatsBackup, ShopCatalogMigration).
CI contracts (6 Python тестов) проверяют sync между generators и Java constants.

backend=FILE (legacy JSON/YAML, работает как раньше), backend=MYSQL (требует
MySQL 8.0+ и Connector/J 8.3.0 на classpath — админ кладёт в plugins/CHRDK_Core/libs/),
backend=FILE_READONLY (только офлайн-сверка мигратора, блокирует запуск сервера).
См. docs/design/MYSQL-CENTRALIZED-STORAGE.md и docs/releases/1.5.2-rc.12.md.
