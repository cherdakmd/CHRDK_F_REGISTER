# 1.4.277 — приглашение в сообщество и ВК-2FA

## Напоминания без запрета игры

После авторизации CHRDK_VK проверяет три пункта: привязка игрового аккаунта,
подписка на сообщество и участие в выбранной беседе. Невыполненные пункты
предлагаются повторно (по умолчанию раз в 180 секунд). Ни kick, ни запрета играть нет.
Нажатие ссылки не считается вступлением: членство подтверждается API ВК.
После подтверждения всех трёх сообщения прекращаются; проверка продолжает работать,
чтобы выход из сообщества/беседы мог снова показать предложение. Ошибка API означает
«не удалось проверить», а не «вы не вступили»; подтверждённым игрокам во время сбоя
повторное предложение не показывается до успешной сверки.

В config.yml CHRDK_VK:
- `onboarding.enabled`, `onboarding.interval-seconds` (60..3600);
- `onboarding.peer-id`: ботовый ID нужной беседы, 0 — беседа игрового моста;
- `onboarding.chat-invite-url`: настоящая HTTPS-ссылка приглашения (локально, не в Git).

Для текущей беседы известен peer_id 2000000001, но конфигурация сервера этой работой
не меняется. Без ссылки предлагается уточнить её у администрации; без права читать
участников статус беседы неизвестен. Боту нужны соответствующие права в беседе.
Не выводятся списки участников и сырые ответы. Запросы выполняются вне игрового потока,
результат сверяется с текущей привязкой, конфигурацией и подключением игрока.

## Добровольная ВК-2FA

Core API 34, новый CHRDK_VK требует согласованный Core 1.4.277+.
1. Авторизоваться и привязать аккаунт через `/vk link` в ЛС сообщества.
2. `/vk 2fa on` → получить код в ЛС → `/vk 2fa confirm <код>` в игре.
3. При следующем входе: пароль → существующая TOTP, если подключена → код ВК
   командой `/2fa <код>`. Повторная доставка — `/2fa resend`.
4. Отключение: `/vk 2fa off` → новый код в ЛС → `/vk 2fa confirm <код>`.
   Статус и подсказка: `/vk 2fa status`.

TOTP автоматически не отключается и не заменяется. IP-сессия не пропускает пароль
или VK-код у защищённого аккаунта. Код — 6 цифр, срок — 120 секунд, до 5 попыток; между
запросами не менее 30 секунд, в том числе после переподключения. Коды привязаны к
аккаунту, текущему подключению, назначению и закреплённому личному VK ID; код из
одного сценария нельзя использовать в другом. Старый код при перевыпуске отменяется.
Поздний ACK доставки не активирует другое подключение. Отвязка ВК при включённом
факторе запрещена (в том числе через ЛС/админ-команду аддона).

Core хранит обязательство в `plugins/CHRDK_Core/vk-second-factor.json` (фактический
каталог Core определяет хостинг), а не в аддоне. Коды и их хеши туда не пишутся.
Настройка подтверждается после атомарной записи вне игрового потока. Отключение,
отсутствие или сбой аддона не снимает уже включённую защиту: вход остаётся закрытым.
Коды нельзя отправлять в общую беседу; аргументы /vk маскируются в штатном логе Core,
но сторонние плагины/прокси могут иметь собственные журналы — проверьте их настройки.

## Восстановление и установка

Перед установкой — резервная копия каталога Core, CHRDK_VK и привязок. При утрате ВК
нужна ручная проверка владельца администратором. После подтверждения личности и
остановки сервера сохранить резервную копию `vk-second-factor.json`, снять только
запись подтверждённого аккаунта из `accounts`, сохранить валидный JSON и запустить
сервер. Не удалять файл и не сбрасывать все аккаунты. При повреждении/нечитаемости
файла Core закрывает завершение входа до восстановления валидного файла из backup.
Внешний провайдер и бот не умеют сбрасывать пароль, TOTP или обязательство ВК-2FA.

Не откатывайте Core на версию без ВК-2FA при подключённой защите: старый Core
не знает об этом обязательстве. Обновлять Core и CHRDK_VK нужно согласованно.

Основной ZIP: 22 JAR + ОБНОВЛЕНИЕ.txt, CHRDK_VK отдельно. Не смешивать версии.
Сервер Minecraft, TradeMC, действующие токены и Variables не изменяются.
Установка — отдельное действие: публикация релиза не обновляет сервер автоматически.
