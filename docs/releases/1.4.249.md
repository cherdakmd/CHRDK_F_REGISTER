# 1.4.249 — кланы и добровольный доступ к личной территории

25 плагинов, Core API 28, Purpur 26.3 / Java 25.

## Игрокам

- `/clan` и `/clans` — новые алиасы прежнего `/guild`; данные клана не переименованы.
- `/claim clan` — настройка территории под вами. Собственник явно выбирает
  `access` (двери/механизмы), `containers` (также контейнеры), `build` (полная стройка).
  Это настройка всей связной территории и всех нынешних/будущих членов данного
  клана. `off` отключает только клановую часть, не стирая личные приглашения.
- Земля, лимит и содержание остаются личными. Нет кланового собственника,
  автоматического снятия содержания из казны клана или донатных мест всему клану.
- Клановый ID не меняется при переименовании. Исключение/выход прекращают
  производный доступ. Новый клан владельца и новый клан с прежним именем не
  наследуют привязку. Возвращение владельца в прежний нераспущенный клан вновь
  активирует её; для окончательного отзыва нужен `off`. Продажа/передача сбрасывают её.
- Личная роль главнее клановой, в том числе ограниченная ACCESS. Если личное
  приглашение удалено, остающийся член разрешённого клана всё ещё имеет клановый доступ.
- Оплаченная аренда отдельного чанка не обходится: остаётся доступ владельца и
  арендатора; сроки, цена, продление и казна арендатора не меняются.
- `/claim menu`: новая вкладка «Доступные» с личными приглашениями, клановым
  доступом и арендой; кнопка клана. Телепорт остаётся платным и перепроверяет права.
- Меню клана связано с приватами и личным `/rank my`, показывает весь состав до
  26 игроков. Донат не назначает должности и не открывает чужие владения/казну.
- Закрытый чат и уведомления не уходят до авторизации; приглашения напоминаются
  после входа. Исправлены проверка очищенного тега и модель единственного лидера.

## Администратору

Все новые привязки по умолчанию выключены. Пользовательские цены, ранги,
приглашения, деньги, auth/2FA и PvP не перенастраиваются. Messages.load добавляет
недостающие тексты из ресурсов, без сброса собственных переводов. Соседние свои
чанки наследуют общую настройку; при конфликтующем слиянии клановый доступ
снимается: собственник должен проверить и включить его заново.

Новые опциональные поля включены в существующий строгий домен Claims и его WAL;
старые пустые привязки не изменяют canonical hash. Настройка не списывает деньги.
Отсутствие/ошибка кланового сервиса блокирует только производный доступ, а не
превращает землю в общедоступную. Подробнее: [архитектура](../design/CLANS_INTEGRATION.md).

Устанавливать только отдельно согласованно: штатно остановить сервер,
сделать согласованный backup миров, JAR, данных, банка и платёжных журналов;
заменить **все 25 JAR одной версии**, без дубликатов и `/reload`. Если переход
ещё с 1.4.247 или раньше, сначала выполнить ручное снятие старого аддона по
[инструкции 1.4.248](1.4.248.md), включая staged-копии в plugins/update/.
Не откатывать старые JAR поверх новых pending: восстановление только согласованной копии.

Проверить двумя авторизованными участниками и посторонним: opt-in, три роли,
личное приглашение, исключение во время TP, смену клана владельца, аренду,
продажу, рестарт и `/gchat` до авторизации. Открытое старое меню не сохраняет права.
Полный CI — в PR; серверная проверка этой публикацией не подтверждается.
Minecraft-сервер не изменён, tag/release и TradeMC-материалы не создаются.
