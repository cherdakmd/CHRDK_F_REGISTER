# CHRDK_Artifacts: аудит релиза 1.4.73, исправления и доработки 1.4.101+

Документ фиксирует разбор модуля **CHRDK_Artifacts** из релиза **v1.4.73**
(`chrdk-artifacts-1.4.73.jar`, Purpur 26.3 / Minecraft 26.3, Java 25), найденные
дефекты, внесённые исправления и план следующих волн. Исходной точкой служит тег
`v1.4.73`; ссылки на строки даны по этому тегу.

## 1. Резюме

Модуль закрывает «магический лут» сервера: 65 артефактов (33 светлых и 32
проклятых, из них 30 активных и 35 пассивных), которые работают просто из
инвентаря. Пассивные вешают зельевые эффекты пульсом, отвечают на события
(«Перо Феникса», «Тернистый Плащ») или стреляют случайными проклятиями; активные
срабатывают по ПКМ за уровни опыта и кулдаун. Метки предметов живут в PDC,
отдельного хранилища у плагина нет.

Архитектура аккуратная: чистые таблицы (`ArtifactRegistry`, `ArtifactEffects`,
`ArtifactLooter`), покрытие эффектов проверяется тестом, тексты — в
`messages.yml`. Основные проблемы — в «стыке» с ванильной игрой:

## 2. Методика

1. **Статический разбор** всех 16 классов модуля, трёх ресурсов (`plugin.yml`,
   `config.yml`, `messages.yml`) и пяти тестов; сверка с README и фактическим API
   ядра (`ChrdkRegisterApi`, `Messages`).
2. **Контракт текстов** `.github/scripts/check_messages.py`: ключи `messages.yml`
   ↔ литералы Java. До волны 1 — 237 ключей, 36 литералов, один динамический
   префикс (`art.<id>.name|lore`), пять «мёртвых» ключей — ложные срабатывания
   (динамические `line-*` и корневой `messages`).
3. **Ресёрч** ванильных механик, с которыми стыкуется модуль: категории рыбалки,
   переполнение амплификатора `jump_boost`, события Paper для защиты предмета и
   блокировки взаимодействия (см. §6).
4. **Прогон сценариев**: ПКМ по сундуку/верстаку/наковальне с артефактом в руке;
   приседание перед блоком; размещение `COAL_ORE`-артефакта; поедание
   `CHORUS_FRUIT`; полный инвентарь при `/artifactsadmin give`; дуэль двух
   «Тернистых Плащей»; выдача и перезапуск сервера (кулдауны).
5. **Сборка и тесты** в GitHub Actions на Purpur API 26.3 (Java 25).

## 3. Критичные дефекты

### A-01. Артефакт блокирует всю игру с блоками

`ActiveEffectsListener.onInteract` (v1.4.73, строки 45–64):

```java
if (action != Action.RIGHT_CLICK_AIR && action != Action.RIGHT_CLICK_BLOCK) {
    return;
}
ItemStack held = event.getItem();
...
event.setCancelled(true);                 // ← до всех проверок
if (event.getHand() != ...) return;
if (!player.hasPermission(...)) return;   // а событие уже отменено
```

Любой правый клик с активным артефактом отменяется целиком: нельзя открыть
сундук, дверь, воронку, верстак, наковальню, кафедру, нажать кнопку. Причём
отмена происходит **до** проверок права, авторизации, включённости в конфиге и
кулдауна: артефакт «молчит», но блок всё равно не открывается. На практике
игрок с «Грозовым колоколом» в руке не может пользоваться половиной мира.

Исправление: клик по интерактивному блоку и клик в приседе отдаются игре, а
отмена и активация выполняются только после проверок (правила вынесены в
`ArtifactUseRules`).

### A-02. Артефакт можно потерять как обычный предмет

Каталог использует настоящие ванильные материалы: `COAL_ORE` («Ключ Пропасти»),
`OBSIDIAN` («Камень стойкости»), `SNOW_BLOCK`, `PACKED_ICE`, `COBWEB`, `BOOK`,
`CHORUS_FRUIT` («Эндер-сдвиг») и другие. Пока A-01 глушил все клики, предметы
нельзя было ни поставить, ни съесть — но вместе с игрой была отнята и защита:
достаточно одного будущего ослабления обработчика (или другого плагина,
вызывающего `BlockPlaceEvent`/`PlayerItemConsumeEvent`), и артефакт исчезает
навсегда, оставив после себя обычный блок.

Исправление: отдельные обработчики `BlockPlaceEvent` и `PlayerItemConsumeEvent`
отменяют расход предмета с меткой PDC и показывают `item-protected`.

### A-03. Выдача теряет предметы

`ArtifactCommandHandler.handleAdmin` (строка 107):

```java
target.getInventory().addItem(stack);   // результат проигнорирован
```

`Inventory#addItem` возвращает карту непоместившихся стопок. При полном
инвентаре админ видел «Выдан артефакт», а предмет исчезал. Исправление: излишек
падает под ноги игроку (`dropItemNaturally`), а отправитель получает
`admin-given-dropped` с количеством — тот же приём, что в `CHRDK_Claims`
(`DiamondItems.addOrDrop`) и `CHRDK_TierForge` (`giveItems`).

### A-04. «Тернистый Плащ»: ответный удар зацикливается

`ArtifactEventListener.onRetaliate` (строки 87–97) наносит урон нападавшему
внутри обработчика `EntityDamageByEntityEvent` на `MONITOR`. Если у нападавшего
тоже есть плащ, его ответ запускает новое событие, которое снова бьёт первого
носителя, — и так до смерти обоих (2 урона за отскок, ~10 отскоков на 20 HP).
Плюс ответный урон получал игрок в креативе.

Исправление: набор `retaliating` (UUID нападавшего) обрывает цепочку после
первого ответа; креатив и спектаторы пропускаются; мёртвые и снаряды — тоже.

## 4. Волна 1 (1.4.101): клики, защита предмета и выдача

Одна тема — «артефакт перестаёт мешать играть и не теряется».

- **`ArtifactUseRules`** — чистые правила клика: `isRightClick`,
  `passesToBlock(action, interactableBlock, sneaking)`, `shouldActivate(...)`.
  Интерактивный блок и приседание отдают клик игре; воздух и «пустые» блоки —
  артефакту. Правила покрыты шестью юнит-тестами без запуска сервера.
- **Порядок проверок в `ActiveEffectsListener`.** Сначала рука, предмет, ид и
  режим; затем «клик не наш» → выход без отмены; затем отмена события; затем
  право `chrdkartifacts.use`, включённость, авторизация, кулдаун и цена.
- **`BlockPlaceEvent` и `PlayerItemConsumeEvent`.** Артефакт нельзя поставить
  блоком или съесть; в чат уходит `item-protected`.
- **Выдача без потерь.** `/artifactsadmin give` выкладывает излишек под ноги и
  сообщает количество (`admin-given-dropped`).
- **Плащ отвечает один раз.** Рекурсия обрезана, креатив/спектаторы пропущены.
- **Актуальное описание.** `plugin.yml` больше не обещает «30 артефактов (15/15)».

Контракт `messages.yml` — 239 ключей и 38 литералов (+`item-protected`,
`admin-given-dropped`); `config.yml` не менялся. Новый класс `ArtifactUseRules`
и тест `ArtifactUseRulesTest` (6 проверок); всего 19 `@Test` в 5 классах.
Версия 1.4.101, полный перезапуск.

### 4.2. Волна 2 (1.4.102): добыча, тексты и мягкая зависимость

Одна тема — «модуль честно говорит и не зависит лишнего».

- **Рыбалка по ванильной категории.** `TreasureLoot` сокращён с 16 материалов
  до шести настоящих сокровищ (лук, зачарованная книга, удочка, бирка, раковина
  наутилуса, седло); `isTreasure(null)` больше не бросает исключение.
  Комментарий `sources.fishing-treasure-percent` в `config.yml` исправлен:
  состояния `CAUGHT_TREASURE` в Bukkit нет, есть категория лута.
- **Находка у поплавка.** `ArtifactLootListener.onFish` выкладывает артефакт в
  точке пойманного предмета, а не под ногами рыбака — на берегу и в лодке
  находка не уходит в воду.
- **Фолбэки текстов.** Новый чистый класс `ArtifactText`: пустое имя из
  `messages.yml` заменяется читаемым именем из ида, пустая строка лора не
  добавляется в предмет. Класс `ArtifactItems` получил `nameOf(def)`, и все
  сообщения (`activated`, `dropped`, `admin-given`, `admin-received`, каталог)
  используют его — безымянных артефактов и пустых мест в шаблонах больше нет.
- **Право везде.** `chrdkartifacts.use` теперь проверяется в
  `ArtifactEventListener.carries`, в пульсе `PassiveEffectsService` и в
  `/artifacts`: объявленное право действительно для всех путей.
- **Мягкая зависимость от чар.** `plugin.yml`: `depend: [CHRDK_Core]` +
  `softdepend: [CHRDK_Enchants]`; вся работа с чарами изолирована в
  `EnchantBridge` (единственный класс с типами `CHRDK_Enchants`, грузится только
  при активации хартии). Без аддона чар включаются остальные 64 артефакта,
  «Хартия чар» отвечает `enchant-failed`, а при старте пишется предупреждение в
  лог. `build.gradle`-комментарий приведён в соответствие.
- **Текст хартии — в messages.yml.** Строка «✦ Хартия вписала: …» заменена
  ключом `enchant-applied` с `%name%` и `%level%`; имя чары берётся из аддона,
  уровень переводится в римские цифры (`roman`).
- **`EnchantBridge` различает отказ.** `Result(Status.OK|NO_ROOM|UNAVAILABLE)`:
  «нет подходящей чары/места» и «архив недоступен» — разные сообщения.

Контракт `messages.yml` — 240 ключей и 39 литералов (+`enchant-applied`);
`config.yml` — без новых ключей (поправлен только комментарий). Новые классы
`ArtifactText` и `EnchantBridge`; тест `ArtifactTextTest` (5 проверок) и
`TreasureLootTest` расширен до 3; всего 26 `@Test` в 6 классах.
Версия 1.4.102, полный перезапуск.

### 4.3. Волна 3 (1.4.103): проклятия и эффекты без хаков

Одна тема — «никаких переполнений и зря сожжённых кулдаунов».

- **Прыжок на атрибуте (A-09).** «Глиняная душа» больше не вешает
  `jump_boost` с амплификатором 250 (это переполнение знакового байта: на
  1.20+ десинк клиента, на 1.21.5 трюк обходится высоким прыжком). Новый класс
  `JumpLimiter` ставит transient-модификатор на `Attribute.JUMP_STRENGTH` с
  суммой, вычитающей базовое значение: итог ровно 0, база не портится, в
  playerdata ничего не остаётся. Пульс снимает модификатор, когда артефакт
  убран; `stop()` снимает его у всех онлайн-игроков при выключении/релоаде.
  Зельевого `jump_boost` у артефакта больше нет, зато появился
  `SpecialKind.JUMP_WARD`.
- **Пассивные зелья не моргают (A-08).** `PotionRefresh.durationTicks` считает
  длительность как `max(refresh, 20) + 40` тиков: при
  `passive-refresh-ticks: 200` эффект живёт 240 тиков и не пропадает между
  пульсами. Мгновенные эффекты (сытость) по-прежнему срабатывают раз за пульс.
- **Чужое зелье не понижается (A-08).** `PotionRefresh.shouldApply` не даёт
  перебить более сильный или более долгий эффект: Speed II из бутылки, маяк или
  другой плагин остаются как есть.
- **Феникс уступает тотему (A-06).** Проверка в `EntityDamageEvent` идёт на
  `HIGHEST`; если в руке есть тотем бессмертия, «Перо» молчит — ванильное
  спасение сработает само, а кулдаун не сгорит.
- **Щиты в расчёте (A-06).** Новый чистый класс `CombatMath`:
  `healthDamage = max(0, finalDamage − absorption)`, `isLethal` учитывает щиты
  и не спасает уже мёртвого (здоровье ≤ 0). `reviveHealth` зажимает долю 0..1
  и вырожденный максимум трактует как 20.
- **Без исключений в `setHealth`.** Воскрешение идёт через `CombatMath`,
  поэтому нулевой/отрицательный максимум здоровья больше не валит обработчик.

Новых настроек и сообщений нет (240 ключей, 39 литералов). Новые классы
`CombatMath`, `PotionRefresh`, `JumpLimiter`; тесты `CombatMathTest` и
`PotionRefreshTest` (по 4 проверки), `ArtifactRegistryTest` расширен до 8
(проверка «у JUMP_WARD нет зельевого хака» и разумности всех амплификаторов);
всего 36 `@Test` в 8 классах. Версия 1.4.103, полный перезапуск.

## 6. Ресёрч

- **Рыбалка (Minecraft Wiki).** Ванильная категория «treasure» — ровно шесть
  предметов: зачарованный лук, зачарованная книга, зачарованная удочка, бирка,
  раковина наутилуса, седло (по 1/6 внутри категории, 5 % улова без «Морской
  удачи»). Мусор — кувшинка, чаша, палка, нить, чернильный мешок, крюк,
  гнилая плоть, кожаная обувь, кость, бутылочка воды, повреждённая удочка.
  Текущий `TreasureLoot` смешивает обе категории — исправление в 1.4.102.
- **Jump Boost (Minecraft Wiki, Arqade, ViaVersion #4350).** Амплификаторы
  128–250 не являются «отрицательным прыжком» по контракту API: это
  переполнение знакового байта в клиенте/NBT. На 1.20+ трюк десинкается, на
  1.21.5 его обходят (высокий прыжок), а официальный путь — атрибут
  `minecraft:generic.jump_strength` (с 1.20.5 — `Attribute.JUMP_STRENGTH`).
  «Глиняную душу» переводим на атрибут в 1.4.103.
- **Paper API.** `Material#isInteractable()` различает блоки с ванильным
  взаимодействием; `BlockPlaceEvent#getItemInHand()` и
  `PlayerItemConsumeEvent#getItem()` дают предмет с PDC; `Inventory#addItem`
  возвращает непоместившиеся стопки — основа защиты и честной выдачи.
