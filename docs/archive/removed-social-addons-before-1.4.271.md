# Архив снятых систем — до 1.4.271

Не инструкция действующего сервера. Модули удалены; история сохранена для аудита старых данных.

## Аддон CHRDK_Referrals — реферальная система (с версии 1.4.9)

Игроки зовут друзей и получают **бонусные дни проходки** — за реальные оплаты, без накруток.

### Как это работает

- Код приглашения — **просто ваш ник**: ничего генерировать не нужно.
- Новичок **до первой оплаты** пишет `/ref use <ник>` — привязка одноразовая и необратимая.
- Когда он **впервые оплачивает проходку** (донат сработал — событие `PassGrantedEvent` из ядра),
  оба получают бонус: пригласивший **+7 часов**, приглашённый **+3 часа** (настраивается
  `bonus-hours:` в `plugins/CHRDK_Referrals/config.yml`; старый `bonus-days:` читается как часы).
  Начисление идёт через API ядра (`grantPassHours`) — в аудите видна метка `referral:<ник>`.
- Анти-накрутка: пригласитель обязан быть зарегистрирован (`rules.require-inviter-registered`),
  нельзя привязаться к себе, привязка — только до первой проходки. «Бесплатные часы» живы только
  за реальную оплату друга.
- Новичку при входе показывается одноразовая подсказка про `/ref use` (отключается).

### Команды аддона

| Команда | Описание |
|---|---|
| `/ref` | Мой код (ник), сколько приглашено, заработано часов, чья я реферал |
| `/ref use <ник>` | Привязаться к пригласившему (один раз, до первой проходки) |
| `/ref top` | Топ-10 приглашателей по оплатившим друзьям |
| `/refadmin lookup <ник>` | Карточка игрока (`chrdkref.admin`) |
| `/refadmin reset <ник>` | Сбросить чужую привязку |
| `/refadmin reload` | Перечитать конфиг |

Права: `chrdkref.use` (все), `chrdkref.admin` (OP). Данные — `referrals-data.json`.

## Аддон CHRDK_Party — группы игроков (1.4.158)

Сервер, где играют вместе, отличается от сервера, где каждый копает свой
туннель, ровно одним: люди зовут друг друга. `CHRDK_Party` даёт для этого
минимум — группу до восьми человек, отдельный чат и небольшой бонус опыта,
когда свои стоят рядом. Ни урона, ни брони, ни алмазов группа не даёт: это
удобство общения, а не второй источник силы.

### Как это работает

- **Группа до восьми человек.** `/party create` собирает группу, дальше лидер
  зовёт игроков через `/party invite <ник>`. Приглашение живёт 60 секунд
  (`limits.invite-expire-seconds`), у группы не может висеть больше пяти
  приглашений сразу — spam-защита. Состав и лидер хранятся в
  `plugins/CHRDK_Party/parties.json`, поэтому перезапуск сервера группу не
  рвёт; приглашения не сохраняются — у них есть срок.
- **Чат группы.** `/pc <текст>` (или `/party chat`) отправляет сообщение только
  участникам; строка видна и самому автору, чтобы было понятно, что она дошла.
  Длина ограничена 256 символами.
- **Бонус опыта за игру рядом.** Каждый участник группы в радиусе 24 блоков
  добавляет +5 % опыта, потолок — +15 % (`bonus.per-member-percent`,
  `bonus.max-percent`, `bonus.radius`). Считаются только свои: случайный
  прохожий бонуса не даёт, иначе выгода была бы у толпы на спавне. Бонус
  применяется к событию получения опыта, поэтому работает с любым источником —
  шахтой, охотой, кладом, зельем.
- **Своих не бьём.** Дружеский огонь внутри группы выключен
  (`protection.friendly-fire`): случайный удар по своему — самая частая причина
  ссор. Включается обратно одной строкой в конфиге.
- **Лидерство не теряется.** Если лидер вышел из группы, лидерство переходит
  следующему по порядку вступления; если ушёл последний — группа распускается.
  Исключить участника и распустить группу может только лидер.
- **Список с жизнями.** `/party list` показывает роли, имена и здоровье
  участников; офлайн-игроки помечены отдельно. `/party info <ник>` показывает
  чужую группу — без права что-либо менять.
- **`/profile`.** Раздел «Группа» показывает состав, лидера и потенциал бонуса.
  Одиночке раздел не показывается.

### Команды

| Команда | Что делает |
|---|---|
| `/party` | состав группы или справка, если игрок один |
| `/party create` | создать группу |
| `/party invite <ник>` | позвать игрока (лидер) |
| `/party accept` / `/party deny` | принять или отклонить приглашение |
| `/party leave` | выйти из группы |
| `/party kick <ник>` | исключить участника (лидер) |
| `/party disband` | распустить группу (лидер) |
| `/party list` | состав, роли и здоровье |
| `/party info [ник]` | группа другого игрока |
| `/party chat <текст>` | чат группы (то же, что `/pc`) |
| `/pc <текст>` | чат группы |
| `/partyadmin reload\|info\|disband <ник>` | перезагрузка, сводка и роспуск чужой группы |

### Права

`chrdkparty.use` (по умолчанию всем) и `chrdkparty.admin` (OP).

### PlaceholderAPI

Мягкая интеграция: `%chrdkparty_in_party%`, `_size%`, `_max%`, `_leader%`,
`_bonus%` (потенциал группы), `_invites%`, `_members%`.

### Установка

Рядом с ядром положить `chrdk-party-1.4.160.jar`; зависимость — `CHRDK_Core`,
необязательная — `PlaceholderAPI`. Конфиг и тексты создаются при первом
запуске; данные лежат в `plugins/CHRDK_Party/parties.json`.

### Тесты

`PartyConfigTest` (зажим значений, умолчания), `PartyServiceTest` (приглашения,
срок, лидерство, потолки бонуса), `PartyStoreTest` (запись, чтение, битый файл,
игрок в двух группах) и `PartyMessagesTest` (контракт «код ↔ messages.yml»).


## Обновление до 1.4.9

Вышел второй аддон — **CHRDK_Referrals**, реферальная система: игрок привязывается к
пригласившему `/ref use <ник>` (один раз, только до первой проходки), при его первой оплате
оба получают бонусные дни (по умолчанию +7 пригласившему / +3 приглашённому, `bonus-days:`).
Команды `/ref`, `/ref top`, `/refadmin`. Это вторая демонстрация API 1.4.6: событие
`PassGrantedEvent` + начисление через `ChrdkRegisterApi.grantPass`.

**Важно при обновлении:** ядро — как обычно заменой JAR. Рефералка опциональна: положите
`chrdk-referrals-1.4.9.jar` в `plugins/` рядом (требует ядро ≥ 1.4.6, `depend`). Настройки —
`plugins/CHRDK_Referrals/config.yml` после первого запуска.

## Лотерея за алмазы — CHRDK_Lottery (1.4.67)

Устанавливается отдельным аддоном вместе с **CHRDK_Core 1.4.67**. Входит в общий
`chrdk-plugins-1.4.67.zip`, отдельный JAR — `chrdk-lottery-1.4.67.jar`.
Использует только обычные ванильные алмазы из инвентаря: именованные и другие
кастомные DIAMOND не расходуются. Vault и реальная валюта не используются.

- `/lottery` или `/lottery info` — банк, дата следующего тиража с таймзоной, ваши билеты и шанс.
- `/lottery buy [n]` — купить ровно указанное число билетов (по умолчанию один).
- `/lottery top` — десять владельцев наибольшего числа билетов.
- `/lottery last` — последний выигравший тираж.
- `/lottery claim` — забрать приз после авторизации. Выдаётся столько, сколько помещается;
  остаток хранится до следующего обращения. Призы не выбрасываются на землю.
- `/lotteryadmin reload` — перечитать настройки и тексты.
- `/lotteryadmin drawnow confirm` — досрочно разыграть текущий банк; требуется `chrdklottery.admin`.

Дефолты: билет **20 алмазов**, максимум **64 билета на игрока**, **32 за покупку**;
розыгрыш **воскресенье 20:00 Europe/Moscow**, напоминания за **30/5/1 минуту**.
Каждый билет имеет равный шанс, один победитель забирает **80%** банка,
**20%** (включая округление вниз выплаты) сгорает. При маленьком банке
выплата может округлиться до нуля; точные суммы публикуются в результате.
Покупки и получение призов требуют завершённой авторизации, проходка для
покупки опциональна (`general.require-pass`).

Настройки: `plugins/CHRDK_Lottery/config.yml`; тексты MiniMessage:
`plugins/CHRDK_Lottery/messages.yml`. `draw.announce-minutes: []` отключает напоминания.
Цена билета меняет **только будущие покупки**: фактически внесённый банк хранится отдельно.
`pot.payout-percent` применяется при розыгрыше — не меняйте процент в середине тиража,
если игрокам уже объявлены прежние условия. Лимиты защиты: 1 000 000 алмазов в банке
и 1 000 000 билетов, до 1024 билетов за команду и цена до 4096 алмазов.

Если сервер был выключен в момент розыгрыша, `draw.catch-up-on-start: true`
разыгрывает накопленный банк после запуска; покупка в просроченный тираж сначала
закрывает его. При `false` пропускается календарный слот, но **оплаченные билеты и
банк остаются** для следующего розыгрыша. Первая установка не считается пропуском.
Пустой тираж не создаёт победителя. Идентификаторы владельцев — UUID, не никнеймы.

Discord использует вебхук ядра: добавьте **`lottery.draw`** в
`notifications.events` живого конфига ядра и включите Discord, если он ещё выключен.
В свежем конфиге событие уже включено. API v2 добавляет `notifyEvent(...)`;
учётные данные вебхука не передаются аддону. После установки запустите
`/pass luckperms setup`: игрокам добавится `chrdklottery.use`, администраторам —
`chrdklottery.admin`, обычным игрокам административное право не выдаётся.

### Сохранность и эксплуатационные ограничения

Тиражи, внесённый банк, призы и отметка розыгрыша хранятся в
`plugins/CHRDK_Lottery/data.json`. Покупки, розыгрыши и списание призов сохраняются
сразу через временный файл и замену. Ошибка записи не публикует новое состояние;
инвентарь при ошибке покупки/получения восстанавливается. Повреждённый ledger
**отключает аддон**, а не запускает пустую экономику. Перед редактированием файла
остановите сервер и сделайте резервную копию.

Инвентарь Minecraft и JSON не образуют общую транзакционную БД: аварийное завершение
процесса строго между заменой ledger и сохранением playerdata может привести к
расхождению. `Player.saveData()` сокращает это окно, но не устраняет его. Делайте
согласованные резервные копии мира/playerdata и ledger; не восстанавливайте один
из них отдельно. Для большого рынка/аукциона нужен отдельный транзакционный дизайн,
а не обещание «невозможности дюпа» на базе этого файла.

Проверка серверного поведения перед широким включением: покупка обычными/кастомными
алмазами, лимиты и отрицательное число; досрочный тираж; оффлайн-победитель и
вход без /login; частичная выдача при полном инвентаре; перезапуск и catch-up;
ошибка записи и восстановление резервной копии. CI покрывает чистую математику,
календарь, конфиг, сообщения и переходы ledger — не заменяет эти игровые проверки.


### Группы игроков: чат, бонус и «своих не бьём» — релиз 1.4.158

Соло-игрок копает туннель и уходит; двое, которые договорились копать вместе,
остаются. До сих пор у них не было даже способа переписываться, не засоряя
общий чат. `CHRDK_Party` закрывает эту дырку тремя вещами — группой, отдельным
чатом и бонусом за игру рядом.

**1. Группа до восьми человек.** `/party create` собирает группу, лидер зовёт
игроков через `/party invite <ник>`. Приглашение живёт минуту, у группы не
висит больше пяти приглашений — пригласить весь сервер разом не выйдет.
Группы сохраняются в `parties.json` и переживают перезапуск; приглашения — нет,
у них есть срок. `/partyadmin reload` меняет числа в конфиге, не выбрасывая уже
отправленные приглашения: перезагрузка не должна наказывать игроков.

**2. Чат группы.** `/pc <текст>` доставляет сообщение только своим (и самому
автору). Длина ограничена 256 символами, чтобы один игрок не занял весь экран.

**3. Бонус опыта — мягкий и с потолком.** Каждый свой в 24 блоках даёт +5 %
опыта, максимум +15 %. Считаются только участники группы: случайный прохожий
бонуса не даёт. Это не второй источник силы, а причина стоять рядом, а не в
разных концах карты.

**4. Своих не бьём.** Дружеский огонь внутри группы выключен. Случайный удар по
своему во время боя с боссом — самая частая причина, по которой группы
распадаются. Включается обратно через `protection.friendly-fire: true`.

**5. Лидерство не теряется.** Ушёл лидер — группа переходит следующему по
порядку вступления; ушёл последний — распускается. Исключать и распускать может
только лидер, а админ — через `/partyadmin disband <ник>`.

**Совместимость.** Новый аддон: остальные модули, их конфиги и данные не
меняются, ядро и аддоны должны быть одной версии. PlaceholderAPI — мягкая
интеграция. Ставить рядом с ядром `chrdk-party-1.4.158.jar`.

**Тесты.** `PartyConfigTest`, `PartyServiceTest`, `PartyStoreTest` и
`PartyMessagesTest`; счётчик модулей в апдейтере и список YAML-контракта ядра
обновлены до 24.
