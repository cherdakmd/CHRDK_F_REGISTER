# Чек-лист живого smoke для 1.5.2-rc.2 (изолированный staging)

**Статус:** только документ для администратора staging. Дата: 6 ноября 2026 года.
**Артефакт:** prerelease
[v1.5.2-rc.2](https://github.com/cherdakmd/CHRDK_F_REGISTER/releases/tag/v1.5.2-rc.2)
(`c7233e8`, ZIP 4 714 219 B + `chrdk-vk-1.5.2-rc.2.jar` 277 966 B).

**Границы.** Проверка идёт **только на отдельной staging-копии**, никогда на
production. `Latest` остаётся `v1.5.1`, тег и ассеты rc.2 не переписываются,
TradeMC, соц. новости, PR/merge в `main` и CHRDK_Live не затрагиваются. Агент в
песочнице **не проводит** этот smoke: здесь нет JVM, Minecraft-сервера, клиента
и доступа к RCON. Документ — готовый сценарий для владельца; запрет на
live/RCON/игровой smoke снимается только отдельным явным решением, если доступ
будет предоставлен.

Полные заметки и backup-матрица — в [1.5.2-rc.2.md](releases/1.5.2-rc.2.md),
баланс-аудит — в [PRESTIGE.md](design/PRESTIGE.md).

---

## 0. Что понадобится

- Копия сервера Purpur 26.3 / Java 25, **не** боевой мир и не боевая база.
- Два тестовых аккаунта: `A` — с навыками на 100-м уровне, `B` — свежий, без
  престижа. У `A` должен быть платный ранг для проверки `RankBonus`, у `B` — нет.
- Доступ к консоли/логам и к файлам `plugins/CHRDK_Skills/`.
- Возможность остановить сервер, отредактировать `skills.json` на копии и
  снова запустить (для п. 2.6).
- Часы сервера/Environment `Europe/Moscow` для п. 2.7; желательно уметь
  перевести дату на staging.

## 1. Подготовка

1. **Полный backup до распаковки:** все папки `CHRDK_*`, Core `data.json` и
   `bank.json` со всеми SHA/журналами, `skills.json`, `abilities.json`,
   `perk-trees.json`, `shop-data.json`, `professions.json`,
   `tierforge/stats.yml`, миры и playerdata.
2. Поставить **весь комплект совместно**: 22 JAR одной версии из
   `chrdk-plugins-1.5.2-rc.2.zip`; `chrdk-vk-1.5.2-rc.2.jar` — отдельно.
   Не смешивать с rc.1/1.5.1. Не удалять банковские квитанции и WAL-pending.
3. Сверить авторские конфиги с эталоном: `skills/config.yml`
   (`prestige.*`, `diamonds.*`, `excluded-materials`), `skills/messages.yml`,
   `anvil.*`, `forge-shop.*`. Новые ключи в старом конфиге читаются из
   значений по умолчанию; **владельческие правки не перезаписываются**. Не
   редактировать конфиги параллельно с reload.
4. Запустить, убедиться в отсутствии `SEVERE`/`WARN` при старте, проверить
   версию в логе и то, что `API_VERSION` остался 42.

### 2.6 Миграция `skills.json`

| Шаг | Ожидаемый результат |
| --- | --- |
| Остановить сервер, положить в `plugins/CHRDK_Skills/skills.json` старый файл без новых полей: `{"version":1,"players":{"<uuid>":{"name":"Alex","xp":{"mining":131175},"milestones":[10,25]}}}` | Старт без `SEVERE`, XP и вехи на месте, престиж 0 |
| Положить файл **с** `prestige` (>10) и без `claimedTiers`: `"prestige":{"mining":99,"combat":10}` | Ступени прижимаются к 10, сумма ≤ 100, уже достигнутые звания помечаются **без выплаты**, файл перезаписывается с `claimedTiers` |
| После этого сделать первый сброс | Не должно разом выпасть 248 алмазов за «накопленные» звания |
| Проверить `MilestoneMigration` ядра | Плагин не отключается, `version` остаётся `1` |

**Признак провала:** `version` поднялся, плагин отключился с сообщением про
legacy-ledger, вехи перевыданы, старые ступени >10 сохранились.

### 2.7 Физический дроп и дневной лимит

| Шаг | Ожидаемый результат |
| --- | --- |
| У `B` (1 ур., без ранга) добыть 100+ честных блоков | Изредка падает `DIAMOND` предметом; шанс ≈ 1 % |
| У `A` (100 ур., ранг) добыть 100+ блоков | Шанс ≈ 20 %, но **не более 4 алмазов за событие**; дневной лимит 64 |
| Убить враждебного моба со живым `killer` | Дроп тоже возможен, с `mob-chance-factor 1.5` и `mob-amount-bonus 1` |
| Поставить блок и сразу сломать | **Нет** бонусного дропа (`PlacedBlocks`) |
| Креатив/спектатор, `DIAMOND_ORE`, `DEEPSLATE_DIAMOND_ORE` | **Нет** бонусного дропа |
| Набрать 64 алмаза за день, продолжить | Дальше дроп прекращается до смены календарной даты `Europe/Moscow` |
| Перевести дату на staging | Лимит обновляется, `diamondDay` в `skills.json` меняется |

**Признак провала:** алмазы в `/bal`, дроп из поставленного блока, дроп из
алмазной руды, пробитие `max-amount 4`, счётчик дня не сбрасывается.

### 2.8 Конфиги и reload

| Шаг | Ожидаемый результат |
| --- | --- |
| Выставить `prestige.enabled: false` и reload | «Престиж выключен в config.yml.», дроп и бонусы престижа не работают, обычная прокачка идёт |
| Выставить `prestige.perk-per-step: 0` и reload | Профильные прибавки исчезают, XP-множитель и звания остаются |
| Выставить `diamonds.daily-cap: 8` и reload | Лимит 8, `MAX_DAILY_CAP` не пробивается |
| Кривой YAML / отрицательные значения | Старт без падения, значения клампятся, в логе предупреждение |

## 3. Что ловить в логах

- `[CHRDK_Skills] … подтвердил престиж, серверный уровень N` — на каждый
  успешный сброс.
- `[CHRDK_Skills] … достиг звания «…» (престиж N)` — по одной строке на
  пересечённый порог.
- `[CHRDK_Skills] Загружено профилей: …` — после миграции `skills.json`.
- Любые `SEVERE`, `NullPointerException`, `InvalidConfigurationException`,
  `ConcurrentModificationException` при кликах по GUI — стоп, сохранить логи и
  идти к п. 4.

## 4. Откат

1. Остановить сервер.
2. Вернуть **согласованные** копии всех 22 JAR предыдущей версии из backup,
   отдельный VK JAR и все данные из п. 1. Не оставлять смесь версий.
3. Учесть, что данные, записанные rc.2 (`prestige`, `claimedTiers`,
   `diamondDay`, `diamondToday` в `skills.json`), старые сборки игнорируют, но
   сам файл лучше вернуть из backup, чтобы не было расхождений.
4. Запустить, убедиться, что `Latest`/production не затронуты.

## 6. Что не входит в этот smoke
