# Стартовый комплект новичка — дизайн

**Статус:** реализовано в CHRDK_Core активной ветки, без релиза. Дата: 7 ноября 2026 года.
**Решение владельца:** `core_join` (код в ядре), `once` (один раз при первом
входе), `both_separate` (1000 на `/bal` + 32 физических вне дневного лимита),
`mixed` (артефакты из каталога CHRDK_Artifacts плюс ванильные).

## 1. Архитектура

| Класс | Роль | Bukkit |
| --- | --- | --- |
| `StarterKitSettings` | неизменяемый снимок секции `starter-kit`, клампы, defaults | чтение YAML |
| `StarterKitPlan` | чистый бросок: материалы, ид артефактов, суммы | **нет** (JUnit) |
| `StarterKitStore` | `starter-kits.json`, UUID, pending/given, атомарная запись | нет |
| `StarterKitService` | `PlayerJoinEvent` → `PlayerAuthCompletedEvent` → выдача | да |
| `RegisterPlugin` | создание, `reload`, `shutdown`, accessor `starterKit()` | да |

Чистая логика вынесена в `StarterKitPlan`, чтобы тесты не требовали сервера.

## 2. Ключевые решения

1. **Выдача после авторизации.** `PlayerAuthCompletedEvent` (MONITOR), как у
   книги-путеводителя `GuideBookService`: до входа игрок заморожен
   `PlayerRestrictionListener`. `PlayerJoinEvent` (LOWEST) лишь помечает
   новичка как `pending`, чтобы выход до регистрации не потерял подарок.
2. **Только новые игроки.** `hasPlayedBefore()` → `given` без выдачи. Иначе
   обновление плагина влило бы в экономику 1000 алмазов на каждого ветерана.
   Это трактовка слова «стартовый»; в вики зафиксировано явно.
3. **UUID, а не ник.** Ключ в `starter-kits.json` — UUID; смена ника не дарит
   комплект заново. Инвариант «given важнее pending», запись через temp +
   `ATOMIC_MOVE`.
4. **Деньги и предметы идут разными путями.** `1000` — обычный
   `BankStore.deposit` (виден в `/bal`, `bank.json`). `32` алмаза —
   `Inventory.addItem(new ItemStack(Material.DIAMOND, 32))`, минуя
   `DiamondDrops`/`MoneyLoot`/`dailyCap`. Пользователь явно выбрал
   «оба, вне дневного лимита»; Q1-решение `a_status_quo` и потолки дропа
   не пересматривались.
5. **Артефакты без жёсткой зависимости.** `ChrdkArtifactsApi` из
   ServicesManager; `compileOnly`-зависимости на аддон не появляется (обратная
   связь зависимостей запрещена). `ids()`/`ids(false)` дают каталог с учётом
   выключенных в конфиге аддона идов, `create(id, 1)` бросает свойства как при
   обычной находке. Нет сервиса — ванильная часть закрывает оба слота.
6. **Fail-closed на дубли.** `markGiven` выполняется ДО выдачи: обрыв сервера
   между записью и выдачей теряет один подарок, но не удваивает алмазы.
7. **Defaults при отсутствии секции.** Как у `GuideBookSettings`: владельческий
   `config.yml` не переписывается, `ConfigUpgrader` и `API_VERSION=42` не
   трогаются. Новые ключи лежат в эталонном `config.yml` и `messages.yml`.
8. `itemStacks()` у стокового набора = 10 (4+3+1+1+1 стак алмазов) —
   свободные слоты у нового игрока есть. Остаток, если инвентарь полон,
   выбрасывается рядом стандартным `dropItemNaturally`.

## 3. Отклонённые варианты

- Отдельный Gradle-модуль / команда админа / выдача при каждом входе — не
  выбраны владельцем (`core_join`, `once`).
- Выдача через `DiamondDrops` или списание `dailyCap` — отвергнуто явно:
  стартовый подарок не добыча.
- Только ванильные или только каталожные артефакты — выбрано `mixed`.
- Прямая зависимость Core → artifacts — цикл по Gradle, заменён на
  ServicesManager.

## 4. Границы

Нет GUI, команд перевыдачи, компенсаций, зачарований, незерита, боссового
лута, выдачи ветеранам и персистентного «долга» по `/bal` при недоступном
банке (только предупреждение в лог). Живой игровой вход, реальный инвентарь,
`/bal`, MSPT и RCON не проверялись: в песочнице нет JVM и Minecraft-сервера.
Проверка — JUnit, контрактные тесты, валидаторы и CI.

Тег, prerelease, `Latest`, `main`, TradeMC, соц. новости, production,
`CHRDK_Live`, bump версии и `API_VERSION` не выполнялись.
