# CHRDK_Disasters — дизайн

**Статус:** реализовано в активной ветке. Первая версия (3 катастрофы) вышла в
пререлизе `v1.5.2-rc.3`; вторая итерация (6 катастроф, фазы, реестр, звуки и
эффекты) — **в разработке без нового релиза**. Дата: 7 ноября 2026 года.
**Решение владельца:** не ставить сторонний GPL-плагин, а «собрать его аналог
с нашими функциями и под наши реализации»; полная интеграция, модуль
`disasters/`, commit/push/CI. Позднее «делаем пререлиз» разрешило отдельный
пререлиз rc.3 с самостоятельным JAR.

## 0. Почему не готовый плагин

Аудит [DeadlyDisasters 1.1.0](https://www.spigotmc.org/resources/deadly-disasters.90806/)
и форка `cherdakmd/CHRDK_DeadlyDisasters` (GPL-3.0, Maven, Java 17,
`spigot-api 26.1.2`, 53 файла / ~22 400 строк) показал:

- автор тестировал до **26.2**, наш сервер — Purpur **26.3**;
- `BlackPlague` и `VersionUtils` лезут в NMS/рефлексию;
- список поддерживаемых region-плагинов фиксирован, `CHRDK_Claims` в нём нет;
- разрушение идёт через `block.setType()` без `BlockBreakEvent`, поэтому наша
  защита приватов на событиях не срабатывает;
- по умолчанию `targeting: INDIVIDUAL` и включены все катастрофы;
- GPL-3.0 несовместим с MIT нашего репозитория при включении в общий артефакт.

**Вывод:** отдельный GPL-JAR можно было бы поставить как агрегацию, но это не
даёт защиты приватов и требует ручного обновления. Пишем своё, оригинальное,
MIT. Ни одна строка кода, текст или ассет форка не скопированы; совпадает
только идея «случайные катастрофы у игрока».

## 1. Архитектура

| Класс | Ответственность | Bukkit |
| --- | --- | --- |
| `DisastersPlugin` | жизненный цикл, reload, доступ к компонентам | да |
| `DisastersConfig` | неизменяемый снимок YAML, клампы, фазы/звуки/эффекты, миры | чтение YAML |
| `DisasterKind` | шесть видов, ид, признаки, звук и эффект по умолчанию | нет |
| `DisasterScheduler` | таймер на игрока, случайная пауза, выбор вида/уровня | **нет** (JUnit) |
| `DisasterPhasePlan` | секунды → тики, распределение лимита блоков по шагам | **нет** (JUnit) |
| `DisasterRun` | состояние фаз одного запуска, счётчики, остановка по id | **нет** (JUnit) |
| `DisasterGeometry` | спираль, кольцо, круг, плотность частиц | **нет** (JUnit) |
| `DisasterFx` | звуки и мягкие эффекты состояния, очистка по типу | да |
| `DisasterProtection` | приваты `CHRDK_Claims`, спавн, миры, площадь радиуса | да |
| `DisasterRestore` | снимок `BlockData` и откат, лимит, защита от перетирания построек | да |
| `DisasterEffects` | шесть катастроф, фазы, единственная точка `setType` | да |
| `DisasterBroadcaster` | `Messages` + общий кулдаун на игрока | да |
| `DisasterEngine` | тик расписания, реестр активных запусков, тик фаз, откат | да |
| `DisasterCommandHandler` | `/disasters`, `/disastersadmin` (list, stop <id>) | да |

Чистая логика вынесена в `DisasterScheduler`, `DisasterPhasePlan`,
`DisasterRun`, `DisasterGeometry` и статический
`DisasterProtection.chunkKeysInRadius`, чтобы тесты не требовали сервера.

## 2. Ключевые решения

1. **Всё выключено по умолчанию.** `enabled: false`, `worlds: []` при включении
   означает все миры. Все площадные разрушительные катастрофы
   (`earthquake`, `tornado`, `flood`) выключены отдельно, даже при включённом
   модуле. Сторонний плагин стартует с полным набором разрушений — это
   неприемлемо для выживания.
2. **Защита приватов до изменения блока.** `ClaimStore.claimAt(world, cx, cz)`
   через `ClaimsPlugin` (`softdepend`), плюс обход всех чанков в радиусе для
   площадных катастроф. Спавн-радиус и хранилища (`InventoryHolder`) тоже
   исключены.
3. **Никаких Bukkit-событий при разрушении.** Только
   `Block.setType(..., false)`. Это намеренно: `CHRDK_Skills` не начислит
   опыт/алмазы, `CHRDK_Claims` не получит ложный `BlockBreakEvent`,
   `ClaimProtectionListener` не будет отменять уже отменённое.
4. **Откат обязателен.** Снимок `BlockData`, восстановление по таймеру, по
   команде, при reload/stop/onDisable; не перетираем блоки, поставленные
   игроком после катастрофы. Вода наводнения ставится в воздух над
   поверхностью, поэтому откат возвращает исходный воздух.
5. **Антиспам.** Один общий кулдаун на игрока, как в CHRDK_VK; ручной запуск
   админом — `force`.
6. **Конфиги и тексты** идут через общие `ConfigUpgrader` и `Messages`. В
   `settings.gradle` модуль уже есть (23-й), но в пререлизе `v1.5.2-rc.3`
   он поставляется **отдельным JAR**: общий ZIP намеренно остаётся из 22 JAR,
   как и `CHRDK_VK`. Соответственно модуль не входит в карту автообновления
   `PluginUpdateService.MODULES`. Во второй итерации у модуля появился
   собственный `config-schema.yml` (v2): новые `phases.*`, `sounds.*`,
   `player-effects.*` и тексты дописываются владельцу аддитивно.
7. **МСК** в логах движка, как у остальных модулей.
8. `API_VERSION` ядра не поднимался: новый модуль не меняет публичный контракт.
9. **Фазы вместо одного тика.** Предупреждение → активные тики → затухание.
   Блоки меняются только в активной фазе и порциями: `budget()` раскладывает
   прежний `max-blocks` по шагам, нулевая длительность фазы всё равно даёт один
   видимый тик.
10. **Реестр запусков.** `DisasterEngine` держит `Map<Integer, DisasterRun>`,
    `/disastersadmin list` показывает фазу и остаток, `stop <id>` снимает
    эффекты и возвращает блоки; при выключении модуля активные сценарии
    завершаются досрочно.
11. **Звуки и эффекты без урона.** `DisasterFx` разрешает только константы,
    уже используемые другими модулями CHRDK; неизвестное имя из YAML просто
    выключает звук. Мягкие potion-эффекты снимаются на затухании, `bypass`
    защищает от них, `player-effects.enabled` отключает целиком.
12. **Геометрия проверяется без сервера.** Спираль смерча, круг заливки и
    кольцо предупреждения детерминированы по seed/шагу и покрыты JUnit.

## 3. Отклонённые варианты

- Копирование/форк GPL-кода в репозиторий — лицензионный конфликт.
- Постановка готового JAR и «мостик» на `DisasterStartEvent` — не защищает
  отдельные блоки внутри радиуса и оставляет внешнее обновление.
- Bukkit-взрывы (`createExplosion`) для метеоров — порождают
  `EntityExplodeEvent`, ломают инвариант № 3 и задевают приваты.
- Хранение таймеров в JSON — отложено: после рестарта безопаснее выдать всем
  новую паузу, чем накапливать катастрофы.
- Мгновенное изменение всех блоков на первом тике — заменено порциями по
  активным тикам: так меньше пиковая нагрузка и проще остановить сценарий.
- Падающие блоки (`FallingBlock`) для смерча — сущность может задеть игрока
  или оставить предмет; визуального `Particle.BLOCK` достаточно.
- Урон игрокам и настоящая погода мира — сознательно оставлены за границей:
  катастрофа не должна убивать и не должна менять погодный цикл сервера.

## 4. Границы

Есть шесть катастроф, фазы, реестр, звуки и мягкие эффекты состояния. Нет NMS,
взрывов Bukkit, урона игрокам, погодного API, мобов, кастомных предметов,
интеграции с `/bal`, публичного API и персистентных таймеров. Живой игровой
smoke не проводился (в песочнице нет JVM/Minecraft-сервера/клиента/RCON);
проверка — JUnit, контрактные тесты и CI.

`Latest` остаётся `v1.5.1`, `main`, TradeMC, соц. новости, production и
перевод версии в стабильную не выполнялись. Вторая итерация не меняла версию,
тег, memo и ассеты rc.3.

## 5. Вторая итерация: ещё три катастрофы

| Катастрофа | Ид | Геометрия | Блоки | Эффект |
| --- | --- | --- | --- | --- |
| Смерч | `tornado` | `DisasterGeometry.spiral` | AIR + откат | `SLOW_FALLING` |
| Наводнение | `flood` | `DisasterGeometry.scatter` | WATER в воздух + откат | `SLOWNESS` |
| Метель | `blizzard` | `SNOWFLAKE` + белая пыль | не меняет | `SLOWNESS` (уровень 1) |

Три прежних вида тоже проработаны: пыльная буря, метеоритный дождь и
землетрясение получили фазы, порционные изменения, звуки, подсказки и мягкие
эффекты (`SLOWNESS`, `NAUSEA`, `MINING_FATIGUE`). Названия и подсказки всех
шести видов строятся из `id` (`kind-*`, `hint-*`), поэтому
`DisasterBroadcaster` и `DisasterEffects` больше не содержат switch по списку
текстовых ключей.

Оформление по решению владельца: только разработка и CI в текущей ветке, без
bump `plugin_version`, нового пререлиза и пересборки ассетов.
