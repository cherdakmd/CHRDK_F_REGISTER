# Отдельные файлы данных игроков

Эта правка разделяет «настройки сервера» и «записи конкретных игроков». Цель —
убрать дубли в TAB и сделать связи/варны/баны доступными для аккуратной ручной
правки без расшифровки перегруженного checksummed JSON.

## Что где лежит

| Файл | Плагин | Содержимое | Защита |
| --- | --- | --- | --- |
| `plugins/CHRDK_VK/players/social.yml` | CHRDK_VK | привязки ВКонтакте/MAX, `firstSeenAt`, донатный доступ, отметка награды, обратный индекс профилей | читаемый YAML, без встроенного checksum |
| `plugins/CHRDK_VK/social-links.json` | CHRDK_VK | rollout, аварийный режим, `lastNewsTag`, найденные чаты, MAX `chat_id`, маркер выноса игроков | SHA-256 по каноническому JSON |
| `plugins/CHRDK_Core/players/warns.yml` | CHRDK_Core | активные и снятые варны, `nextWarnId` | читаемый YAML, без встроенного checksum |
| `plugins/CHRDK_Core/players/bans.yml` | CHRDK_Core | зеркало ванильного `BanList` для админ-панели | читаемый YAML, без встроенного checksum |
| `plugins/CHRDK_Core/moderation.json` | CHRDK_Core | роли модераторов, журнал, `nextJournalId`, маркер выноса игроков | SHA-256 по каноническому JSON |

В каждую папку `players/` при первом запуске записывается `README.md` с краткими
правилами. Пароли, TOTP-секреты, токены ботов и 2FA в эти YAML не попадают.
`vk-links.json` и `data.json` остаются на месте: исторические бонусы `/vk` и
авторизация ядра этой правкой не переносятся.

## Формат `social.yml`

```yaml
schema: 1
players:
  alex:
    link:
      provider: vk            # только vk или max
      external-id: 12345       # положительное число
      external-name: "Иван"
      linked-at: 1700000000000 # миллисекунды Unix
    first-seen-at: 1700000000000
    donor:
      granted-at: 1700000000000
      source: "manual:оплата на сайте"
    reward-claimed-at: 1700000000000
profiles:
  vk-12345: alex              # один профиль мессенджера → один игрок
```

Ключ игрока — ник в нижнем регистре. `profiles` — обратный индекс для проверки
«один профиль не привязан к двум аккаунтам»; ключ имеет вид `vk-12345` или
`max-12345`. Пустые/нулевые поля можно не писать.

## Формат `warns.yml` и `bans.yml`

```yaml
# players/warns.yml
schema: 1
next-warn-id: 8
warns:
  - id: 7
    player: steve
    issuer: owner
    reason: "грифинг"
    at: 1700000000000
    removed-by: ""
    removed-at: 0
```

```yaml
# players/bans.yml
schema: 1
bans:
  alex:
    reason: "пять активных варнов"
    by: owner
    at: 1700000000000
```

Снятие варна **не удаляет** запись: она остаётся в истории с `removed-by` и
`removed-at`. `bans.yml` — зеркало для GUI; ванильный `BanList` остаётся
источником блокировки соединения.

## Миграция при первом запуске

1. Плагин читает старый `social-links.json` / `moderation.json`, проверяет его
   SHA-256. Повреждённый файл не мигрируется: копия уходит в `.broken`,
   включается штатный аварийный/пустой режим. При `fail-open-on-corruption: true`
   CHRDK_VK автоматически подтверждает аварийный режим, перед перезаписью
   `social-links.json` создаёт дополнительный `.bak`, а повреждённый
   `players/social.yml` не затирает до ручной правки.
2. Создаётся backup с меткой времени:
   `social-links.json.before-players-move-*.bak` или
   `moderation.json.before-players-split-*.bak`. Без успешного backup исходный
   JSON не перезаписывается.
3. Персональные поля переносятся в `players/*.yml` атомарной записью. Если YAML
   уже существует, он считается авторитетным и не перезаписывается устаревшей
   копией из JSON — это защищает уже сделанные ручные правки.
4. Из исходного JSON удаляются только персональные поля, добавляется
   `playerDataSchema: 1` и пересчитывается checksum. Глобальные чаты, новости,
   роли и журнал сохраняются.

Миграция идемпотентна: повторный старт её не повторяет. Если раздельные файлы
были восстановлены из более старого backup, сделайте полный backup папки
`plugins/` перед запуском и вручную сверьте оба источника.

## Ручная правка

* Останавливайте сервер. При работающем сервере следующее действие плагина
  перезапишет YAML из памяти.
* Сохраняйте UTF-8 без BOM, соблюдайте отступы и кавычки. Ник — в нижнем
  регистре; время — миллисекунды Unix; `external-id` и `id` — положительные числа.
* Не разрывайте пару `players/<ник>.link` и `profiles/<provider>-<id>`.
* Нечитаемый YAML копируется в `*.yml.broken`, а затронутая часть стартует
  пустой: привязки не загружаются и включается аварийный режим, варны/баны не
  загружаются до исправления файла. Оригинал остаётся на месте и не
  перезаписывается последующими сохранениями, пока администратор не исправит
  его вручную.
* Контрольные суммы в YAML намеренно отсутствуют: они превращали бы любую
  ручную правку в «подделку». Глобальные JSON по-прежнему защищены SHA-256.

## Связь с TAB

Эталонный `tablist.footer` CHRDK_Core теперь содержит одну строку
`%chrdksocial_tab%`. Старые три плейсхолдера во владельческом `config.yml`
сливаются в неё на лету `TabFooterNormalizer`: файл администратора не
перезаписывается. Строка `%auth_hint%` скрывается только когда она состоит
лишь из этой подстановки и повторяет уже показанный статус «в игре».
После привязки новая строка показывает `✅ ВКонтакте привязан — можно играть`
и не содержит ни срока, ни дедлайна. Без PlaceholderAPI/CHRDK_VK строка
скрывается целиком, а не оставляет сырой `%chrdksocial_tab%`.

Старые `%chrdksocial_status%`, `%chrdksocial_link%` и `%chrdksocial_access%`
остались в PAPI для внешних TAB/скорбордов, но эталонный footer их не дублирует.
