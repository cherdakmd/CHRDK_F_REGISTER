# Кланы, личные приваты и донат: решение 1.4.249

База обследования: 1.4.248 / API 27, commit e71316658aa0902bbd074f83f038fcde09bf2083.
Реализация: 1.4.249 / API 28. Проверки и публикация фиксируются отдельно в PR.
Документ не подтверждает установку или проверку на действующем Minecraft-сервере.

## Выбор пользователя

- `personal_sharing`: только личная собственность с добровольным доступом клана.
- `personal_only`: донатные удобства только личные. Нет покупки мест/должностей
  для всего клана, связи его вместимости с рангом лидера или автоплаты из казны.
- PvP, военные формулы и отдельные резервы этим изменением не перерабатываются.

## Контракт членства

`ClanMembershipIndex` в Core API 28, зарегистрирован через Bukkit ServicesManager.
Запрос имени разрешается в UUID через существующий локальный knownBankPlayer,
членство читается из действующего GuildService. ID клана стабилен; name/tag/role —
только описание. Должность не повышает роль на личной земле.

Claims не читает guilds.json и не держит старый снимок разрешений. Сервис ищется
динамически, в серверном потоке: порядок включения не создаёт жёсткой зависимости.
При отключении Guilds регистрация снимается; disabled, нездоровый durable-домен,
банк/UUID без подтверждения, отсутствие сервиса или ошибка => нет клановых прав.
Это сознательный отказ в производном доступе, а не открытие территории.

## Разрешение и срок жизни

Claim хранит cg (ID), cgo (владелец при привязке), cgr (ACCESS/CONTAINER/BUILD).
По умолчанию полей нет. Только собственник явно включает доступ текущему клану
на всю связную территорию. Лидер чужого клана не может открыть чужую землю.

Единый Claim.roleAt используется защитой, TP (включая финальную перепроверку),
картой, info, уведомлениями и вкладкой доступных территорий:
1. Собственник сохраняет BUILD.
2. При оплаченной аренде — только арендатор BUILD (кроме собственника).
3. Явное персональное приглашение/роль имеет приоритет.
4. Иначе нужны совпадающие текущие ID владельца и гостя с сохранённым ID.

Участник выходит/исключён — производные права сразу исчезают; личные остаются.
Роспуск или переход владельца в другой клан деактивирует старую привязку, новый
клан её не наследует. Возвращение в тот же нераспущенный клан вновь делает
привязку действующей; окончательный отзыв — off. Продажа/передача сбрасывает её.

Доступ арендатору не расширяется на весь клан арендатора. Смена состава/роли и
изменение клановой настройки не трогают rentUntil, tenant или оплату. Новые чанки
наследуют настройку общей территории; конфликтующие настройки при слиянии
отключаются, без повышения доступа. Personal members и clan binding разделены.

## Данные и финансы

Схема остаётся 4: новые поля опциональны, пустые поля не записываются. Это важно
для побайтного canonical domain/hash старых незавершённых WAL: отсутствие
привязки сохраняет прежний снимок без преобразования. Новые поля проходят read,
snapshot, financeCopy, validateFrozenDomain и публикацию с сохранением Claim identity.
Неизвестная роль/частичная привязка блокируют запись, исходник сохраняется.

Каждое изменение настройки проходит отделённый снимок → строгую проверку →
prepare → банковский receipt с нулевыми дельтами → finish. Неоднозначный commit
не выдаёт новых прав в live-модели; после рестарта восстанавливается ровно frozen
состояние. Автосохранение не затирает pending. Старые платёжные механизмы не заменены.

Откат старых JAR поверх новых pending не поддерживается: нужен согласованный
backup всех доменов. Вариант коллективной собственности/общей оплаты отвергнут.
Личные лимиты 24/28/34/40/44/48 и игровые клановые 10/14/18/22/26 не меняются.

## Приёмка

Регрессии: три роли; отсутствие согласия; exit/kick/роспуск/смена ID; личная роль
ниже клановой; пропажа/ошибка провайдера; lease; владелец и арендатор; merge;
продажа/transfer; round-trip и byte-exact legacy; owner-only mutation; доступная
вкладка без арендованного представителя; отказ/неопределённый commit/restart и
нулевые деньги; один лидер; очищенный тег; восемь сочетаний ворот чата.

Дополнительно обязательны все 25 Gradle-модулей, контракты сообщений, проверки
пакета и вики/браузера на точном SHA. На сервере после отдельной разрешённой
установки: два клиента и третий вне клана; pre-auth чат; контейнеры/стройка;
исключение во время ожидания TP; аренда; собственный config/messages и рестарт.
