# Снятие Bosses / Treasures — 1.4.239

## Граница изменения

Решение владельца: оба аддона полностью удалены и больше не развиваются.
Удалены деревья `bosses/`, `treasures/` вместе с их ресурсами, API реализации,
тестами и Gradle-проектами. Состав: Core + 27 аддонов, 28 JAR, Core API 26.
Проверка состава ZIP выводится из `settings.gradle` и `plugin.yml`; регрессия
явно запрещает присутствие имён двух снятых плагинов.

## Разрешённые исторические упоминания

Снимки `presentation-legacy-*` — **не активный конфиг**, а входные образцы
для распознавания старого стока. Снимок 1.4.238 содержит только сравниваемые
презентационные секции. Изменение этих образцов до удаления старых пунктов
сломало бы миграцию уже установленного конфига.

`EnchantBookSource.TREASURE/SHARDS` — deprecated-коды чтения вещей из прежних
выпусков, не возобновление источника. Новая генерация от них запрещена в
базовом API, реализации API и фабрике книг. Банковские квитанции не вычищаются.
Архивные release notes и завершённые пункты дорожных карт не переписываются
так, будто старых релизов не существовало; решение об отмене явно отмечено.

## Что намеренно сохранено

Ванильные Wither/Ender Dragon и другие проверки типа сущности, PvE-защита,
достижения и общие цели по ванильным боссам, bossbar срока ранга, Hunt,
рыболовные сокровища Artifacts, перки рыбалки Skills и свойство удачи TierForge.
Совпадение слова `treasure`/«клад» не делает их частью снятого аддона.

## Проверки

12 новых JUnit-сценариев: 9 RetiredAddons, 1 миграция презентации, 1 блокировка
обновлятора, 1 чтение старого происхождения без генерации. Обновлены существующие
контракты количества модулей/плиток/автосообщений и регрессии остальных источников. Старый пользовательский текст usage теряет только токен снятого
источника в списке; владельческий файл не переписывается.
Полная Gradle-сборка проверяет все оставшиеся модули; локально проверяются
контракт сообщений, вики со ссылками, упаковка ZIP и существующие регрессии каталога.

Автотесты не являются live-проверкой GUI/мира. Установка на рабочий сервер,
ручная сверка его конкретных выплат и удаление его старых JAR не выполнялись.
Новый Core не переносит очереди выплат удалённых модулей: неоднозначные
обязательства должны быть сверены **до** снятия аддонов.

## Повторная проверка остатков

После первого удаления найдены и устранены пропуски:

- строка `/boss` в действующей таблице команд вики;
- отдельная спецификация `docs/TREASURES_ARSENAL.md` с каталогом и механизмами
  уже удалённого модуля — файл удалён, ссылок на него не осталось;
- пять устаревших упоминаний потребителя «Клады» в комментариях/конфиге TierForge:
  общий API сохранён, описание больше не обещает несуществующий источник;
- действующие описания композиции звания, бонуса добычи кладов и сохранения их
  прогресса в документации рангов, а также отдельные подсказки README;
- имя удалённого интерфейса в JavaDoc версии Core API заменено общим описанием.

Добавлен `.github/scripts/check_retired_addons.py` и восемь регрессионных сценариев.
Проверяются действующие Java-исходники и ресурсы всех модулей, включая осиротевший
модуль вне settings.gradle, вики, её инструменты и текущие документы рангов.
Проверка запрещает возвращать идентификаторы/namespace двух плагинов, удалённый
интерфейс, команды со всеми алиасами и namespace, страницы, каталоги модулей и
спецификацию арсенала. Поддержаны и YAML-, и JSON-подобные поля `command`.
Она выполняется в Build, Wiki site и Release до сборки/публикации.

Проверка намеренно не стирает архивные release notes/аудиты, образцы старого
стока для миграции и тестовые фикстуры. Тестами отдельно подтверждено, что
ванильный bossbar, боссы, рыболовные сокровища и коды чтения старых вещей
не считаются остатками аддонов. Тематическое название гильдии в прежних
материалах рангов не является зависимостью от удалённой игровой механики;
магазинные изображения не перегенерировались и не публиковались.
