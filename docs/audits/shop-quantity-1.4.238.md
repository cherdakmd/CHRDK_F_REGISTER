# Поштучный магазин — повторный аудит 1.4.238

Область: DiamondShop, его переходы в Core ShopExchange/BankCash/ShopInventory,
команды и обе GUI, source recovery/совместимость 237, сообщения и упаковка.
Это анализ исходников и автоматические тесты, не live-тест рабочего сервера.

## Найдено и исправлено

| Путь | Риск до проверки | Исправление |
|---|---|---|
| `/shop sell … all`, `/shop sellall` | Количество подбиралось по bid, затем обычный sell заново выбирал текущую цену; на границе восстановления запаса могли измениться доход/оптимальный остаток | Immutable Sale: партия, bid, штуки и деньги вместе; sellMaximum передаёт тот же batch/bid в quoted; несоответствие отклоняется до inventory/source intent |
| Окно покупки | Общая кнопка «минимум продажи» использовала ask и могла неверно подсказывать порог | Buy-details отдельно; кнопка/подсказка минимальной продажи только в sell-окне по его frozen bid; доступное количество обычного товара видно в обоих окнах |
| Подтверждение на следующий тик | Только identity текущего inventory не доказывала отсутствие закрытия и повторного открытия того же объекта | QuantitySession: один владелец, одно submit, окончательный close; InventoryCloseEvent закрывает сессию, callback проверяет pending + точный view + online/plugin enabled |

UI-отмена касается лишь запроса, ещё не принятого Source/Core. Неизвестный исход
принятой сделки остаётся в журнале и не отменяется закрытием меню.

## Проверенные инварианты

- Количество — 1..2304 штуки, не число партий. Командные сценарии со старой
  семантикой нужно обновить; это явно отмечено в справке, вики и памятке.
- Цена = ceil(ask × units / batch) для покупки, floor(bid × units / batch)
  для продажи. Long безопасен после проверки границ; 0 и overflow не создают сделку.
  Полная эталонная партия и её целые кратные сохраняют прежние цены.
- Округление не создаёт прибыль от дробления при неизменной котировке.
  Это не обещание отсутствия обычного дохода на динамическом рынке между разными ценами.
- Автопродажа находит максимальную выручку в пределах cap/quota и минимальное
  число предметов для неё. Нулевые/неоплачиваемые остатки остаются игроку.
- Актуальность service/каталога/котировки проверяется до исполнения; сумма
  принятой сделки хранится в ShopExchange, а не восстанавливается из нового конфига.
- Auth/Survival/permission/NPC/dead, storage-only, обычные предметы без meta,
  offhand/броня, bank-first/сдача, запрет overflow drops сохранены.
- Повторные клики и редактирование после submit не создают второй запрос.
  Close/reload/disable/уход игрока не разрешают отложенный новый запрос.
- До source prepare строится независимый BEFORE/AFTER; недостаток места,
  предметов, денег, лимита или нулевая выручка не публикует новый эффект.
- Canonical source WAL и Core receipt/native witness сохраняют точные units,
  целую сумму и sequence. Старые pending не пересчитываются после обновления;
  импорт старого кошелька не повторяется. Independent files не объявляются ACID.

## Тесты и выпуск

33 новых теста к 237: 21 TradeAmounts, 6 QuantitySession, 3 ShopJournal и
3 ShopNativeBank. Матрицы цен/количеств/минимума, BigInteger oracle для границ,
нулевая выручка, cap/quota, frozen selection, partial units, restart/spent/retry,
native checkpoint failures, lifecycle/повторные подтверждения и production wiring.
Существующие финансовые/нативные тесты остаются в общей сборке.

Обязательные проверки выпуска: message contract всех модулей, вики с якорями,
тесты упаковщика, Gradle Root + 29, затем повторная сборка tag и verify_release:
ровно 30 уникальных plugin.yml одной версии, CRC JAR и ZIP, русская памятка.
В релизе один ZIP, без отдельных JAR и без установки на рабочий сервер.
