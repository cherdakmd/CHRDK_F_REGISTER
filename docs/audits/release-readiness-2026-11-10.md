## Найденные пробелы и исправления

### R1. Проверка комплекта начиналась только после публикации Release

**Риск:** публичный стабильный Release мог остаться без рабочих ассетов при
ошибке tagged build. **Исправлено:** `release.yml` поддерживает ручной dry-run
с обязательным подтверждением версии. Он проходит тот же путь сборки и
упаковки, загружает временный candidate artifact, но не вызывает
`gh release upload`. Публикация по-прежнему запускается событием Release.

### R2. Не было контрольных сумм ассетов

**Риск:** пользователь не мог штатно проверить целостность скачанного ZIP/JAR.
**Исправлено:** создаётся `chrdk-<версия>-SHA256SUMS.txt`, немедленно
проверяется `sha256sum -c` и прикрепляется к Release/candidate artifact.

### R3. Метаданные архивов зависели от времени и порядка ФС

**Риск:** одинаковый tagged source мог дать разные байты JAR, усложняя сверку.
**Исправлено:** для всех `AbstractArchiveTask` включены
`preserveFileTimestamps=false` и `reproducibleFileOrder=true`.

## Оставшиеся gates и риски

1. **Обязательный live staging:** полный backup, совместная замена JAR,
   auth/2FA, GUI, экономика/WAL, restart, внешние интеграции и MSPT.
2. **Внешний VK:** известный из 1.5.1 `code 38` зависит от токена/прав группы
   и не закрывается изменением release pipeline.
3. **Эксплуатационная настройка:** LuckPerms, PlaceholderAPI, RCON, TradeMC и
   права VK/MAX проверяются на сервере отдельно.
4. **Supply chain:** GitHub Actions адресуются major-тегами, а не commit SHA;
   перевод на pinned SHA можно выполнить отдельным изменением с процессом
   обновления зависимостей.
5. **Защита main:** через доступный токен sandbox прочитать branch protection
   нельзя (HTTP 403); требуется ручная сверка required checks и запрета force
   push в настройках GitHub.
6. **Большой монорепозиторий:** README и историческая памятка велики, но это
   эксплуатационный долг документации, а не блокер текущего release contract.

## Решение

Source/CI gate для текущего состояния пройден. Изменения этой ветки повышают
надёжность следующего выпуска и сами требуют зелёного Build + успешного
Release dry-run. Версию, тег и публичный Release этот аудит не создаёт.
