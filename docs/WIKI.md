# Вики для игроков: как устроена и как её править

Вики — это отдельный статический сайт: `wiki/*.md` → `site/*.html`. Сборщик
лежит в `tools/wiki/`, публикация — GitHub Pages через
`.github/workflows/pages.yml`. Ни один файл вики не влияет на работу плагинов.

- Сайт: <https://cherdakmd.github.io/CHRDK_F_REGISTER/>
- Исходники: `wiki/` (текст) и `tools/wiki/` (сборщик, стили, поиск)
- Готовый сайт: `site/` — собирается в Actions и в git не попадает

## Быстрый старт

```bash
python3 -m pip install pyyaml
python3 tools/wiki/build.py            # собрать site/
python3 tools/wiki/build.py --check    # собрать и проверить ссылки и якоря
python3 -m http.server -d site 8000    # посмотреть локально
```

`--check` — обязательный шаг: он ловит ссылку на несуществующую страницу,
якорь на отсутствующий заголовок, страницу вне `config.yml` и страницу,
указанную дважды.

## Одна страница = один файл

`wiki/<слаг>.md`. Слаг — это имя файла и адрес страницы (`rank.html`). Каждая
страница обязана начинаться с front matter:

```markdown
---
title: "Ранги"
description: "Пять ступеней: цены, лимиты и что ранг даёт."
---
```

- `title` — заголовок страницы, пункт меню и название в поиске;
- `description` — подзаголовок, `meta description` и текст в карточках;
- поля обязательны, без них сборка падает — это намеренно.

## Навигация — `wiki/config.yml`

Порядок разделов и страниц задаётся списком `groups`. Порядок страниц внутри
раздела = порядок в меню и порядок кнопок «Назад / Дальше». Новая страница,
которой нет в `config.yml`, — ошибка сборки, как и ссылка на отсутствующий
файл.

Главная (`index`) не показывается в карточках раздела, но остаётся в меню.
Карточка раздела ведёт на первую «содержательную» страницу, поэтому раздел
«Начало» открывает `start.html`, а не главную.

## Разметка

Поддерживается подмножество markdown, которого хватает вики:

| Что | Как |
|---|---|
| Заголовки | `#`, `##`, `###` (из них строится оглавление справа) |
| Таблицы | обычные `\|`-таблицы, выравнивание через `:--` |
| Списки | `-` и `1.`; перенос строки внутри пункта продолжает пункт |
| Цитата-вывод | `> **Важно.** Текст` — акцентный блок |
| Код | `` `команда` `` и блоки ``` |
| Ссылки | `[текст](ranks.html)` или `[текст](ranks.md)` |

Ссылки на страницы пишите в `.html` (так они попадают в проверку). Якоря
`#заголовок` генерируются транслитерацией: «Как купить» → `#kak-kupit`.

## Правила текста

- **Русский язык**, обращение к игроку, без канцелярита.
- **«Ранг», не «проходка».** Вход бесплатный, платят за удобства.
- **Только проверенные числа.** Цена, лимит, шанс — из `config.yml` аддона или
  кода; если число не подтверждено, его не пишем.
- **Без TODO и заглушек.** Страница либо готова, либо её нет в `config.yml`.
- **Не обещать больше, чем есть.** Если механика не даёт силы или валюты, это
  сказано прямо.
- **Команды — в таблицах** «Команда → что делает», без выдуманных подкоманд.

## Публикация

`pages.yml` собирает вики на каждый push в `main` (и на pull request — только
сборка, без деплоя), затем выкладывает `site/` артефактом Pages.

Один раз в настройках репозитория нужно выбрать источник:

**Settings → Pages → Build and deployment → Source: GitHub Actions.**

После этого адрес сайта — `https://cherdakmd.github.io/CHRDK_F_REGISTER/`.
Если Pages выключен, job `deploy` упадёт с 404 от `configure-pages`; сборка и
проверка ссылок при этом всё равно выполнятся.

## Что собирается автоматически

- `index.html` и все страницы по `config.yml`;
- `search-index.json` — поиск в шапке (Ctrl-K);
- `sitemap.xml` и `robots.txt`;
- `.nojekyll` — чтобы Pages не трогал файлы Jekyll-ом;
- `assets/version.txt` — версия из `gradle.properties`.

Версия в шапке сайта, в подвале и в `version.txt` берётся из
`plugin_version`, поэтому вики всегда показывает актуальную версию плагинов.
