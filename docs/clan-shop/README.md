# CHERDAK — комплект трёх клановых товаров

Подготовлено по отдельному запросу после выпуска **1.4.278**. Это материалы для
карточек, а не публикация внешнего магазина и не установка Minecraft-плагинов.
Общий исторический комплект в `docs/trademc` не заменяется; его 26 товаров и
изображения не менялись. Флаг исключения новых SKU из общего экспорта оставлен
как был: этот отдельный комплект не включает и не обновляет остальные товары.

## Содержимое

| Товар | Цена | Срок | Картинка |
| --- | ---: | ---: | --- |
| Цвет названия клана | 189 ₽ | 30 дней | `images/clan-name-style.png` |
| Значок клана | 179 ₽ | 30 дней | `images/clan-emblem.png` |
| Рамка карточки клана | 219 ₽ | 30 дней | `images/clan-card-frame.png` |

Все PNG — **1200 × 1200**, отдельная картинка для каждого товара. Иллюстрации
выбраны владельцем, надписи и цены набраны отдельно для читаемости. Изображения
художественные: нарисованные физические знамёна, медальоны и рамки не выдаются.
Фактический товар — только оформление чата и/или интерфейса.

- **`ТОВАРЫ.md`** — карточки с изображениями, полными описаниями и командами.
- **`ОПИСАНИЯ_ТОВАРОВ.txt`** — готовые тексты для копирования в описания.
- **`КОМАНДЫ_RCON.txt`** — команды выдачи и границы доверия для администратора.
- **`manifest.json`** — цены, сроки, описания, команды, размеры и SHA-256 картинок.

## Заполнение карточки

1. Создайте три отдельных товара с ценами из таблицы, сроком 30 дней и точным
   игровым ником покупателя. Назначение лицензии клану выполняется **после** выдачи.
2. Для каждого прикрепите его картинку и описание из комплекта.
3. Вставьте **только одну основную команду** соответствующего товара. Начальный
   `/` для RCON не нужен. `%username%` — используемый в существующих материалах
   placeholder ника; если другая панель использует иной синтаксис, замените
   только эту переменную согласно документации панели.
4. Не прикрепляйте все три команды к одному товару. Не добавляйте вторую команду
   по сумме, свой срок или команду применения оформления: это даст неверную
   выдачу либо повторную продажу. В поле доставки не нужны игровые `/clan style`.

## До открытия реальных продаж

- Убедитесь, что **на сервере действительно установлены согласованные Core и
  Guilds 1.4.278 или совместимые новее**. Выход релиза сам сервер не обновляет.
- Проверьте активный `shop.products`: все три ID, цены, срок, отсутствие команд
  и боевых прав. Миграция не заменяет собственные владельческие значения — при
  совпадении ID локальные настройки могут отличаться от стандартных.
- Лицензии читаются через Core. Личные роли I–V, включая V, покупку не заменяют;
  существующий набор «Всё включено» не содержит этих трёх новых товаров.
- Защитите RCON: доверенный отправитель, закрытый доступ, необходимые серверные
  настройки `trademc.enabled` и журнала платежей. Никому из игроков не выдавайте
  административные права для shopbuy/shoppay/shopgift.
- Одна реально подтверждённая оплата → **один** вызов соответствующей команды.
  Команда без номера заказа разрешается только доверенному RCON при штатных
  настройках. Для ручной серверной консоли нужен предусмотренный Core путь
  подтверждения с настоящим номером платежа; шаблоны комплекта не являются
  разрешением придумывать `payment=` или обходить проверку оплаты.
- Повтор той же RCON-команды не распознаётся автоматически как дубль заказа:
  может произойти новая продажа/продление. Повторы и уникальность заказов
  контролируются на стороне магазина и при сверке журнала, не выдуманным токеном.
- Проведите отдельно согласованный контрольный платёж и сверьте результат,
  срок и журнал. **Этот комплект не выполняет тестовую оплату или выдачу.**
  Сбой доставки не означает, что платёж можно повторно выдать без проверки.
- При TIME_LIMIT проверьте ручную очередь `/pass pending` и кабинет оплаты.
  Запись очереди — запрос сверки, не самостоятельное доказательство оплаты.

## Как покупатель включает оформление

`/clan style` показывает варианты и срок. Примеры:

```text
/clan style name aurora
/clan style emblem crown
/clan style frame amethyst
```

Участник предлагает оформление главе. Глава за 2 минуты принимает:

```text
/clan style accept НикПокупателя
```

Оба должны быть в одном клане; покупатель — в сети, авторизован и с действующей
лицензией. Глава применяет собственную покупку напрямую. Все личные выбранные
украшения одного покупателя связаны с одним его кланом; переносится весь выбор,
не чаще раза в реальные 24 часа, включая первый день после назначения.

Снять свой выбор: `/clan style off name`, `off emblem` или `off frame`.
Глава убирает тип со всего клана через `/clan style clear name|emblem|frame`.
Это не отзыв покупки и не сброс срока переноса. Смена главы не передаёт покупку.
При нескольких спонсорах активен последний одобренный действующий вариант типа;
после его отключения может вернуться действующий вариант другого участника.

Для возврата/спорной оплаты сначала сверяют реальную оплату и историю продлений.
Отзыв накопленного права не является автоматическим возвратом одного заказа;
команды отзыва намеренно не добавлены в автоматическую доставку.

## Проверка и пересборка материалов

Из корня репозитория, без подключения к серверу:

```bash
python3 -m pip install -r tools/clan_shop/requirements.txt
python3 tools/clan_shop/build.py --check
python3 -m unittest discover -s tools/clan_shop -p 'test_*.py' -v
# Пересобрать картинки и документы из выбранных иллюстраций:
python3 tools/clan_shop/build.py --build
# Собрать отдельный ZIP с тремя товарами:
python3 tools/clan_shop/build.py --zip /путь/cherdak-clan-products-1.4.278.zip
```

Никакие из этих команд не обращаются к RCON, магазину, оплатам или Minecraft.
Подробности механик в репозитории:
[описание выпуска 1.4.278](https://github.com/cherdakmd/CHRDK_F_REGISTER/blob/v1.4.278/docs/releases/1.4.278.md) и
[кланы в справочнике](https://github.com/cherdakmd/CHRDK_F_REGISTER/blob/v1.4.278/wiki/guilds.md).
