# Анализ проекта для меню, автосообщений и TAB — 1.4.70

Область проверки: settings.gradle, все 16 plugin.yml (ядро + 15 аддонов),
игровые обработчики команд, текущие config.yml/messages.yml, авторизация,
рендер автосообщений, меню и TAB, интеграции рангов и пробного срока.
Это анализ навигации/взаимодействия модулей, не полный аудит безопасности
каждого боевого эффекта и не нагрузочное испытание сервера.

## Реальная карта возможностей

| Модуль | Что доступно игроку | Навигация |
|---|---|---|
| Core | регистрация, пробные дни, проходка, 2FA, сессии, чат/ЛС | pass menu, pass donate, 2fa status, session, chat |
| DailyRewards | ежедневная награда, стрик | daily |
| BattlePass | задания сезона и награды | battlepass |
| Ranks | звания за время | ranks |
| CommonGoals | общие цели и личный вклад | goals |
| Referrals | привязка друга, бонусные дни | ref |
| DiamondShop | обмен ресурсов, динамические цены, отдельный счёт | shop |
| Auction | рынок игроков, почта, отдельная выручка | auction, auction mail |
| Lottery | билеты, банк, розыгрыш и сохранённые призы | lottery info, lottery last |
| Claims | покупка чанков, казна/рента, участники, карта | claim help/list/map/balance |
| Teleports | дома, RTP, запросы к игрокам | homes, rtp, tpa |
| Enchants | каталог и игровые способы получения чар | enchants |
| TierForge | редкости крафта, статистика находок | tiers |
| Artifacts | каталог, носимые артефакты, источники добычи | artifacts |
| Cosmetics | шлейфы и эффекты | cosmetics list |
| Queue | сведения об очереди и VIP-приоритете | queue info |

Аукцион, Lottery и Shop не являются единым Vault-кошельком: почта/выручка,
счёт магазина и алмазы в инвентаре различаются. UI это объясняет.
Не рекламируются будущие доска заказов, альбом коллекции, достижения,
престиж, промокоды, recovery-коды или двусторонний Discord-бот.
Не фиксируются спорные «100 артефактов»/числа боссов — каталог зависит от кода/конфига.

## Обнаруженные проблемы и исправления

1. Старое меню имело только 6 кнопок. Добавлено 27 действий на 4 тематических ряда:
   аккаунт/награды; экономика/территории; телепорты/справка; артефакты/защита/сервис.
   Каждая кнопка аддона проверяет enabled-plugin и use-permission; отсутствующие скрываются.
2. `/claim` без аргументов покупает чанк. Кнопка справки теперь `claim help`,
   отдельные кнопки списка/карты/казны. RTP явно помечен как платное действие;
   покупки лотов и билетов не запускаются прямо из серверного меню.
3. Открытый GUI ссылался на новую конфигурацию после reload. Holder теперь хранит
   UUID владельца и конкретные действия; перед кликом повторно проверяются
   конфиг, права, аддон, авторизация. Устаревшее меню просит переоткрыть себя.
   Действие переносится на следующий тик; переносы/drag/shift/hotbar блокируются.
4. Автосообщения были 4 общими строками и рендерились только legacy-кодами.
   Теперь 22 структурированных подсказки, MiniMessage + legacy, персональный остаток,
   фильтры аддона/прав/пробного срока/неподключённой 2FA. Только авторизованные
   получатели с правом automessage.receive; минимум считается по этой аудитории.
   Случайный режим исключает немедленный повтор, когда доступен другой текст.
5. TAB не показывал стадию входа и тип проходки. Добавлены контекстные подписи,
   следующий шаг, состояние 2FA, доступные быстрые команды; пробный срок не
   называется пробным после последующего обычного продления.
6. Принудительное серое имя могло перебивать чужое оформление; восстановление
   pinned-team каждые 2 секунды могло лишать Ranks его сортировки. По умолчанию
   name-format пустой; pin не перетягивает игрока из чужой команды. Сопоставление
   ника учитывает регистр реального онлайн-имени. При выключении/выгрузке
   сбрасываются только имена и header/footer, которые менял этот сервис.
7. Пробный срок закрывал `/ref use`, а его PassGrantedEvent мог расходовать привязку.
   API v3 добавляет isTrialOnly (default false); история только trial не мешает
   привязке, событие trial не платит бонус. Подсказка рефералов приходит после
   авторизации, когда командой действительно можно пользоваться.
   Остальная прежняя семантика бонуса при непробной выдаче сохранена — не заявляется,
   что абсолютно любая такая выдача обязательно была реальной оплатой.
8. Новые defaults не обновляли живые старые конфиги. Консервативная миграция
   сравнивает 6 конкретных значений с точными defaults 1.4.69, копирует backup,
   затем атомарно заменяет конфиг. Пользовательские списки/тексты, расписания,
   выключенные флаги и pinned-names не заменяются. Если backup/запись не удались,
   обновление пропускается. Не мигрируются messages.yml с кастомными текстами.

## Что не внедрялось и где нужна отдельная работа

- Прямые показатели ранга, баланса каждого аддона и прогресса BattlePass в TAB:
  у аддонов нет единого публичного snapshot API, ядро не должно читать их JSON
  или рефлексией вызывать внутренние классы. Здесь показаны только данные ядра
  и доступные команды; PlaceholderAPI-плейсхолдеры в шаблонах TAB не выполняются.
- Универсальное меню-квест/подробный учебник, динамические цены RTP/Claim,
  текущий банк/расписание Lottery внутри TAB — отдельные API-интеграции.
- Общий транзакционный кошелёк: не смешивались ledger аукциона, Lottery и Shop.
- Полный анализ безопасности/нагрузки — за пределами этого изменения.

## Проверки

CI: YAML и контракт сообщений; все команды/permission дефолтного меню сверяются
с реальными plugin.yml; охват 15 аддонов; layout без пересечений; условия сообщений;
новые placeholders и escaping; точная/повторная/частичная миграция с сохранением
кастомных списков и defaults; trial-only история и фильтр реферального события.

Живой Purpur: полный комплект / ядро без аддонов; потеря use-права; /pass reload
с открытым меню; Shift/drag/number-key/double-click; новичок до /register, trial,
login+2FA, истечение/обычное продление; TAB с CHRDK_Ranks и чужими prefix-плагинами;
случайная рассылка при разной аудитории; старый stock/custom config и наличие backup;
привязка реферала после trial и отсутствие бонуса на событии trial.
