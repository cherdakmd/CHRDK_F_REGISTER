# CHRDK_TierForge: аудит релиза 1.4.73, исправления и доработки 1.4.80+

Документ фиксирует разбор модуля **CHRDK_TierForge** из релиза **v1.4.73**
(`chrdk-tier-forge-1.4.73.jar`, Purpur 26.3 / Minecraft 26.3, Java 25), найденные
дефекты, внесённые исправления и план дальнейших волн. Исходной точкой служит тег
`v1.4.73`; все ссылки на поведение даны по этому тегу.

## 1. Резюме

Модуль — «Terraria-накат»: крафт, дроп с мобов и кузнечный апгрейд дают броне,
оружию и инструментам один из 7 тиров; наковальня умеет сливать два одинаковых
предмета в тир выше, перекатывать тир за катализатор и поднимать 85 кузнечных
свойств. Хранилище — только PDC предметов, то есть модуль не ведёт собственных
данных и почти не может «потерять базу». Основные проблемы релиза 1.4.73 — не
падения, а расхождения конфига с поведением и тихая потеря прогресса предмета.

| № | Серьёзность | Проблема | Статус |
|---|---|---|---|

## 2. Методика

1. **Статический разбор** всех 17 классов модуля (3298 строк), `config.yml`,
   `messages.yml`, `plugin.yml`, `build.gradle` и 7 тестовых классов.
2. **Сверка конфига с кодом**: каждый ключ `config.yml` проверен на фактическое
   использование и на диапазон значений; отдельно — ключи, которые читались, но
   ни на что не влияли.
3. **Контракт текстов** `.github/scripts/check_messages.py` (ключи Java ↔
   `messages.yml`, динамические префиксы `tier.<id>.*`).
4. **Сборка и тесты** в GitHub Actions на Purpur API 26.3 / Java 25 (локального
   JDK в рабочем окружении нет — зелёный CI является критерием).
5. **Ресёрч** событий Bukkit/Paper, на которых держатся механики: `PrepareAnvilEvent`,
   `PrepareSmithingEvent`, `PrepareItemCraftEvent` / `CraftItemEvent`,
   `EntityDeathEvent`, `PlayerDeathEvent`, `EntityPotionEffectEvent` (см. §7).

## 3. Дефекты релиза 1.4.73

### T-01. Накат при крафте игнорировал шансы по видам предметов

`TierCraftListener.onPrepareCraft` (v1.4.73) в двух ветках считал шанс по-разному:

```java
if (plugin.config().identifyUnidentified()) {
    int chance = plugin.config().craftChanceFor(kind);   // свой шанс группы
    ...
    return;
}
TierDef.Snapshot roll = rollKeeper.preview(
        player.getUniqueId(), result.getType().name(), this::rollFresh); // только общий
...
private TierDef.Snapshot rollFresh() {
    int chance = plugin.config().rollOnCraftChancePercent(); // <- общий, не по виду
```

Сервер с `craft.tools-chance-percent: 10` и `identify.enabled: false` продолжал
выдавать инструментам накат со 100%. Хуже того, `identify.pass-bonus-chance-percent`
(бонус активной проходки) применялся только в identify-ветке — включение/выключение
режима неопознанных меняло не только UX, но и экономику.

**Исправление.** Обе ветки идут через один расчёт `craftChance(player, kind)`
(свой шанс → фолбэк на общий → бонус проходки), а отложенный ролл получает шанс
уже с учётом вида предмета.

### T-02. `anvil.enabled` не был мастер-выключателем

Ключ документирован как выключатель наковальни, но в коде проверялся только перед
веткой слияния:

```java
// ---- апгрейд: два предмета одного материала и одного тира ----
if (!plugin.config().anvilEnabled()) return;
```

Улучшение и перекат проверяли лишь собственные `improve.enabled` / `reroll.enabled`.
Администратор, выключивший наковальню целиком, всё равно получал работающий
перекат и ковку.

**Исправление.** Проверка `anvilEnabled()` стоит сразу после определения игрока —
до «неопознанных» и до всех трёх веток, поэтому `false` действительно возвращает
наковальню ванили целиком. `config.yml` теперь прямо называет ключ мастер-выключателем.

### T-03. Незеритовый апгрейд терял кузнечные улучшения и кличку

`onPrepareSmithing` применял к результату только тир:

```java
ItemStack result = event.getResult();
ItemStack base = event.getInventory().getInputEquipment();
String tier = plugin.items().tierOf(base);
plugin.items().apply(result, snapshot);
```

`apply` наносит тир, но не копирует `up_<id>`-уровни и `forge_name` со старого
предмета. Игрок, вложивший десятки материалов в «Кромку V», после апгрейда в
незерит получал предмет с тиром и **без** улучшений; кличка при этом выдавалась
заново случайная. Это самая дорогая потеря прогресса во всём модуле.

**Исправление.** Новый `TierItems.copyForgeState(from, to)` переносит кличку и все
уровни улучшений, затем наносится тир. Результат явно отдаётся через
`event.setResult(result)`, чтобы не зависеть от того, является ли `getResult()`
живой ссылкой на слот.

### T-04. Утечка отложенных роллов переката

`TierAnvilListener` чистил `previewKeys` только при заборе результата, а
`CraftRollKeeper.rerollKeeper` — только при `consume`. Игрок, открывший наковальню
и вышедший из игры, оставлял запись навсегда. На сервере с сотнями игроков это
медленная, но бесконечная утечка.

**Исправление.** `PlayerQuitEvent` в `TierAnvilListener` чистит `previewKeys`,
`rerollKeeper` и анти-спам-память.

### T-05. Спам подсказок в окне наковальни

`PrepareAnvilEvent` вызывается многократно: на каждое перекладывание слота, на
каждую букву в поле переименования, при закрытии и повторном открытии. Каждый
вызов с «не нашей» парой отправлял игроку сообщение — «на второй слот нужен
предмет того же материала и тира» могло прийти 20+ раз подряд, а «улучшение
применено» — на каждую букву имени.

**Исправление.** Новый `AnvilNoticeGate` помнит последнюю сигнатуру на игрока и
пропускает повтор один раз; успешные ветки используют сигнатуры
`improved:<свойство>:<уровень>` / `upgraded:<материал>:<тир>`, поэтому повторная
подсказка появляется только при реальном изменении ситуации. Чистая логика
покрыта `AnvilNoticeGateTest`.

### T-06. Границы `identify.scan-ticks`

`Math.max(5, getInt(...))`: значение `1` означало «скан раз в тик» и молча
превращалось в 5 (4 раза в секунду) без предупреждения; верхней границы не было
вовсе. Период регулируется в разумных 10..1200 тиков (0,5–60 с) с логом при
клампе.

### T-07. Множитель босса

`Math.max(0.0, getDouble(...))` пропускал `0` (шанс дропа у босса становился 0%,
что противоречит смыслу «множитель»), отрицательные значения и `NaN`. Теперь
диапазон 1.0..20.0 с предупреждением; «выключить» множитель = поставить `1.0`.

### T-08. `/tiers` не показывал шансы групп

Заголовок печатал только `roll-on-craft-chance-percent`. После T-01 действующий
шанс группы может отличаться от общего — добавлена строка
`list-chances: оружие X%, броня Y%, инструменты Z%`.

## 6. Ресёрч: на чём держатся механики

- **`PrepareAnvilEvent`** приходит на любое изменение входов/поля имени, поэтому
  любые сообщения из него обязаны быть идемпотентными. Результат задаётся
  `event.setResult(...)`; `AnvilInventory#setRepairCost` + `setRepairCostAmount`
  управляют ценой в уровнях. Забор результата ловится `InventoryClickEvent` по
  `rawSlot == 2`.
- **`PrepareSmithingEvent`** — единственная точка, где можно сохранить PDC при
  апгрейде в незерит: ванильный результат собирается заново и не наследует
  произвольные PDC-ключи. Отсюда `copyForgeState`.
- **`PrepareItemCraftEvent`** повторяется на каждое движение ингредиентов — ролл
  обязан быть отложенным (`CraftRollKeeper`), иначе перебором сетки можно
  «выкрутить» легендарку без крафта. `CraftItemEvent` фиксирует реальный крафт.
- **`EntityDeathEvent`** — `getDrops()` изменяем, тир наносится до выпадения;
  `getKiller()` даёт атрибуцию статистики (план 1.4.83).
- **`PlayerDeathEvent` + `PlayerRespawnEvent`** — единственный корректный способ
  «привязки души»: убрать предмет из `getDrops()` и вернуть на респауне; при
  `keepInventory` вмешиваться нельзя (двойной дроп).
- **PDC** (`PersistentDataContainer`) — хранилище модуля. Ключи: `item_tier`,
  `item_unidentified`, `item_tier_source`, `forge_name`, `up_<id>`; атрибуты
  `tier_*` и `fu_*`.

## 7. План следующих волн

- **1.4.81 — статистика на диск.** `TierStatsKeeper` → атомарный `stats.yml`
  (UUID → тиры → счётчики), асинхронный сейв, загрузка при старте, `/tiers stats`
  за всё время, `/tiers stats reset`, `/tiersadmin stats <ник>`; счётчики также
  пополняются крафтом и дропом с мобов (сейчас — только опознанием).
- **1.4.82 — производительность кузни.** PDC-индекс улучшений (`up_index`),
  чтобы `upgradesOf` читал один ключ вместо 85; пульс по игрокам с кэшем
  экипировки; магнит через `setVelocity` вместо `teleport`; рекурсионные
  флаги `zoneBreaking`/`effectShifting` — `ThreadLocal` для Folia-регионов.
- **1.4.83 — дроп с мобов.** «Босс» = `Boss`/именной моб, список выключенных
  миров, `killer-only`, атрибуция статистики убийце, отдельный шанс по видам.
- **1.4.84 — разбор предмета.** `/tiers info` для предмета в руке: тир, источник,
  кличка, улучшения с описаниями, цена следующего уровня и переката; подсказки
  по правам в `/tiers`.
