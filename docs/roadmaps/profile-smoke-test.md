# Серверная проверка профиля и социальных действий

Статус: **чек-лист, не результат испытаний**. Использовать отдельный тестовый
сервер с обновлёнными ядром, навыками, гильдиями, приватами и социальным
модулем. Проверять с обычными правами, а не только с правами оператора.
Отдельно проверить установленные сторонние провайдеры профиля и плагины,
которые отменяют ПКМ или управляют видимостью: за их данные отвечает автор
провайдера. Не записывать в отчёт реальные идентификаторы и личные ссылки.

## Подготовка

- Три тестовых игрока A, B, C; у A/B право `chrdkregister.profile` и
  `chrdkregister.profile.others`, у C — без права на чужие карточки.
- Тестовые URL, доступные для публикации; никаких настоящих служебных привязок.
- Гильдии с включённой командой группы; для её проверок нужны игроки,
  доступные друг другу и не находящиеся в активной войне.
- Зафиксировать версии всех плагинов, результаты и логи; после теста очистить
  тестовые данные через игровые команды, не удаляя файлы реальных игроков.

## Карточка, права и ПКМ

1. A открывает `/profile`, `/profile B`, `/profile chat B` и карточку B ПКМ
   пустыми руками. Проверить одинаковый состав публичных разделов и рейтинг.
2. Проверить предмет в каждой руке по отдельности, отменённый другим плагином
   ПКМ, NPC, невидимого для A игрока и неавторизованного игрока. ПКМ не должен
   перехватывать отменённые действия и работу предметов. Уточнить поведение
   с торговлей, умениями, PvP и плагином vanish на конкретной сборке.
3. C не может открыть карточку B; автодополнение не должно выдавать чужие ники
   без права. Невидимый для A B не должен появляться в подсказках и открываться
   по имени. Проверить снятие прав и скрытие B *после* открытия карточки, затем
   нажатие раздела, «В чат» и «Обновить».
4. A открывает свою карточку: банк, 2FA и личные разделы видны только ему.
   Проверить чужие профили на отсутствие ID служебных привязок, личной казны,
   долга и дисциплинарных сведений, включая просмотр в чате и офлайн.

## Публичные ссылки

1. B публикует тестовый URL, A открывает его карточку. B удаляет или меняет
   ссылку, пока карточка A открыта; при клике по разделу A не должен получить
   в чат удалённый адрес. Уже показанное на клиенте ранее отозвать невозможно.
2. Проверить отдельное сохранение пяти платформ, неверные домены, URL с портом,
   параметрами, userinfo и переадресацией, удаление и перезапуск сервера.
   Служебная привязка сама по себе не должна публиковать ссылку.

## Друзья и группа

1. A отправляет запрос кнопкой и командой `/friend invite B`; B отклоняет,
   затем принимает новый запрос. До согласия дружбы нет; после согласия список
   и удаление симметричны. Проверить старую команду `/profile friend`.
2. Проверить истечение через 60 секунд, лимит запросов, таймаут между ними,
   выход каждого игрока и перезапуск. Подтверждённые друзья переживают
   перезапуск, ожидающие запросы — нет. Удалить офлайн-друга.
3. Проверить кнопку приглашения в группу, согласие, отказ и истечение 60 секунд;
   членство не должно возникать без согласия. Проверить уход лидера/одного из
   двух участников, войну между участниками и ограничение размера группы.
4. В тестовой копии отдельно проверить повреждённый файл друзей и ошибку записи:
   изменение должно быть отклонено, исходный файл не перезаписан. Вернуть
   тестовую копию из резервной копии; не переносить повреждённый файл в продакшен.

## Рейтинг

Сверить сумму уровней всех навыков, перерождения и бонусные очки с формулой
в карточке. Проверить незаполненную запись, офлайн-профиль, перераспределение
очков и перерождение. Экипировка и роль не должны изменять этот прототип.

Результат зафиксировать отдельно: дата, серверная сборка, версии плагинов,
каждый пункт pass/fail/не проверен и ссылки на обезличенные логи.
