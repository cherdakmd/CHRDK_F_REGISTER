# Генератор: контейнер и печное топливо — план реализации

Статус: **в разработке**, на сервере пока не работает. Существующий бункер
остаётся счётчиком; существующее необязательное лавовое топливо не является
новой системой.

## Согласовано

Владелец открывает общий интерфейс генератора, похожий на сундук, с продукцией
и отдельными ячейками топлива. Принимаются стандартные виды топлива Minecraft
с соответствующей длительностью горения; без топлива производство прекращается.

## Что необходимо сделать до включения

- Хранить конкретные произведённые предметы и топливо, а не только число
  единиц. Старый счётчик бункера сохранить и перенести без повторного
  случайного перебора после сбоев. Учесть смену тира, удачи, конфигурации,
  автопродажу, снятие и перерождение генератора.
- Для перемещения между инвентарём игрока и постоянным хранилищем определить
  журнал с восстановлением при сбое, а не считать обычное событие клика
  атомарной записью. Проверить shift-click, drag, hotbar, double-click,
  выход и переполнение инвентаря; закрыть доступ чужим игрокам.
- Разрешать только действительно действующее в текущей версии сервера топливо
  печи, учитывая остаточные предметы (например, пустое ведро после лавы).
  Не превращать ценные предметы с пользовательскими данными в простое топливо.
- Производство, расход топлива и метку времени фиксировать вместе. После
  исчерпания топлива не накапливать время простоя для будущей заправки.
  Сохранить исходную классификацию онлайн/офлайн при ограничении временем
  топлива: иначе короткий остаток топлива может ошибочно получить онлайн-КПД.
- Согласовать старую необязательную лавовую заправку и её конфиг с новой
  системой, без неожиданного повторного списания денег и без бесплатного
  стартового топлива. Продумать остановку при заполненном контейнере.
- Покрыть миграцию, перезапуск на каждом этапе, снятие, перерождение, автопродажу,
  несколько генераторов и действия в GUI тестами; отдельно провести smoke на
  реальном сервере. До этого не описывать новый контейнер как работающий.

`GeneratorFuelBudget` — только проверяемая арифметическая основа, к рабочему
циклу и GUI ещё не подключена. Она не заменяет журнал транзакций и не определяет
состав топлива. Значение печных тиков необходимо получать из серверной версии,
а не поддерживать отдельный вручную составленный неполный список.
